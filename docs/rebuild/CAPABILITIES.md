# Capability matrix with parity evidence

This matrix lists every capability of the reconstruction and the evidence that
it behaves like the reference implementation (commit
`0ae7767f7b75dd6c640ca547f9ff85b60f46e69d`, imported unchanged as `edf3032`).
Rows C1 to C21 are the concepts of the
[architecture index](../current-architecture.md); rows P1 to P13 add the
official package capabilities that those concepts do not already cover.

Columns:

- **Owner**: the package directory or Core module that implements the
  capability today. Every path was checked to exist on `main` (`7d52537`).
- **Unchanged reference tests**: two to five of the most relevant test files.
  Each one is byte-identical to the reference
  (`git diff --quiet edf3032 HEAD -- <file>` exits 0, checked for every file
  listed). The tag gives the Vitest project that runs it, inferred from
  `vitest.config.ts`: `unit` (`packages/*/src/**/*.test.ts`,
  `packages/*/tests/**/*.test.ts` and tooling tests, including package
  `*.browser.test.ts` and language-service tests), `types` (`*.test-d.ts`),
  `e2e` (`*.e2e.test.ts`), `postgres-e2e` (`*.postgres.e2e.test.ts`),
  `performance` (`*.performance.test.ts`) and `website-content`
  (`apps/website/tests/*.content.test.ts`). `pack` marks the 32 archive suites
  of `yarn test:pack:built`. Source-mode coverage reruns the `e2e` and
  `postgres-e2e` files as `coverage-e2e` / `coverage-postgres-e2e`, except the
  built-only audits excluded in `vitest.config.ts`.
- **Projects**: the union of those tags, which is what must be green for the row.
- **Rebuild-specific evidence**: what the reconstruction adds beyond the
  unchanged suites, taken from the package `REBUILD*.md` files,
  [VALIDATIONS.md](VALIDATIONS.md), [DX-AUDIT.md](DX-AUDIT.md) and
  [HANDOFF.md](HANDOFF.md): side-by-side runtime oracles with their case
  counts, emitted declaration identity, the editor-visible (DX) audit and
  production line counts (`node tooling/measure-rebuild.mjs`, non-blank lines,
  before -> after). Oracles were scratch harnesses that were not committed;
  their results are recorded, not re-runnable from the tree.
- **Differences**: the rows of [DIFFERENCES.md](DIFFERENCES.md) that apply, all
  limited to untyped or forged inputs, or "none".
- **Status**: filled by the coordinator from the final calm-machine run in
  [VALIDATIONS.md](VALIDATIONS.md). A validation that was not executed does not
  count as passed.

Cross-cutting evidence that applies to every row: the full DX audit went from
383 differences to 2, none editor-visible (an unused `FrameworkError` import in
the reference access-plugin declarations and an unused `Relation` import in the
rebuilt roles-plugin declarations); no completion, diagnostic or export-list
difference was ever reported.
