## What you will build

Nothing new in this step. You will choose the shortest path from the working
`Task` application to the capability your project needs next.

## Prerequisites

Finish [First Application](./first-application). Keep the first application
small until one requirement proves that another plugin or concept is needed.

## Steps

Choose a Core concept when the behavior is native. Choose a plugin page when an
optional package owns the behavior. Use guides only for workflows that combine
several capabilities.

<Cards>
	<Card title="Model schemas" href="/docs/1.0/core/data-modeling/schemas">
		Explore fields, defaults, embedded objects, pointers, and relations.
	</Card>
	<Card title="Read with Query" href="/docs/1.0/core/reading-data/overview">
		Build immutable filters, selections, ordering, pagination, and includes.
	</Card>
	<Card
		title="Understand security"
		href="/docs/1.0/core/security-foundations/security-model"
	>
		Separate Core authority from optional identity and authorization plugins.
	</Card>
	<Card title="Choose a plugin" href="/docs/1.0/plugins/using-plugins">
		Learn explicit identity, privileges, capabilities, and lifecycle.
	</Card>
	<Card
		title="Expose REST"
		href="/docs/1.0/plugins/official/http-and-apis/rest"
	>
		Map HTTP resources into the same Runtime operation model.
	</Card>
	<Card
		title="Expose GraphQL"
		href="/docs/1.0/plugins/official/http-and-apis/graphql"
	>
		Generate a network-independent schema before choosing an HTTP adapter.
	</Card>
</Cards>

## Expected result

You can name the next application requirement and the single public contract
that explains it. Add plugins only when that requirement needs their concrete
behavior.
