## What you will build

You will turn the three-file example into a structure that can grow without
hiding the application graph or treating generated declarations as Runtime
code.

## Prerequisites

Run the record creation from [First Application](./first-application). Keep the
application configuration importable: later transports, tests, and Typegen all
need the same graph.

## Steps

The first project has this shape:

<Files>
	<Folder name="src" defaultOpen>
		<File name="schema.ts" />
		<File name="ultimabase.ts" />
		<File name="main.ts" />
	</Folder>
	<File name=".env" />
	<File name=".gitignore" />
	<File name="package.json" />
	<File name="tsconfig.json" />
</Files>

- `schema.ts` owns deterministic data declarations. Split it by domain when
  several schemas emerge, then export one explicit schema list.
- `ultimabase.ts` owns the application graph: schemas, plugin instances,
  privileges, and application-level configuration.
- `main.ts` owns process lifecycle. It starts the application and disposes it
  during shutdown or after bounded work.
- `.env` belongs to the local process, not source control. Production secrets
  should come from the deployment environment or its secret manager.

### Optional generated declarations

UltimaBase runs from the compiled application graph without Typegen. Add
`@ultimabase/typegen` when you want application-specific editor types for
plugin-contributed fields, operations, and schema surfaces.

The Typegen plugin reads the already compiled static graph and writes
`.ultimabase/schema.generated.d.ts` before infrastructure connects. Keep that
file included by TypeScript, but do not import it as an executable client. It is
replaceable declaration output; your schema and plugin configuration remain the
Runtime truth.

<Callout type="info" title="One application definition">
	Do not maintain a separate “Typegen application” and Runtime application.
	Export and load the same `UltimaBase` graph so generated declarations cannot
	describe a different configuration.
</Callout>

## Expected result

A reader can locate data declarations, composition, lifecycle, and secrets
without opening generated output. Deleting and regenerating the Typegen file
does not change Runtime behavior.
