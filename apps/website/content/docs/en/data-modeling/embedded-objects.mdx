An embedded object is a structured value owned by one parent record. Use it
when the nested data has no independent identity or lifecycle.

```ts title="src/customer.ts" fixture="data-modeling/embedded-objects.ts"
import { Schema } from '@ultimabase/core'

export const Customer = Schema.define({
	className: 'DocsCustomer',
	fields: (field) => ({
		name: field.string({ required: true }),
		shippingAddress: field.object({
			fields: (embedded) => ({
				city: embedded.string({ required: true }),
				countryCode: embedded.string({ required: true }),
				line1: embedded.string({ required: true }),
				line2: embedded.string(),
			}),
			required: true,
			typeName: 'DocsAddress',
		}),
	}),
})
```

`typeName` gives the generated object contract a stable reusable TypeScript
name. The parent field's `required` option controls whether the whole object may
be null; each nested field independently controls its own nullability.

## Value, not entity

The entire object is one stored logical value. Nested object fields may contain
portable value fields and further embedded objects, but they cannot contain:

- pointers or relations;
- virtual fields;
- indexes or uniqueness constraints;
- auto-increment or other entity identity mechanisms.

Use a separate schema plus a [pointer](./pointers) when the nested thing needs
its own `id`, independent updates, access rules, or relationships.

Value lists remain one-dimensional. If your domain genuinely needs arbitrary
matrix-shaped data, declare a JSON field and validate that JSON through the
appropriate plugin instead of disguising it as nested field lists.
