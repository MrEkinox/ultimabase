A pointer stores one immutable logical reference: the exact target schema plus
one record ID. It does not load the target and does not expose a mutable target
object.

```ts title="src/session.ts" fixture="data-modeling/pointers.ts"
import { Schema } from '@ultimabase/core'

export const Account = Schema.define({
	className: 'DocsAccount',
	fields: (field) => ({
		email: field.string({ required: true }),
	}),
})

export const Session = Schema.define({
	className: 'DocsSession',
	fields: (field) => ({
		account: field.pointer({
			onDelete: 'cascade',
			required: true,
			target: 'DocsAccount',
		}),
		expiresAt: field.dateTime({ required: true }),
	}),
})

export const accountReference = Account.pointer(
	'0198f090-2a50-7000-8000-000000000034',
)
```

The string `target` is resolved against the schemas registered in the same
application. Typegen then narrows `Session.account` to the generated
`DocsAccount` pointer handle rather than a generic string.

Use `Account.pointer(id)` to construct a typed reference. The equivalent general
form is `new Pointer(Account, id)`. Pointer construction performs no I/O.
`pointer.equals(other)` compares both schema identity and ID, while
`pointer.toJSON()` returns the frozen logical reference shape.

## Deletion behavior

`onDelete` states what should happen when the target is deleted:

- `restrict` rejects target deletion while the pointer exists;
- `cascade` deletes the referencing record;
- `setNull` clears the pointer and therefore requires a nullable field.

Use `indexed: 'unique'` on a pointer to express a one-to-one constraint. Use a
[relation](./relations) instead when one record owns a changing set of target
members.
