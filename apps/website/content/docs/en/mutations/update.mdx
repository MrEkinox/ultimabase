`updateOne` accepts either an `id` or an exact unique `where` predicate. Direct
values replace stored values; field-specific helpers express operations that
must stay atomic in the database.

```ts title="src/update-post.ts" fixture="mutations/update.ts"
import { increment, unset } from '@ultimabase/core'

import { Post } from './schemas.js'
import { ultimabase } from './ultimabase.js'

export const publishPost = (postId: string) =>
	Post.updateOne(
		{
			data: {
				summary: unset(),
				title: 'Published',
				views: increment(1),
			},
			id: postId,
			select: { title: true, views: true },
		},
		{ ultimabase },
	)
```

The schema-root command returns `null` when no visible record matches. A model
loaded with `get` can instead call `model.update(...)`; that strict identity
command returns a new immutable model and reports `NOT_FOUND` if its target has
disappeared. Neither command mutates the previously loaded instance.

Numeric `increment` and `decrement` operations validate the complete projected
value while the target is locked, then remain an atomic adapter operation. Use
`unset()` for an optional field; assigning `null` is only legal for a nullable
field.

Selections and inclusions follow the same result-shaping rules as reads. See
[Selections](../querying/selections) for the projection contract.
