Bulk commands are ordered lists of singular operations. They are a convenient
application API, not a public set-based database shortcut.

```ts title="src/bulk-posts.ts" fixture="mutations/bulk.ts"
import { Account, Post } from './schemas.js'
import { ultimabase } from './ultimabase.js'

export const createPostBatch = (
	authorId: string,
	posts: readonly { readonly slug: string; readonly title: string }[],
) =>
	Post.createMany(
		{
			data: posts.map((post) => ({
				author: Account.pointer(authorId),
				...post,
			})),
			select: { slug: true, title: true },
		},
		{ ultimabase },
	)

export const renamePostBatch = (
	updates: readonly { readonly id: string; readonly title: string }[],
) =>
	Post.updateMany(
		{
			data: updates.map(({ id, title }) => ({
				data: { title },
				where: { id: { eq: id } },
			})),
			select: { title: true },
		},
		{ ultimabase },
	)
```

`createMany`, `updateMany`, `upsertMany`, and `deleteMany` preserve input order.
Every item gets singular validation, policy evaluation, Hooks, and result
materialization inside one transaction. One failure rolls back the entire
batch; there is no partial-success mode.

Each update, upsert, or delete item must identify at most one target through an
ID or exact unique predicate. Nested writes are intentionally unavailable on
bulk roots. If a privileged persistence-plan plugin combines physical work, it
must preserve the original itemized logical behavior.
