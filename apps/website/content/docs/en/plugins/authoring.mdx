Use `@ultimabase/plugin-kit` to remove repeated authoring boilerplate. It is a
helper library, not a plugin, registry, service locator, or permission bypass.
Its helpers delegate to the public Core kernel.

```ts title="src/plugin.ts" fixture="plugins/authoring.ts"
import { definePluginModule } from '@ultimabase/plugin-kit'

const workflow = definePluginModule({
	core: '^0.0.0',
	pluginId: 'community.workflow',
	version: '1.0.0',
})

export const workflowPlugin = (instanceId?: string) =>
	workflow.plugin({
		...(instanceId === undefined ? {} : { instanceId }),
		setup: () => ({ ready: true as const }),
	})
```

`definePluginModule` binds stable package facts once. The factory still returns
a static typed definition; it must not connect, read files, start listeners, or
perform other effects. Put resource creation in an application capability
factory or `setup`, where Core can attribute and dispose it.

Use Core directly for capability definitions, Runtime behavior, protected
constraints, persistence rewrites, raw adapter leases, transport bindings,
Master elevation, and explicit cross-owner transformations. Keeping those
calls visible makes ownership and privilege boundaries reviewable.

A publishable plugin package ends in `-plugin`. Export its factory and public
contracts from the package root; consumers must not deep-import `src/`.
