A plugin owner is the structured pair `{ pluginId, instanceId? }`.
`pluginId` is the stable namespaced package identity. `instanceId` is an
explicit non-empty configuration identity; Core never guesses it from options.

```ts title="src/ultimabase.ts" fixture="plugins/instances.ts"
import { UltimaBase } from '@ultimabase/core'

import { workflowPlugin } from './authoring.js'

export const ultimabase = new UltimaBase({
	plugins: [workflowPlugin('editorial'), workflowPlugin('publishing')],
	schemas: [],
})
```

Two separately configured definitions with the same `pluginId` require
different `instanceId` values. Reusing the exact same definition object is
composition reuse, while duplicating one structured identity is an error.

Ownership, privileges, capability contributions, setup exports, diagnostics,
and lifecycle all retain the pair. A dependency or peer may target one exact
instance only when the distinction is semantically necessary. Do not
concatenate IDs into an ad hoc string or derive them from secrets and URLs.
