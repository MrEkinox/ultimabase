`where` is a schema-correlated object. Fields and operators at the same level
combine with implicit `AND`; the reserved `AND`, `OR`, and `NOT` keys create
recursive logical groups.

```ts title="src/discover-posts.ts" fixture="querying/filters.ts"
import { Post } from './schemas.js'
import { ultimabase } from './ultimabase.js'

export const readDiscoverablePosts = () =>
	Post.findMany(
		{
			where: {
				NOT: { title: { startsWith: 'Archive' } },
				OR: [{ score: { gte: 80 } }, { tags: { has: 'featured' } }],
				published: { eq: true },
				views: { between: { lower: 100, upper: 10_000 } },
			},
		},
		{ ultimabase },
	)
```

## Operator families

Autocomplete exposes only the operators supported by a field kind.

| Family                | Representative operators                          | Notes                                      |
| --------------------- | ------------------------------------------------- | ------------------------------------------ |
| Equality              | `eq`, `ne`, `in`, `notIn`                         | Exact logical values                       |
| Ordering              | `gt`, `gte`, `lt`, `lte`, `between`, `notBetween` | Ordered values; ranges include both bounds |
| Text                  | `contains`, `startsWith`, `endsWith`, `matches`   | String-specific matching                   |
| Nullability           | `isNull`, `isNotNull`                             | Accept literal `true`, not `eq: null`      |
| One-dimensional lists | `has`, `hasSome`, `hasEvery`, `isEmpty`           | Element-aware list checks                  |
| JSON and objects      | `contains`, `containedBy`, key and path operators | Structured portable values                 |

Several operators on one field still combine through `AND`. For example,
`{ views: { gte: 100, lt: 1_000 } }` is a half-open interval. Prefer
`between: { lower, upper }` when both bounds should be inclusive.

## Pointer filters

A pointer stores target identity. `eq`, `ne`, `in`, and `notIn` accept target
object IDs, while `is` and `isNot` traverse the visible target with its exact
schema filter:

```ts
const memberships = await Membership.findMany({
	where: {
		project: {
			eq: projectId,
			is: { archived: { eq: false } },
		},
	},
})
```

`eq` checks only stored identity. `is` and `isNot` evaluate target visibility
and policy. A null pointer satisfies `isNot`; add `isNotNull: true` when null
must be excluded.

## Structured values

Typed embedded objects preserve exact keys and path segments. JSON fields allow
dynamic paths with JSON-compatible operands. Paths stay as segment arrays, so a
dot inside a declared field name is never parsed as nesting.

```ts
where: {
	profile: {
		at: [{ path: ['contact', 'email'], eq: 'ada@example.com' }],
	},
}
```

For dynamic conditions, build a `WhereBuilder`, call `.build()`, and pass the
result as ordinary `where`. It uses the same operators and normalization; it is
not a second query language.
