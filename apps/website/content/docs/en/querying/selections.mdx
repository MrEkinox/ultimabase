## Outcome

Use a flat `select` object to make Runtime output and the inferred immutable
model agree on exactly which scalar and pointer fields are visible.

## Prerequisites

Start with [Query Overview](./overview). Relationships have their own nested
projection contract in [Includes](./includes).

## Steps

Select only the fields needed by the caller. Every returned root or nested model
always includes `id`, so it does not need to be repeated:

```ts title="src/post-results.ts"
import { Post } from './schemas.js'
import { ultimabase } from './ultimabase.js'

export const readPostCard = (id: string) =>
	Post.get({ id, select: { createdAt: true, title: true } }, { ultimabase })

export const readPostSignals = () =>
	Promise.all([
		Post.findOne(
			{
				orderBy: { createdAt: 'desc' },
				select: { title: true },
				where: { published: { eq: true } },
			},
			{ ultimabase },
		),
		Post.count({ where: { published: { eq: true } } }, { ultimabase }),
		Post.exists({ where: { published: { eq: false } } }, { ultimabase }),
	])
```

Selection has two modes:

- any `true` flag enables inclusion mode, keeping only fields marked `true`;
- an object containing only `false` flags excludes those fields and keeps the
  rest.

An empty object keeps the complete output. A mixed object uses inclusion mode,
so `{ title: true, internalNote: false }` selects only `title` plus the always
available `id`. `id: false` is rejected instead of silently changing identity
semantics.

## Verify

Hover the result of `readPostCard()`. It contains `id`, `createdAt`, and `title`,
but not `internalNote`, `published`, or other unselected fields. At Runtime,
direct properties, `get()`, enumeration, inspection, and `toJSON()` expose that
same visible snapshot.

`findOne` returns the selected model or `null`. `get` returns the selected model
or throws `NOT_FOUND`. `count` and `exists` accept only filtering because they do
not materialize model fields.
