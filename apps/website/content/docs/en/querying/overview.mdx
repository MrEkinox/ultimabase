UltimaBase reads start on a generated schema class. Pass one canonical object
that describes filtering, projection, relationships, ordering, and pagination;
then pass execution options only when no request context is active.

```ts title="src/read-posts.ts"
import { Post } from './schemas.js'
import { ultimabase } from './ultimabase.js'

export const readPublishedPosts = () =>
	Post.findMany(
		{
			limit: 20,
			orderBy: { createdAt: 'desc', id: 'asc' },
			select: { createdAt: true, title: true },
			where: { published: { eq: true } },
		},
		{ ultimabase },
	)
```

The schema, fields, operators, and result projection are correlated. Typegen
makes invalid fields fail at compile time; Core repeats structural validation
for JavaScript and transport input before Runtime reaches an adapter.

## Read terminals

| Terminal                       | Result               | No visible match | Use it for                              |
| ------------------------------ | -------------------- | ---------------- | --------------------------------------- |
| `findMany(input?, options?)`   | Readonly model array | Empty array      | A filtered collection                   |
| `findOne(input?, options?)`    | One model or `null`  | `null`           | The first match under explicit ordering |
| `get({ id, ... }, options?)`   | One model            | `NOT_FOUND`      | One known stable identity               |
| `count({ where? }, options?)`  | `number`             | `0`              | Collection cardinality                  |
| `exists({ where? }, options?)` | `boolean`            | `false`          | A low-cost presence check               |

`findOne` and `get` communicate different expectations. Use `get` when absence
is exceptional and the ID is already known. Use `findOne` when a filter may
legitimately match nothing.

## Execution context

Inside an active request, hook, or transaction, a read inherits the exact
application, request context, cancellation signal, authority, and transaction:

```ts
const post = await Post.findOne({ where: { published: { eq: true } } })
```

For a root script, worker, or test, pass the started application explicitly as
the final argument, as the first example does. Execution options are not part
of the query and are never serialized by a transport.

## Reusable dynamic queries

Object input is the primary API. Use `QueryBuilder` when conditions are composed
programmatically or reused as a typed scope:

```ts title="src/recent-posts.ts"
import { QueryBuilder, type QueryScope } from '@ultimabase/core'

import { Post } from './schemas.js'

const published: QueryScope<typeof Post> = (query) =>
	query.where({ published: { eq: true } })

export const recentPublishedPosts = new QueryBuilder(Post)
	.select({ createdAt: true, title: true })
	.use(published)
	.descending('createdAt')
	.ascending('id')
	.limit(25)
	.build()
```

Every builder method returns a new frozen branch. `build()` emits the same
canonical object accepted by `Post.findMany`; the builder performs no I/O and
retains no application or authority.

[Selections](./selections).
