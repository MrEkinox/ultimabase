Nested writes belong to `createOne`, `updateOne`, and a persisted model's
`update` command. They execute as one ordered graph inside the root automatic
transaction.

```ts title="src/nested-posts.ts"
import { Post } from './schemas.js'
import { ultimabase } from './ultimabase.js'

export const createPostGraph = (existingCommentId: string) =>
	Post.createOne(
		{
			data: {
				author: {
					create: {
						displayName: 'Ada',
						email: 'ada@example.com',
					},
				},
				comments: {
					connect: [existingCommentId],
					create: [{ body: 'First' }, { body: 'Second' }],
				},
				slug: 'nested-post',
				title: 'Nested post',
			},
			include: {
				author: { select: { displayName: true } },
				comments: { select: { body: true } },
			},
		},
		{ ultimabase },
	)

export const revisePostGraph = (
	postId: string,
	commentId: string,
	oldCommentId: string,
) =>
	Post.updateOne(
		{
			data: {
				author: { update: { displayName: 'Ada Lovelace' } },
				comments: {
					create: [{ body: 'Third' }],
					disconnect: [oldCommentId],
					update: [{ data: { body: 'Edited' }, id: commentId }],
				},
			},
			id: postId,
		},
		{ ultimabase },
	)
```

| Field    | Create root                        | Update root                                                                           |
| -------- | ---------------------------------- | ------------------------------------------------------------------------------------- |
| Pointer  | exactly one of `connect`, `create` | exactly one of `connect`, `create`, `update`, `disconnect`                            |
| Relation | incremental `connect` and `create` | incremental `connect`, `create`, `update`, `disconnect`, or exclusive `set` / `clear` |

Incremental relation commands may coexist and run in the documented order.
`set` and `clear` are exclusive replacement commands. They operate on visible
membership: policy-hidden edges are retained rather than silently removed.

The default graph budget is depth 5 and 100 nested operations; applications may
configure stricter positive limits. Nested delete and upsert commands are not
available. Neither are nested commands on bulk roots, upserts, or drafts. A
failure anywhere rolls back the graph—there is no partial-success branch.
