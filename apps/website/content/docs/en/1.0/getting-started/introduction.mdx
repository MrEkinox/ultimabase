UltimaBase is an open-source, Node.js-first framework for building typed data
applications from static TypeScript schemas. You declare the data model and
choose explicit plugins; UltimaBase compiles that graph and sends every
operation through one Runtime pipeline.

<Callout title="Pre-release contract">
	UltimaBase is under active development before its first stable release. The
	documentation describes behavior that exists today, but public APIs may still
	change deliberately.
</Callout>

## What you will build

This journey creates one `Task` schema, connects it to PostgreSQL, starts the
application, writes one record, and closes the owned database connection. It
uses direct TypeScript only, so transport concerns do not obscure the first
working result.

By the end, you will have seen the central contract:

**One compiled application path**

The schema and selected plugins become the application Runtime truth.

## Prerequisites

You should be comfortable creating a small TypeScript project and setting an
environment variable. You need Node.js 24 or newer and a PostgreSQL database
that is safe to use for development.

No prior UltimaBase knowledge is required. Continue with
[Installation](./installation).

## Steps

UltimaBase deliberately keeps concrete behavior optional:

1. Core owns schemas, the application graph, immutable query and mutation APIs,
   structural validation, transactions, and the shared Runtime pipeline.
2. Plugins add concrete capabilities such as PostgreSQL, validation, access
   policy, authentication, REST, or GraphQL.
3. Your configured graph — not generated code — is the authoritative Runtime
   application.

That separation lets a small application install only what it uses. It also
makes infrastructure, security, and transport boundaries visible in code.

## Expected result

UltimaBase is a good fit when you want a typed TypeScript data application,
PostgreSQL as a first-class persistence path, immutable builders, and explicit
composition instead of a hidden all-in-one server.

It is not a hosted backend service, a Parse Server-compatible clone, or a way
for application code to write Drizzle queries directly. Authentication,
authorization, HTTP, REST, GraphQL, and operational infrastructure are not
silently installed by Core.
