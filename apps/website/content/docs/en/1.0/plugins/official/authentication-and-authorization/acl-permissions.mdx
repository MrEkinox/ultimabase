`@ultimabase/acl-permissions-plugin` adds one persisted ACL to each schema that opts
in. An ACL grants object-level `read`, `update`, and `delete` rights to public,
authenticated, exact-principal, and role subjects.

```ts
import { ACL } from '@ultimabase/acl-permissions-plugin'

import { AppRole, Member } from './schemas.js'

const alice = Member.pointer('0199b38e-ef80-7000-8000-000000000001')

export const articleACL = new ACL()
	.grantPublic('read')
	.grantPrincipal(alice, 'read', 'update')
	.grantRole(AppRole.role('editor'), 'read', 'update')

export const withoutPublicRead = articleACL.revokePublic('read')
```

`ACL` is immutable: every grant or revoke returns a new value. `toJSON()` produces a
detached, versioned format; `ACL.fromJSON()` validates it strictly and restores a
canonical value.

Install `aclPlugin()` and add the schema-level `acl` option. The plugin contributes
its policy directly through Core protected constraints and adapter constraints. It
does not depend on or peer with `@ultimabase/access-plugin`; both may be installed,
and their restrictions compose with logical `AND`.

The reserved ACL field is stored atomically with the object and indexed by supported
database plugins. Non-Master requests cannot select, filter, order by, or replace it.
Create defaults and `resolveInput` may derive policy from the proposed data and the
current neutral principal. Explicit ACL input is Master-only and still requires the
schema's input resolver.

Authentication and Roles are optional subject providers. They resolve exact public
schema references, while ACL remains independent of their concrete packages. The
default size limits are 100 principals and 50 roles per object.

Master bypasses ACL authorization, but not ACL size validation, reference integrity,
input resolution, change events, or transaction behavior.
