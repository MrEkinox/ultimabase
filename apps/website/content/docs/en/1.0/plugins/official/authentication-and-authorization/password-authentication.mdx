`@ultimabase/password-auth-plugin` owns one local `User` identity domain per
application. The public User schema is available to server Query and Typegen, while
password verifiers and session records live in owner-private storage. Query,
generated transports, Hooks, Access, ordinary observers, and raw adapter surfaces
cannot discover that private storage.

```ts
import { MasterAuthority, UltimaBase } from '@ultimabase/core'
import {
	PasswordUserSchema,
	passwordAuthOperations,
	passwordAuthPlugin,
} from '@ultimabase/password-auth-plugin'

const AppUser = PasswordUserSchema.define({
	className: 'User',
	fields: (field) => ({ displayName: field.string() }),
})

const ultimabase = new UltimaBase({
	masterAuthority: new MasterAuthority({
		keys: [{ id: 'server', value: 'read-from-a-secret-store' }],
		onUse: (event) => {
			console.info('Master use', event.reason)
		},
	}),
	plugins: [passwordAuthPlugin({ user: AppUser })],
	schemas: [],
})

const signedUp = await ultimabase
	.operation(passwordAuthOperations.signUp)
	.execute({
		username: 'Ada',
		password: 'correct horse battery staple',
	})

const auth = ultimabase.application.getPlugin(
	'@ultimabase/password-auth-plugin',
)
await auth.runWithSession(signedUp.session.token, () => AppUser.findMany())
```

`signUp`, `login`, `logout`, and `refresh` are transport-neutral operations. They
remain private until explicitly exposed by REST or GraphQL. Sign-up temporarily
uses the configured Master authority to create the User and records one audit event;
the resulting session still has anonymous Core authority.

## Session contract

- Tokens contain 32 random bytes and start with `ub_s1.`; storage keeps only their
  SHA-256 digest.
- Rolling expiry defaults to seven days, with a thirty-day absolute ceiling.
- Refresh rotates atomically. Exactly one concurrent refresh wins, and the old token
  becomes invalid at commit.
- Logout revokes only the current session. Multiple sessions per User are allowed.
- V1 has no recovery, MFA, device list, logout-all, automatic refresh, or rate
  limiter.

HTTP accepts exactly one `Authorization: Bearer <token>` by default. Missing
credentials remain anonymous; malformed, expired, revoked, unknown, or foreign-app
tokens fail before route dispatch.

Cookie mode is opt-in. Its `__Host-` cookie is always `Secure`, `HttpOnly`,
host-only, and `Path=/`. It requires exact allowed browser origins with credentials,
JSON, a matching non-null `Origin`, and `X-UltimaBase-Application-Id`. Sending both
Bearer and cookie credentials is rejected as ambiguous. Sign-up and login alone may
ignore one stale cookie so the browser can replace it.

> **Security boundary:** A valid session adds a principal and session value to the
> request. It does not grant reads, writes, roles, ACL rights, or Master authority.
