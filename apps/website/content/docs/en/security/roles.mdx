`@ultimabase/roles-plugin` models application-local role membership and hierarchy.
A role reference is stable and immutable; use a normalized name for declarations or
an exact UUID when identity must survive a rename.

```ts fixture="security/roles.ts"
import { AppRole } from './schemas.js'

export const editor = AppRole.role('editor')
export const administrator = AppRole.role('administrator')
```

Define the role schema with the exact member schema, then install `rolesPlugin()`.
`hasRole(AppRole.role('editor'))` is an official Access decision, so using it in an
`access` declaration also requires `accessPlugin()`.

Roles can also resolve neutral role subjects for ACL without importing or depending
on Access. This keeps membership storage separate from the policy that consumes it.

> **Security boundary:** A role, a role hierarchy, and an authenticated principal
> grant nothing by themselves. Permission exists only when an installed policy such
> as Access or ACL explicitly consumes that subject. Master authority does not imply
> role membership.
