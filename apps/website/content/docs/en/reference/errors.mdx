## Signature

```ts
import { FrameworkError, frameworkErrorCodes } from '@ultimabase/core'

const error = new FrameworkError('NOT_FOUND', 'Trusted diagnostic', {
	publicMessage: 'The requested object was not found.',
	publicDetails: { resource: 'Post' },
	retryable: false,
})
```

## Parameters

The constructor accepts a declared `FrameworkErrorCode`, a non-empty diagnostic
message, and optional `cause`, `publicMessage`, `publicDetails`,
`internalDetails`, and `retryable` values.

| Boundary                    | Representative stable codes                                                                                         | Diagnostic path                                                    |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| Core data                   | `VALIDATION_ERROR`, `NOT_FOUND`, `PERMISSION_DENIED`, `TRANSACTION_ERROR`                                           | owning concept or guide                                            |
| Core plugins                | `PLUGIN_DEPENDENCY_MISSING`, `PLUGIN_CAPABILITY_CONFLICT`, `PLUGIN_PRIVILEGE_DENIED`, `PLUGIN_DECLARATION_INVALID`  | [startup](../troubleshooting/startup)                              |
| PostgreSQL                  | sanitized `INTERNAL_ERROR` or schema `VALIDATION_ERROR`                                                             | [PostgreSQL](../troubleshooting/postgres)                          |
| Typegen                     | `SCHEMA_TYPEGEN_FAILED` with a stable reason                                                                        | [Typegen](../troubleshooting/typegen)                              |
| HTTP before dispatch        | `HTTP_BAD_REQUEST`, `HTTP_APPLICATION_REJECTED`, `HTTP_NOT_FOUND`, `HTTP_REQUEST_TIMEOUT`, `HTTP_INTERNAL_ERROR`    | [HTTP identity](../troubleshooting/http-and-application-identity)  |
| REST after dispatch         | `REST_READ_INVALID_INPUT`, `REST_READ_BODY_TOO_LARGE`, `REST_INTERNAL_ERROR` and operation-specific public mappings | owning API page                                                    |
| GraphQL compilation/runtime | `GRAPHQL_SCHEMA_COMPILATION_FAILED`, `GRAPHQL_INVALID_CURSOR`, safe GraphQL extensions                              | owning API page                                                    |
| Password Auth               | `PASSWORD_AUTH_INVALID_CREDENTIALS`, `PASSWORD_AUTH_INVALID_SESSION`, `PASSWORD_AUTH_SIGN_UP_REJECTED`              | [authentication](../troubleshooting/http-and-application-identity) |

## Defaults

`retryable` defaults to `false`. Diagnostic message, stack, cause, and internal
details are private. Unknown failures collapse to the owning boundary's fixed
internal-error representation.

## Returns

`error.toJSON()` returns only `{ code, retryable, message?, details? }` using
explicitly public values. REST and GraphQL map that payload into their own wire
envelopes. HTTP failures before route dispatch keep the protocol-neutral HTTP
envelope.

## Errors

Constructing a `FrameworkError` with an unknown code or malformed options throws
`TypeError`. A plugin may expose only error codes declared on its operation and
mapped by the selected transport; undeclared errors are masked.

## Example

```ts
try {
	await Post.get({ id: postId })
} catch (error: unknown) {
	if (error instanceof FrameworkError && error.code === 'NOT_FOUND') {
		return null
	}
	throw error
}
```
