## Symptom

Startup may fail with the public message `The database connection could not be
established.` and `INTERNAL_ERROR`. The failure is retryable, but its driver
message is intentionally private. Schema preparation instead reports
`VALIDATION_ERROR` when `schemaPolicy: 'fail'` detects drift or an unsupported
live structure. A query or transaction failure occurs only after startup.

## Cause

Connection failures commonly mean the configured endpoint is unavailable, the
credential is invalid, TLS requirements differ, or the database rejected the
client. Schema failures mean the registered UltimaBase graph and the live
namespace differ, or the live table uses a structure direct synchronization
cannot safely replace. Operation failures can also be ordinary constraints or
transaction rollbacks.

## Confirm

First check presence without printing the connection value:

```sh
node -e "process.exit(process.env.DATABASE_URL ? 0 : 1)"
```

Confirm the same URL and TLS settings with your provider's supported client.
Do not paste the URL into a shell history or issue. If startup succeeds, the
public connection service reports `connected`:

```ts
import { postgresPluginName } from '@ultimabase/postgres-plugin'

const { connection } = app.application.getPlugin(postgresPluginName)
console.log(connection.state)
```

For suspected drift, temporarily choose `schemaPolicy: 'fail'` in a controlled
environment and inspect the trusted server diagnostic. Never return its raw
cause, SQL, or connection details to an HTTP client.

## Resolve

- Correct the endpoint, credential, database availability, or provider-required
  TLS configuration, then start a fresh application.
- For expected additive drift, review the plan and apply the supported direct
  synchronization or an owned migration after a backup.
- Use explicit `renamedFrom` metadata for a deliberate column rename.
- Keep unsupported structures under a migration owner; do not approximate them
  with `schemaPolicy: 'override'`.
- Use `ignore` only when another reviewed process owns the schema. It is not a
  general workaround for unexplained drift.

Direct synchronization does not infer destructive removal of unmatched tables
or columns.

## Escalate

Record the UltimaBase and PostgreSQL versions, selected schema policy, sanitized
driver code when available, application lifecycle stage, and a minimal schema.
Exclude URLs, usernames, passwords, certificates, SQL values, and raw causes.
Then follow [Reporting a problem](./reporting-a-problem).

See [operating PostgreSQL](../operations/postgres),
[transactions](../mutations/transactions), and the [error reference](../reference/errors).
