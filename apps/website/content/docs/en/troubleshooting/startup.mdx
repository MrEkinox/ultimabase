## Symptom

`await app.start()` rejects before the application accepts work. Keep the stable
error code and lifecycle stage; do not reduce every startup failure to a database
problem.

| Diagnostic | Meaning |
| --- | --- |
| `PLUGIN_DEPENDENCY_MISSING` or `PLUGIN_DEPENDENCY_CYCLE` | the static plugin graph cannot be ordered |
| `PLUGIN_DUPLICATE` or `PLUGIN_CONFLICT` | identity or replacement is ambiguous |
| `PLUGIN_CAPABILITY_MISSING` or `PLUGIN_CAPABILITY_CONFLICT` | an application capability has no valid composition |
| `PLUGIN_PROTOCOL_INCOMPATIBLE` | two versioned contracts cannot communicate |
| `PLUGIN_PRIVILEGE_DENIED` | policy rejected a requested privilege or environment claim |
| `PLUGIN_DECLARATION_INVALID` | a static contribution violates its public contract |

A plain `TypeError` usually points to malformed options or an unknown key.

## Cause

Typical causes are a missing required plugin, duplicate instances without
distinct instance IDs, incompatible capability versions, a denied privilege,
or invalid configuration. Constructors compile and snapshot the static graph;
`start()` then runs setup, preparation, connection, and start in dependency
order. The first failed stage triggers cleanup.

## Confirm

Capture only stable identity at the application boundary:

```ts
import { FrameworkError } from '@ultimabase/core'

try {
	await app.start()
} catch (error: unknown) {
	const diagnostic =
		error instanceof FrameworkError
			? { code: error.code, retryable: error.retryable }
			: { name: error instanceof Error ? error.name : 'UnknownError' }

	console.error('UltimaBase startup failed', diagnostic)
	throw error
}
```

Review the default plugin report for exact plugin and instance IDs, declared
privileges, reasons, severity, and environmental claims. Also run the project
checks that validate dependency direction and TypeScript configuration:

```sh
yarn constraints
yarn typecheck
```

## Resolve

- Install a missing dependency or correct its compatible version range.
- Give deliberate duplicate configurations distinct instance IDs and keep
  capability ownership unambiguous.
- Grant only the exact privilege whose documented behavior the application
  needs; do not replace policy with an allow-all rule.
- Correct invalid options at the reported owner, then construct a fresh
  application. A disposed application cannot be restarted.
- If startup reached an infrastructure stage, follow the dedicated
  [PostgreSQL](./postgres) or [Typegen](./typegen) path.

Never treat disabling validation, Hooks, authorization, or privilege checks as
a recovery step.

## Escalate

If the public code and plugin identities do not identify the misconfiguration,
prepare a minimal graph containing only the failing schemas and plugins. Record
the first error code and whether cleanup also failed, sanitize all diagnostics,
then use [Reporting a problem](./reporting-a-problem).

See [plugin lifecycle](../plugins/lifecycle-and-dependencies),
[manifests and privileges](../plugins/manifests-and-privileges), and the
[error reference](../reference/errors).
