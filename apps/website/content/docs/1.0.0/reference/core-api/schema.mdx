## Signature

```ts
import { Schema } from '@ultimabase/core'

const Post = Schema.define({
	className: 'Post',
	fields: (field) => ({ title: field.string({ required: true }) }),
	indexes: [{ fields: ['title'] }],
})
```

`Schema.define()` creates the final immutable class. The `fields` callback is
retained until application compilation, after installed plugins have declared
their application-local methods and options.

## Parameters

| Property        | Required       | Meaning                                                                                               |
| --------------- | -------------- | ----------------------------------------------------------------------------------------------------- |
| `className`     | yes            | Stable logical model name and Typegen identity                                                        |
| `fields(field)` | yes            | Map of stored, relationship, and virtual declarations                                                 |
| `indexes`       | no             | Ordered single or composite logical indexes                                                           |
| plugin options  | only when used | Direct options such as `access`, `hooks`, `rest`, `graphql`, or `postgres` owned by installed plugins |

Names colliding with system fields, Query operators, or immutable model methods
are rejected. Relationship targets resolve against the complete application
graph, so declarations may use a class name or a lazy target.

## Defaults

Every schema receives protected `id`, `createdAt`, and `updatedAt` system fields.
Plugin-owned options do not exist unless their plugin is configured. Omitting a
transport option uses that transport plugin's exposure defaults; it never grants
authorization.

## Returns

The returned class constructs immutable drafts and exposes schema-root read and
mutation commands after it belongs to a compiled application. Use
`ultimabase.schema(Post)` for configuration-dependent application commands and
plugin-created schemas.

## Errors

Field-dependent metadata accessed before compilation throws
`SchemaCompilationError`. Duplicate names, unresolved relationships, unknown
plugin options, and incompatible application reuse fail before plugin setup or
database connection.

## Example

```ts
const Article = Schema.define({
	className: 'Article',
	fields: (field) => ({
		author: field.pointer({ target: 'Author' }),
		slug: field.string({ indexed: 'unique', required: true }),
	}),
})

const Articles = ultimabase.schema(Article)
await Articles.findMany({ select: { id: true, slug: true } })
```
