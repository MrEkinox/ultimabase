Use this page to choose package roots, not to configure each plugin. The
[Manual Installation](/docs/1.0.0/manual-installation) guide builds a working
application; the linked plugin pages own their setup, options, and limitations.

## Platform and version compatibility

| Boundary             | Current documented baseline                                                                                                 |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Runtime              | Node.js 24 or newer                                                                                                         |
| Modules              | ESM                                                                                                                         |
| Application examples | TypeScript; generated types are not needed at Runtime                                                                       |
| Persistence          | Core is database-independent; PostgreSQL requires the optional [PostgreSQL plugin](/docs/1.0.0/plugins/official/postgresql) |

This site currently has one documentation line, `1.0.0`. Its URL identifies
the documentation you are reading; it does **not** prove that an npm package
with that version has been published or promise a stable compatibility window.
The repository packages are still pre-release. Check the version you actually
install and the [release status](/docs/1.0.0/project/release-status) before adopting an
example. When maintained documentation lines are added, use the version
selector to match the line you use.

Core and Shared are configured as one fixed version group for releases.
Official plugins are versioned independently. Each plugin manifest declares
compatibility, dependencies, capability protocols, and provider requirements.
A matching documentation line alone cannot make an incompatible plugin set
work. Review the owning plugin page and
[Using Plugins](/docs/1.0.0/plugins/using-plugins)
when adding or upgrading one. Community plugins own their own version claims;
a listing is not a compatibility guarantee.

## Public package roots

Import only the package root. A path into a package's `src/` directory is not
part of its public contract. Importing a plugin package does not install its
behavior; add its factory to your application graph.

Every current package exposes its root `.` entry; the initializer also provides
its `create-app` executable. Package roots provide
public exports; generated Typegen declarations augment editor types but never
replace the compiled application as Runtime truth. A deep import may fail
package resolution, and a missing plugin or capability fails application
compilation or startup rather than silently enabling substitute behavior.

## Install the smallest set

For an application using PostgreSQL, install Core and that plugin. Use the
package manager of your application:

```bash tab="npm" tab-group="package-manager"
npm install @ultimabase/core @ultimabase/postgres-plugin
```

```bash tab="yarn"
yarn add @ultimabase/core @ultimabase/postgres-plugin
```

```bash tab="pnpm"
pnpm add @ultimabase/core @ultimabase/postgres-plugin
```

Then follow [Manual Installation](/docs/1.0.0/manual-installation) to configure
and start the application. Add only the other plugins that your application
uses; do not import package-private files to reach an unlisted API.
