## What you will build

The initializer creates a Node.js application with a `Task` schema,
PostgreSQL persistence, and a start script that writes one Task. You choose
TypeScript or JavaScript, optional HTTP APIs and plugins, and either a local
Docker database or one you already run. The result is an ordinary project:
you own its schema and application configuration.

## Prerequisites

- Node.js 24 or newer and npm, yarn, or pnpm.
- For the path below, Docker Compose and a disposable local database.
- For the existing-database path, a separate disposable PostgreSQL database
  and its connection URL. The initializer does not create that database.

<Callout type="warn" title="Use only disposable data">
	The generated application uses PostgreSQL's `override` schema policy for local
	development. Do not point it at shared or production data.
</Callout>

## Steps

### 1. Start the initializer

After publication, use the command for the package manager you want in the
generated project:

```bash tab="npm" tab-group="package-manager"
npm create @ultimabase/app@latest
```

```bash tab="yarn" tab-group="package-manager"
yarn dlx @ultimabase/create-app@latest
```

```bash tab="pnpm" tab-group="package-manager"
pnpm dlx @ultimabase/create-app@latest
```

`npx @ultimabase/create-app@latest` will also launch the same package after
publication. It detects npm as the invoking manager; add
`--package-manager yarn` or `--package-manager pnpm` if that manager should
install dependencies in the generated project.

### 2. Choose the project

For a first run, answer the prompts as follows:

| Prompt                             | Choose                                | Effect                                                                                            |
| ---------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Project name and destination       | `notes`; accept the `notes` directory | Creates a new directory. Existing paths are never overwritten.                                    |
| Language                           | TypeScript                            | Includes Typegen before typecheck and build.                                                      |
| How will clients access your data? | None                                  | Uses direct application calls; no HTTP listener. REST and GraphQL can be selected together later. |
| Official plugins                   | No additional plugins                 | PostgreSQL is included automatically.                                                             |
| Starter                            | Runnable Task example                 | Defines `Task` and writes one record on start.                                                    |
| PostgreSQL                         | Local Docker Compose                  | Writes `compose.yaml` and a private `.env`.                                                       |
| Install dependencies now?          | Yes                                   | Installs with the invoking package manager before creating the destination.                       |
| Create this project?               | Yes                                   | Confirms the displayed plan.                                                                      |

The summary identifies automatic dependencies. These are its key lines for
the npm answers above:

```text
Language: TypeScript + automatic Typegen
Data APIs: none; direct application calls
Plugins: @ultimabase/postgres-plugin (included)
Starter: task; database: docker; manager: npm
Install dependencies: yes
```

The manager line reads `yarn` or `pnpm` when launched through those
managers. Cancelling before confirmation leaves the destination untouched.

The official plugin question groups all 16 shipped plugins. The earlier API
answer and this selector share one selection:

| Group            | Available choices                                                        |
| ---------------- | ------------------------------------------------------------------------ |
| Data & behavior  | PostgreSQL, Hooks, Validation, Soft Delete, PostgreSQL Vector            |
| Security         | Password Auth, Access, Roles, Object ACLs                                |
| HTTP & explorers | HTTP, Hono server, REST, GraphQL, GraphQL Yoga, GraphiQL, Apollo Sandbox |

REST includes HTTP and Hono. GraphQL selected as an HTTP API includes
GraphQL, Yoga, HTTP, and Hono. Advanced plugin choices can keep GraphQL
network-independent or add a development-only explorer. See [Using
Plugins](/docs/1.0.0/plugins/using-plugins) for the composition rules.

The TypeScript and Docker choices above create:

`schema.ts` defines Task. `ultimabase.ts` composes Core, PostgreSQL, and
Typegen in one graph. `main.ts` starts the application, writes a Task, and
disposes it. The package depends on `@ultimabase/core`,
`@ultimabase/postgres-plugin`, and `@ultimabase/typegen`; TypeScript and
`@types/node` are development dependencies. Its scripts are:

```json title="package.json — TypeScript scripts"
{
	"generate:types": "node --env-file=.env scripts/generate-types.mjs",
	"typecheck": "node --env-file=.env scripts/generate-types.mjs && tsc --noEmit",
	"build": "node --env-file=.env scripts/generate-types.mjs && tsc",
	"start": "node --env-file=.env dist/main.js"
}
```

Typecheck or build writes `.ultimabase/schema.generated.d.ts`. It is a
replaceable declaration, not a Runtime client. The output is ignored by Git;
regenerate it when schemas or plugins change. [Generate TypeScript
Types](/docs/1.0.0/guides/generate-types) explains the contract.

JavaScript instead writes `src/schema.js`, `src/ultimabase.js`, and
`src/main.js`. It has no `tsconfig.json`, Typegen script, TypeScript
dependency, or generated declaration. Its base dependencies are Core and
PostgreSQL. With an existing database, its initial tree is:

	<Folder name="src" defaultOpen>
		<File name="schema.js" />
		<File name="ultimabase.js" />
		<File name="main.js" />
	</Folder>
	<File name=".env.example" />
	<File name=".gitignore" />

	<File name="README.md" />

It has one script:

```json title="package.json — JavaScript scripts"
{
	"start": "node --env-file=.env src/main.js"
}
```

With an existing database, either language writes `.env.example` but not
`.env` or `compose.yaml`. The generated README records the selected plugins
and exact next steps.

### 4. Start PostgreSQL and run the application

For the Docker choice, enter the directory and start the database:

```bash
cd notes
docker compose up -d
```

For an existing database, copy `.env.example` to `.env` and replace its
`DATABASE_URL` placeholder with your disposable database URL. Keep the file
private. Security plugin choices may also require a local Master key; the
generated README identifies the value without printing it.

The default flow installs dependencies during generation. If you chose
`--no-install` or answered No, first run `npm install`, `yarn install`, or
`pnpm install` in the generated directory. Then run the TypeScript scripts:

```bash tab="npm" tab-group="package-manager"
npm run typecheck
npm run build
npm start
```

```bash tab="yarn" tab-group="package-manager"
yarn typecheck
yarn build
yarn start
```

```bash tab="pnpm" tab-group="package-manager"
pnpm typecheck
pnpm build
pnpm start
```

For JavaScript, skip typecheck and build; use `npm start`, `yarn start`, or
`pnpm start`. Typegen loads the TypeScript configuration without connecting
to PostgreSQL. Starting the application connects to the database.

## Expected result

The Task starter prints a new record with a generated `id`,
`title: 'Ship the first feature'`, and `done: false`. Starting it again
writes another record. The empty starter instead prints
`UltimaBase is ready` and has no Task to query.

If you selected REST or GraphQL, the application also listens on
`127.0.0.1:1337` until you stop it. Its README supplies local requests with
`X-UltimaBase-Application-Id: main`. Generated Task API mutations are
disabled; the seed write is a server-side call. The loopback listener and
unverified-protection acknowledgement are not a public security policy.

## Choose a different path

For automation, use flags. This example selects both HTTP APIs and Hooks
without installing dependencies:

```bash tab="npm" tab-group="package-manager"
npm create @ultimabase/app@latest -- --name api-notes --language ts --api rest --api graphql --plugin @ultimabase/hooks-plugin --starter task --database docker --package-manager npm --no-install
```

```bash tab="yarn" tab-group="package-manager"
yarn dlx @ultimabase/create-app@latest --name api-notes --language ts --api rest --api graphql --plugin @ultimabase/hooks-plugin --starter task --database docker --package-manager yarn --no-install
```

```bash tab="pnpm" tab-group="package-manager"
pnpm dlx @ultimabase/create-app@latest --name api-notes --language ts --api rest --api graphql --plugin @ultimabase/hooks-plugin --starter task --database docker --package-manager pnpm --no-install
```

Without a terminal, provide every choice as above or use `--yes` for
documented defaults. With `--yes` and no API flags, no HTTP API is selected.
`--yes` never permits overwriting an existing directory. Repeat
`--plugin @ultimabase/<id>` for multiple official plugins.

The selector does not invent capabilities. PostgreSQL Vector does not add
persisted vector search. Password Auth identifies callers but does not grant
data access; Roles do not grant permission by themselves. Access or Object
ACLs may intentionally deny sample reads. Password Auth operations appear
over a selected API only through an exact allowlist. GraphiQL and Apollo
Sandbox, including the introspection they need, are development-only in the
generated configuration. Review [Password
Authentication](/docs/1.0.0/plugins/official/password-authentication),
[Access](/docs/1.0.0/plugins/official/access),
[REST](/docs/1.0.0/plugins/official/rest), and
[GraphQL](/docs/1.0.0/plugins/official/graphql) before changing those defaults.
