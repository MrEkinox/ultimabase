Load secrets from your deployment environment or secret manager and validate them at
startup. Never commit them, include them in generated files, or compile them into a
browser bundle.

```ts
import { MasterAuthority } from '@ultimabase/core'

const masterKey = process.env.ULTIMABASE_MASTER_KEY
if (masterKey === undefined)
	throw new TypeError('ULTIMABASE_MASTER_KEY is required')

export const masterAuthority = new MasterAuthority({
	keys: [{ id: 'primary', value: masterKey }],
	onUse: async (event) => {
		await recordMasterAudit(event)
	},
})

declare const recordMasterAudit: (event: Readonly<object>) => Promise<void>
```

Database URLs stay inside the PostgreSQL plugin. Password verifiers and session token
digests stay in Password Auth owner-private storage. Raw session tokens appear only at
issuance or their credential boundary. Master keys stay server-side, and every
successful elevation must complete an audit.

See [Master Authority](/docs/1.0.0/core/security-foundations/master-authority) and
[HTTP Applications](/docs/1.0.0/plugins/official/http-and-apis/http) for the exact transport boundary.
