## Startup and plugin graph

### Symptom

Application construction or `start()` fails before it accepts work. Keep the
first stable error code and the lifecycle stage; not every startup failure is
a database problem.

| Diagnostic                                                  | Likely boundary                                     |
| ----------------------------------------------------------- | --------------------------------------------------- |
| `PLUGIN_DEPENDENCY_MISSING` or `PLUGIN_DEPENDENCY_CYCLE`    | The plugin dependency graph cannot be ordered.      |
| `PLUGIN_DUPLICATE` or `PLUGIN_CONFLICT`                     | Identity or replacement is ambiguous.               |
| `PLUGIN_CAPABILITY_MISSING` or `PLUGIN_CAPABILITY_CONFLICT` | A capability has no valid provider or composition.  |
| `PLUGIN_PROTOCOL_INCOMPATIBLE`                              | Two versioned contracts cannot communicate.         |
| `PLUGIN_PRIVILEGE_DENIED`                                   | Policy denied a privilege or environmental claim.   |
| `PLUGIN_DECLARATION_INVALID`                                | A static contribution violates its public contract. |

A plain `TypeError` can indicate malformed options or an unknown key. See
[API Error Boundaries](/docs/1.0.0/core/runtime/api-errors#frameworkerror)
for the public `FrameworkError` contract.

### Cause

Construction checks the configured graph. Starting the application then
compiles declarations, runs plugin setup, connects resources, prepares schemas,
and starts Runtime and transports in dependency order. The first failed stage
triggers cleanup of completed stages. A missing provider, incompatible version,
denied privilege, invalid declaration, or infrastructure failure can stop this
sequence.

### Confirm

At the boundary that constructs or starts your application, report only safe
diagnostic identity. This helper does not print a connection string, raw
driver cause, or secret:

```ts title="src/report-startup-failure.ts"
import { FrameworkError } from '@ultimabase/core'

export const reportStartupFailure = (error: unknown): void => {
	const diagnostic =
		error instanceof FrameworkError
			? { code: error.code, retryable: error.retryable }
			: { name: error instanceof Error ? error.name : 'UnknownError' }

	console.error('UltimaBase startup failed', diagnostic)
}
```

Call this helper in the catch around `await ultimabase.start()` in your entry
point, then rethrow the error and keep your normal disposal flow.

Review the default plugin report for exact plugin and instance IDs, requested
privileges, reasons, severity, and environmental claims. Preserve the first
failure even if cleanup reports another one. Repository contributors can run
the checks in [Contributing](https://github.com/MrEkinox/ultimadatabase/blob/main/CONTRIBUTING.md#definition-of-done);
those repository commands are not application setup steps.

### Resolve

- Install a missing dependency or choose a compatible version.
- Give deliberate multiple instances distinct IDs and remove ambiguous
  capability providers or replacements.
- Grant only the exact privilege required for the behavior you intend. Do not
  replace policy with an allow-all rule.
- Correct invalid options at their owner, then construct a fresh application.
  A disposed application cannot be restarted.
- If the failure reached an infrastructure or transport stage, follow that
  plugin's own troubleshooting section.

Never disable validation, Hooks, authorization, or privilege checks as a
recovery step.

### Escalate

Reduce the failure to the smallest graph of schemas and plugins that still
reproduces it. Record the first error code, stage, and whether cleanup also
failed. Remove secrets before following [Report a problem](#report-a-problem).

## Find the failing capability

- A connection or schema-preparation error belongs with
  [PostgreSQL troubleshooting](/docs/1.0.0/plugins/official/postgresql#troubleshooting).
- Application selection, browser policy, and pre-dispatch credential failures
  belong with [HTTP troubleshooting](/docs/1.0.0/plugins/official/http#troubleshooting).
- Password or session failures belong with
  [Password Authentication](/docs/1.0.0/plugins/official/password-authentication#troubleshooting).
- A missing or stale generated declaration belongs with
  [Typegen troubleshooting](/docs/1.0.0/guides/generate-types#troubleshooting-generation).

## Report a problem

Use this path when a documented public contract behaves differently in a
minimal application or a stable error has no actionable recovery. Report
suspected vulnerabilities through the repository's
[security policy](https://github.com/MrEkinox/ultimadatabase/blob/main/SECURITY.md),
never a public issue.

Record the runtime and installed package versions without printing environment
variables. Use the package manager of the affected application:

```bash tab="npm" tab-group="package-manager"
node --version
npm --version
npm ls @ultimabase/core
```

```bash tab="yarn"
node --version
yarn --version
yarn why @ultimabase/core
```

```bash tab="pnpm"
node --version
pnpm --version
pnpm why @ultimabase/core
```

Reduce the failure to the smallest schemas, plugins, configuration, and
command. Run it twice from a clean lifecycle. Keep stable error codes,
Typegen reasons, HTTP request IDs, and sanitized driver codes. Remove database
URLs, credentials, cookies, tokens, user data, raw causes, and Master material.

```md title="Issue report"
### Versions

Node, package manager, TypeScript, and every @ultimabase package

### Minimal reproduction

Repository or self-contained code plus the exact command

### Expected behavior

The documented observable result

### Actual behavior

Stable code, sanitized diagnostic, and lifecycle stage
```

Use the repository [issue tracker](https://github.com/MrEkinox/ultimadatabase/issues)
for non-security problems. Link the exact documentation page and public
package entry point involved.
