You can help by reporting a problem, improving the framework or its docs, or
building a community plugin. The repository's
[contribution guide](https://github.com/MrEkinox/ultimadatabase/blob/main/CONTRIBUTING.md)
has the complete pull-request requirements.

## Choose a contribution path

- **Report a bug or documentation gap.** [Open an issue](https://github.com/MrEkinox/ultimadatabase/issues/new)
  with the version or commit you used, the steps to reproduce, what happened,
  and what you expected. For a docs problem, include the page URL.
- **Improve the framework or its docs.** Pick a direction from the
  [roadmap](https://github.com/MrEkinox/ultimadatabase/blob/main/ROADMAP.md) or
  [open an issue](https://github.com/MrEkinox/ultimadatabase/issues/new) that
  describes the problem and the expected behavior before opening a pull
  request. A focused correction can go straight to a pull request.
- **Build a community plugin.** Follow [Build a Plugin](/docs/1.0.0/plugins/build-a-plugin),
  then use the [community plugin proposal](/docs/1.0.0/plugins/community-plugins#propose-a-plugin)
  for feedback or a future listing. A listing requires a published, reviewable
  package; an idea or prototype can still be proposed for feedback.

## Set up and verify a change

After cloning the repository, use Node.js 24 or newer and the pinned Yarn
version. Install dependencies from the repository root:

```bash title="Terminal"
corepack enable
yarn install --immutable
```

Run the tests for the area you changed first. For website content, run
`yarn website:validate` and `yarn website:typecheck`. For framework code, run
the relevant package tests, then `yarn typecheck`, `yarn test`, `yarn lint`,
and `yarn build` as appropriate. Database behavior also needs PostgreSQL
integration coverage. Record checks you could not run.

## Submit the result

Keep code, tests, examples, and affected documentation together. Add a
Changeset when a public package contract changes. In your
[pull request](https://github.com/MrEkinox/ultimadatabase/pulls), link the
issue, explain the developer-visible result and any architectural impact, and
list the checks you ran. Note whether the public docs needed an update and
why. The [definition of done](https://github.com/MrEkinox/ultimadatabase/blob/main/CONTRIBUTING.md#definition-of-done)
contains the full repository checklist.
