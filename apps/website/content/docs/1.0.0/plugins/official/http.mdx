## Overview

`@ultimabase/http-plugin` owns the Fetch-compatible application boundary. It does
not open a socket. Every real public request must carry exactly one public routing
identifier:

```http
X-UltimaBase-Application-Id: blog
```

## Installation

Install the application HTTP boundary:

```bash tab="npm" tab-group="package-manager"
npm install @ultimabase/http-plugin
```

```bash tab="yarn"
yarn add @ultimabase/http-plugin
```

```bash tab="pnpm"
pnpm add @ultimabase/http-plugin
```

For the optional Node.js Hono listener, install its separate provider:

```bash tab="npm" tab-group="package-manager"
npm install @ultimabase/server-hono-plugin
```

```bash tab="yarn"
yarn add @ultimabase/server-hono-plugin
```

```bash tab="pnpm"
pnpm add @ultimabase/server-hono-plugin
```

The existing-Hono-app example below also imports `hono` and
`@hono/node-server` directly; install those as direct dependencies if you use
that ownership mode.

```bash tab="npm" tab-group="package-manager"
npm install hono @hono/node-server
```

```bash tab="yarn"
yarn add hono @hono/node-server
```

```bash tab="pnpm"
pnpm add hono @hono/node-server
```

## Configuration

Give each public application one exact `appId`. Browser policy and request
timeout are optional; the example enables an explicit, restrictive browser
policy:

```ts
import { httpPlugin } from '@ultimabase/http-plugin'

export const applicationHttp = httpPlugin({
	appId: 'blog',
	browser: {
		allowedHeaders: ['Content-Type', 'X-UltimaBase-Application-Id'],
		allowedMethods: ['GET', 'POST'],
		allowedOrigins: ['https://console.example'],
		credentials: false,
		maxAgeSeconds: 600,
	},
	requestTimeoutMs: 15_000,
})
```

`httpPlugin()` also accepts `master: { enabled: true }`, but only when the
selected application has a configured `MasterAuthority`. Do not expose a raw
Master key to browser code.

## Behavior and limitations

### Browser policy

Browser-origin behavior is disabled by default. When enabled, all applications on
one server provider must declare the same effective policy. CORS controls browser
responses; it is not authentication, authorization, or protection from non-browser
clients. Preflight may run without an application ID, but it selects no application
and invokes no context resolver, credential check, route, Runtime, or database work.

List only the origins, methods, and headers the client actually uses. Wildcard
origin is incompatible with credentials, cookies, Authorization, or enabled
Master transport. CORS also does not provide CSRF protection.

### Application selection and authority

Application selection, duplicate sensitive headers, credentials, optional Master
verification, timeout, and request correlation run before a protocol handler. These
failures use the safe `HTTP_*` boundary. Once REST or GraphQL begins, that protocol
owns its response.

Enable the canonical Master header only with `master: { enabled: true }` and a
configured `MasterAuthority`. The selected application's authority verifies the raw
key and must complete its audit before dispatch. Alternative headers, body flags,
foreign credentials, contexts, and grants cannot select Master.

### Run a Node.js server with Hono

The HTTP plugin owns no listener. `@ultimabase/server-hono-plugin` is an optional
Node.js provider that consumes its HTTP capability. It does not install REST,
GraphQL, authentication, TLS, proxy trust, compression, or rate limiting.

#### Let UltimaBase own the listener

Without an existing Hono app, the server plugin creates a listener when
transports start, after the application graph has validated:

```ts
import { UltimaBase } from '@ultimabase/core'
import { httpPlugin } from '@ultimabase/http-plugin'
import { honoServerPlugin } from '@ultimabase/server-hono-plugin'

const server = honoServerPlugin({ host: '127.0.0.1', port: 1337 })

const application = new UltimaBase({
	plugins: [httpPlugin({ appId: 'blog' }), server],
	schemas: [],
})

await application.start()
```

The default port is `1337` if none is configured. Reuse the _same_ `server`
value to share one listener across applications with distinct HTTP `appId`
values. Every application on that provider must use the same effective browser
policy. Stopping one application removes its mount; the listener closes only
after the last attached application stops. Separate `honoServerPlugin()` calls
create independent providers, not a shared server.

#### Join an existing Hono app

Pass an existing `app` to add the UltimaBase dispatcher without letting
UltimaBase start or stop that app or its listener. This mode requires an
explicit `browserPolicyOwner` and rejects `host` or `port` on the plugin:

```ts
import { serve } from '@hono/node-server'
import { Hono } from 'hono'
import { UltimaBase } from '@ultimabase/core'
import { httpPlugin } from '@ultimabase/http-plugin'
import { honoServerPlugin } from '@ultimabase/server-hono-plugin'

const app = new Hono()
app.get('/health', (context) => context.text('ok'))

const application = new UltimaBase({
	plugins: [
		httpPlugin({ appId: 'blog' }),
		honoServerPlugin({ app, browserPolicyOwner: 'ultimabase' }),
	],
	schemas: [],
})

await application.start()
const listener = serve({ fetch: app.fetch, port: 1337 })
```

Choose `'ultimabase'` when HTTP owns the browser policy. If existing middleware
already owns CORS, choose `'external'` and keep the HTTP `browser` policy
disabled. The two owners cannot be combined to produce contradictory CORS
headers. With an existing app, use a Node integration that supplies Hono's
standard `incoming.rawHeaders` evidence; missing evidence fails closed.

## Troubleshooting

Before a route starts, HTTP returns a private, non-cacheable envelope with a
stable code and `X-UltimaBase-Request-Id`:

| Code                        | First interpretation                               |
| --------------------------- | -------------------------------------------------- |
| `HTTP_BAD_REQUEST`          | malformed or ambiguous request evidence            |
| `HTTP_APPLICATION_REJECTED` | application selection or credentials were rejected |
| `HTTP_NOT_FOUND`            | no selected route owns the path                    |
| `HTTP_REQUEST_TIMEOUT`      | the shared request deadline expired                |
| `HTTP_INTERNAL_ERROR`       | the pre-dispatch boundary failed safely            |

Reproduce without credentials first:

```sh
curl -i \
  -H 'X-UltimaBase-Application-Id: blog' \
  http://localhost:3000/api/v1/Post
```

Record status, stable error code, and request ID. Confirm the public `appId`,
mount, method, and route. Send exactly one application ID on real requests and
never combine Bearer and cookie credentials. Do not copy Authorization, Cookie,
Master values, or request bodies into logs or reports.

If the boundary still rejects the request, follow
[Reporting a problem](/docs/1.0.0/operations/application-troubleshooting#report-a-problem)
with sanitized evidence. Widening CORS or switching to Master authority cannot
repair invalid identity or credentials.
