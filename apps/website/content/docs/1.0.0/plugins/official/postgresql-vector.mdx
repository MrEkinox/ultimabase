## Overview

`@ultimabase/pg-vector-plugin` contributes the application-local
`field.vector({ dimensions })` builder and the standalone `vectorField()`
factory. They define a logical field whose value is a detached, immutable
`readonly number[]`. The plugin checks that every component is a finite number
and that the array has exactly the declared length. Core does not provide
`field.vector()` when the plugin is absent.

**You cannot persist this field with the PostgreSQL plugin yet.** There is no
PostgreSQL vector column compiler or similarity-search operator. Use the plugin
to declare and test the logical value contract, not as a working pgvector
storage feature.

## Installation

Install the plugin package in an UltimaBase project:

```bash tab="npm" tab-group="package-manager"
npm install @ultimabase/pg-vector-plugin
```

```bash tab="yarn"
yarn add @ultimabase/pg-vector-plugin
```

```bash tab="pnpm"
pnpm add @ultimabase/pg-vector-plugin
```

For TypeScript authoring, regenerate the application's declarations after
adding the plugin so `field.vector()` appears on this application's builder;
see [Generate TypeScript Types](/docs/1.0.0/guides/generate-types).

## Configuration

Add `pgVectorPlugin()` to the application and declare a stored vector field:

```ts title="src/document.ts"
import { Schema, createApplication } from '@ultimabase/core'
import { pgVectorPlugin } from '@ultimabase/pg-vector-plugin'

const Document = Schema.define({
	className: 'Document',
	fields: (field) => ({
		embedding: field.vector({ dimensions: 1536, required: true }),
	}),
})

export const application = await createApplication({
	plugins: [pgVectorPlugin()],
	schemas: [Document],
})
```

This compiles a schema without starting a database-backed application. It does
not prove that you can create, query, or synchronize a `Document` with a vector
column. `pgVectorPlugin()` takes no factory options.

| Field option | Meaning                                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------------------- |
| `dimensions` | Required positive **safe integer**; each vector must contain exactly this many components.              |
| `required`   | Ordinary Core create-time presence and non-nullability behavior; it does not affect PostgreSQL support. |
| `default`    | A vector snapshot checked against `dimensions` when the field is declared.                              |
| `list`       | Wraps the vector value in a homogeneous list; each element still has the declared dimension.            |

The builder is available for stored schema fields only. It is not available in
embedded objects or output-field descriptors. Standard Schema `validation`
requires the optional [Validation plugin](./validation); it can reject a
complete canonical vector but does not replace the plugin's structural checks.

## Behavior and limitations

### Validate values without a database

The public factory and Core's scalar snapshot boundary can check a value now:

```ts title="src/check-embedding.ts"
import { snapshotScalarFieldValue } from '@ultimabase/core'
import { vectorField } from '@ultimabase/pg-vector-plugin'

const embedding = vectorField({ dimensions: 3 })
const value = snapshotScalarFieldValue(embedding, [0.1, 0.2, 0.3], 'embedding')

console.log(value) // [0.1, 0.2, 0.3]
```

The returned array is a frozen copy; changing the original input later does
not change it. A non-array value, an array of the wrong length, or a `NaN` or
infinite component fails validation. This is a **logical-value check**, not a
database write.

### Wire and storage boundaries

The plugin declares a GraphQL JSON field codec that checks incoming vector
values and encodes them as arrays. That codec is not a PostgreSQL column
compiler, a REST codec, or evidence that a GraphQL mutation can persist a
vector. An ordinary TypeScript `readonly number[]` also does not statically
encode the declared length; `dimensions` is enforced when the value is
snapshotted.

The PostgreSQL plugin currently has no physical mapping for this kind. Do not
add a vector field to an application that must store or read that schema through
PostgreSQL, even if schema compilation succeeds. A raw SQL column cannot make
UltimaBase Query, validation, or schema synchronization understand the field.

## Troubleshooting

- **`field.vector` is missing in TypeScript:** install `pgVectorPlugin()` in
  this application and regenerate its Typegen declarations. Without the
  plugin, schema compilation also rejects the builder method.
- **A dimension or value is rejected:** use a positive safe integer for
  `dimensions`; provide an array of exactly that many finite numbers. A
  `default` is checked when the field is declared.
- **PostgreSQL cannot prepare the field:** physical pgvector support is not yet
  available. No extension setting or raw SQL workaround makes this a supported
  UltimaBase field for database operations.
