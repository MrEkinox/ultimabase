## Overview

`@ultimabase/validation-plugin` owns the optional `validation` field option.
Core always enforces requiredness, nullability, canonical value shapes, defaults,
immutable fields, and database integrity; installing this plugin adds
application-specific rejection rules.

## Installation

Install the plugin and a Standard Schema implementation such as Zod. An
existing UltimaBase application and database provider are prerequisites.

```bash tab="npm" tab-group="package-manager"
npm install @ultimabase/validation-plugin zod
```

```bash tab="yarn"
yarn add @ultimabase/validation-plugin zod
```

```bash tab="pnpm"
pnpm add @ultimabase/validation-plugin zod
```

## Configuration

Add `validationPlugin()` explicitly and attach validators to stored fields or
embedded properties:

```ts title="src/article.ts"
import { Schema } from '@ultimabase/core'
import { validationPlugin } from '@ultimabase/validation-plugin'
import { z } from 'zod'

export const Article = Schema.define({
	className: 'Article',
	fields: (field) => ({
		title: field.string({
			required: true,
			validation: z.string().min(1).max(200),
		}),
	}),
})

export const validation = validationPlugin()
```

Include `validation` in the application's `plugins` and `Article` in its
`schemas`. The factory has no configuration options. The `validation` field
option accepts a synchronous Standard Schema V1 validator compatible with the
field's complete value; virtual fields and output descriptors do not accept it.

## Behavior and limitations

### Execution semantics

Validators use Standard Schema V1. They run synchronously over complete,
present, non-null mutation values after input resolution and structural
validation. They may accept or reject the canonical value, but cannot transform
it. Master mutations follow the same validation path.

Reads and result materialization do not replay application validators.
Validators cannot transform values or return promises.

## Troubleshooting

Submit an empty title and assert the stable `field.validation` issue path. Then
submit a valid title and read it back. Master authority must receive the same
validation result.

If the `validation` option is unknown at startup, confirm that
`validationPlugin()` is in the same application's plugin list. If a validator
tries to transform a value or returns a promise, use a synchronous rejection
rule instead. Use [Hooks](./hooks) when input must be normalized or
transaction-bound business work must run.
