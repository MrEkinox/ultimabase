## Choose the capability

Start from the capability your application needs, not from the number of
packages available. Prefer one focused provider whose contract and operational
effects you can explain.

Before installation, check:

1. **Compatibility:** the plugin declares support for your UltimaBase release.
2. **Ownership:** its manifest identifies one stable plugin and optional exact
   instance.
3. **Privileges:** every requested Core power has a concrete reason.
4. **Environmental claims:** filesystem, network, process, or native behavior is
   visible before startup.
5. **Maintenance:** the package identifies its maintainer, source repository,
   license, release history, and support channel.
6. **Documentation:** setup, configuration, failure modes, and removal are
   documented for the version you use.

Official plugins are maintained with the framework. A community listing makes
a package discoverable; it does not make the package UltimaBase-maintained or
security-audited.

## Install and configure

Complete [Manual Installation](/docs/1.0.0/manual-installation) first: this
example extends its Node.js application with a PostgreSQL provider. Use a
**disposable development database** because the `override` schema policy can
change its physical tables. Hooks normalizes a title; Validation rejects the
empty result. Install both optional plugins and Zod:

```bash tab="npm" tab-group="package-manager"
npm install @ultimabase/hooks-plugin @ultimabase/validation-plugin zod
```

```bash tab="yarn"
yarn add @ultimabase/hooks-plugin @ultimabase/validation-plugin zod
```

```bash tab="pnpm"
pnpm add @ultimabase/hooks-plugin @ultimabase/validation-plugin zod
```

Declare behavior on the field that needs it:

```ts title="src/article.ts"
import { Schema } from '@ultimabase/core'
import { z } from 'zod'

export const Article = Schema.define({
	className: 'Article',
	fields: (field) => ({
		title: field.string({
			required: true,
			hooks: { resolveInput: ({ value }) => value?.trim() ?? null },
			validation: z.string().min(1),
		}),
	}),
})
```

Install the behavior in exactly this application, alongside persistence:

```ts title="src/main.ts"
import { UltimaBase } from '@ultimabase/core'
import { hooksPlugin } from '@ultimabase/hooks-plugin'
import { postgresPlugin } from '@ultimabase/postgres-plugin'
import { validationPlugin } from '@ultimabase/validation-plugin'

import { Article } from './article.js'

const databaseUrl = process.env.DATABASE_URL
if (databaseUrl === undefined) throw new TypeError('DATABASE_URL is required')

const ultimabase = new UltimaBase({
	plugins: [
		postgresPlugin({ schemaPolicy: 'override', url: databaseUrl }),
		hooksPlugin(),
		validationPlugin(),
	],
	schemas: [Article],
})

try {
	await ultimabase.start()
	const article = await Article.createOne(
		{ data: { title: '  Hello  ' } },
		{ ultimabase },
	)
	console.log(article.title) // 'Hello'
} finally {
	await ultimabase.dispose()
}
```

Importing a plugin package never installs it. Calling its factory is also
inert until the returned definition enters an application. Run
[Generate TypeScript Types](/docs/1.0.0/guides/generate-types) after changing
the graph so the editor recognizes plugin-owned options. Generated files are
declarations, not a Runtime client. Read [Hooks](./official/hooks) and
[Validation](./official/validation) for their exact behavior.

## Verify and maintain the plugin set

The example logs `Hello`. Try a whitespace-only title next: normalization
produces an empty string and Validation rejects it before persistence. Verify
both the successful result and the rejected write through the application's
public API. A successful package installation alone proves neither.

If startup fails, inspect the plugin's diagnostic and compatibility range
before changing privileges or infrastructure settings. After removal, delete
the factory from `plugins`, remove plugin-owned schema options or commands,
regenerate Typegen, and verify startup and data compatibility. Removing a
plugin does not automatically migrate its stored data.

## Check compatibility

Every plugin declares the UltimaBase versions and capability protocols it
supports. Core validates these declarations while compiling the application
graph. Required capabilities, privileges, peer identities, and exact protocol
versions must compose without ambiguity.

Use the documentation version that matches your application, then verify the
plugin manifest. UltimaBase rejects missing providers, incompatible protocols,
denied privileges, and duplicate identities before infrastructure effects.

See [Compatibility](/docs/1.0.0/reference/compatibility) for release-line rules,
[Official Plugins](./overview#official-plugins) for shipped integrations, and
[Community Plugins](./community-plugins) for the community maintenance boundary.
