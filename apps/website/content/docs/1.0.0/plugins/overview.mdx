## How plugin composition works

UltimaBase keeps concrete behavior in plugins. A plugin may declare schema
features, provide versioned capabilities, install Runtime behavior, expose a
transport, or own infrastructure. Core stays responsible for graph validation,
ownership, privileges, lifecycle, and cleanup.

Importing a plugin package never installs it. Behavior begins only when the
factory result appears in one application's `plugins` array. This makes the
application graph readable and keeps separate applications isolated.

<Mermaid
	description="Importing a package does not install it; the plugin factory enters application graph validation, static declarations, capability materialization, lifecycle, and disposal."
	chart="flowchart TB
    A[Package import] --> B[Plugin factory]
    B --> C[Application graph validation]
    C --> D[Static declarations]
    D --> E[Capability materialization]
    E --> F[Setup and lifecycle]
    F --> G[Disposal]"
/>

The graph is deterministic. Dependencies run before consumers; configuration
position breaks ties; registration order breaks ties inside one plugin.
Conflicts, missing requirements, incompatible versions, duplicate identities,
and denied privileges fail before infrastructure effects.

## Official plugins

Official packages are grouped by the capability they own. Each plugin has one
long-form page containing its installation, configuration, behavior, limits,
reference, and troubleshooting information when applicable.

- **Data and persistence:** [PostgreSQL](./official/data-and-persistence/postgresql),
  [Soft Delete](./official/data-and-persistence/soft-delete), and
  [PostgreSQL Vector](./official/data-and-persistence/postgresql-vector).
- **Validation and lifecycle:**
  [Validation](./official/validation-and-lifecycle/validation) and
  [Hooks](./official/validation-and-lifecycle/hooks).
- **Authentication and authorization:**
  [Password Authentication](./official/authentication-and-authorization/password-authentication),
  [Access](./official/authentication-and-authorization/access),
  [Roles](./official/authentication-and-authorization/roles), and
  [Object ACLs](./official/authentication-and-authorization/acl-permissions).
- **HTTP and APIs:** [HTTP](./official/http-and-apis/http),
  [Hono Server](./official/http-and-apis/hono-server),
  [REST](./official/http-and-apis/rest),
  [GraphQL](./official/http-and-apis/graphql),
  [GraphQL Yoga](./official/http-and-apis/graphql-yoga),
  [GraphiQL](./official/http-and-apis/graphiql), and
  [Apollo Sandbox](./official/http-and-apis/apollo-sandbox).
