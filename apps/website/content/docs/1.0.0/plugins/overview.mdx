## Context

Core owns schemas, queries, application assembly, and the Runtime. Optional
behavior—such as database persistence, Hooks, authentication, or an HTTP
server—comes from plugins. Each application chooses its own set; importing a
package does not change every application in the process.

## Mental model

Importing a plugin package never installs it. Its factory returns an inert
definition. Add that definition to an application's `plugins` array to opt in:

```ts title="src/application.ts"
import { Schema, UltimaBase } from '@ultimabase/core'
import { hooksPlugin } from '@ultimabase/hooks-plugin'

const Post = Schema.define({
	className: 'Post',
	fields: (f) => ({ title: f.string() }),
	hooks: {
		beforeOperation: {
			create: ({ item }) => console.log(item.title),
		},
	},
})

export const application = new UltimaBase({
	plugins: [hooksPlugin()],
	schemas: [Post],
})
```

The `hooks` option belongs to the Hooks plugin. If you remove `hooksPlugin()`
but leave that option on `Post`, application compilation rejects the unknown
option; it does not silently skip the callback. This excerpt assembles an
application but does not start a database or an API. For a complete working
setup, follow [Using Plugins](./using-plugins).

Core validates plugin identity, versions, dependencies, capabilities, and
active privilege requests before infrastructure effects. It then compiles
static declarations; application-local capabilities and resources are
materialized during initialization and cleaned up on disposal.

## Boundaries

Plugins integrate through versioned capabilities, not a global service
registry. A requirement can demand a compatible provider; Core rejects a
missing required provider or an ambiguous exclusive one. Dependencies run
before consumers. Configuration position breaks ties between ready plugins,
and registration order breaks ties within one plugin.

One stable plugin ID may have multiple configurations only with explicit,
distinct instance IDs. Each application owns its compiled graph and resources;
installing a plugin in one application does not install it in another. Core
enforces declared privileges, but environmental claims such as network or
filesystem access are disclosures, not an operating-system sandbox. For
selection, compatibility, and safe removal, see [Using Plugins](./using-plugins).
For the public authoring contract, see [Build a Plugin](./build-a-plugin).

## Official plugins

Choose by the capability you need. Each guide explains its own installation,
configuration, behavior, and limits. GraphQL's Yoga adapter and development
explorers share a guide, but remain separate packages you install explicitly.

| Need                                                | Official guide                                                |
| --------------------------------------------------- | ------------------------------------------------------------- |
| Persist data in PostgreSQL                          | [PostgreSQL](./official/postgresql)                           |
| Keep tombstones and control restore or purge        | [Soft Delete](./official/soft-delete)                         |
| Declare PostgreSQL vector fields                    | [PostgreSQL Vector](./official/postgresql-vector)             |
| Run application field validators                    | [Validation](./official/validation)                           |
| React to operation and field lifecycle phases       | [Hooks](./official/hooks)                                     |
| Authenticate with passwords and sessions            | [Password Authentication](./official/password-authentication) |
| Define application access rules                     | [Access](./official/access)                                   |
| Represent schema-backed role membership             | [Roles](./official/roles)                                     |
| Enforce per-object ACLs                             | [Object ACLs](./official/acl-permissions)                     |
| Select an HTTP application and apply browser policy | [HTTP](./official/http)                                       |
| Run an HTTP application on Node.js with Hono        | [Hono Server](./official/hono-server)                         |
| Expose generated REST routes                        | [REST](./official/rest)                                       |
| Execute GraphQL or serve it through Yoga            | [GraphQL, Yoga, and explorers](./official/graphql)            |
