## How plugin composition works

UltimaBase keeps concrete behavior in plugins. A plugin may declare schema
features, provide versioned capabilities, install Runtime behavior, expose a
transport, or own infrastructure. Core stays responsible for graph validation,
ownership, privileges, lifecycle, and cleanup.

Importing a plugin package never installs it. Behavior begins only when the
factory result appears in one application's `plugins` array. This makes the
application graph readable and keeps separate applications isolated.

<Mermaid
	description="Importing a package has no effect by itself; only a factory definition in the application's plugin list enters graph validation, declaration, capability materialization, lifecycle, and disposal."
	chart="flowchart TB
    A[Import package] --> B[Call plugin factory]
    B --> C[Add definition to application plugins]
    C --> D[Validate application graph]
    D --> E[Compile static declarations]
    E --> F[Materialize capabilities]
    F --> G[Setup and lifecycle]
    G --> H[Disposal]"
/>

The graph is deterministic. Dependencies run before consumers; configuration
position breaks ties; registration order breaks ties inside one plugin.
Conflicts, missing requirements, incompatible versions, duplicate identities,
and denied privileges fail before infrastructure effects.
