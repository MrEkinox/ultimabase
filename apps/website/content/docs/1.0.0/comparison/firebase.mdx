Firebase is a set of Google-hosted services that clients call directly:
Firestore stores schemaless documents, Security Rules decide what each client
may do, and Cloud Functions run server code. UltimaBase is a TypeScript
library on PostgreSQL that you run in your own Node.js server; clients reach it
through REST or GraphQL. This page maps Firebase concepts to UltimaBase.

This page compares with the hosted Firebase platform, the Firebase JavaScript
SDK 13.0.0 and firebase-tools 15.34.0, checked on 2026-10-17. Cells about
Firestore describe the Standard edition unless they name Enterprise. See the
[comparison overview](/docs/1.0.0/comparison/overview) for every system side
by side.

## Common tasks side by side

| Task                      | Firebase                                                           | UltimaBase                                           |
| ------------------------- | ------------------------------------------------------------------ | ---------------------------------------------------- |
| Read one document         | `getDoc`[^f56]                                                     | `findOneOrThrow` or `findOne` with a `where` on `id` |
| Query                     | `getDocs` on a `query` with `where`, `orderBy`, `limit`[^f4][^f56] | `findMany` with `where`, `orderBy`, `take`           |
| Write                     | `addDoc`, `setDoc`, `updateDoc`[^f55]                              | `createOne`, `upsertOne`, `updateOne`                |
| Several writes atomically | `runTransaction` or `writeBatch`[^f8]                              | `ultimabase.transaction`; each mutation is atomic    |
| Restrict reads            | An `allow read` rule[^f20]                                         | An Access read rule                                  |
| Grant an admin role       | `setCustomUserClaims`, checked in rules[^f25]                      | Role membership and `hasRole` in an Access rule      |
| React to a write          | `onDocumentCreated` and related triggers[^f27]                     | Hooks, or `afterCommit` for external effects         |
| Sign in                   | `signInWithEmailAndPassword`[^f13]                                 | `login`                                              |
| Test locally              | Emulator Suite and `@firebase/rules-unit-testing`[^f45][^f46]      | `testApplication` with Vitest                        |

Firestore rules are not filters: a query fails when it could return a document
the rules forbid, so the client repeats the rule's condition in its
query[^f22]. An UltimaBase read rule is a filter, compiled into the database
query, so a read returns only the rows the caller may see:

## What works differently and why

- **Relational and declared.** Firestore is schemaless, and the Standard
  edition has references but no joins[^f1][^f6]. UltimaBase stores data in
  PostgreSQL with declared, typed schemas, relations, `include` and nested
  writes.
- **Server trust.** The Admin SDK bypasses Security Rules[^f20], and the
  validation written in those rules with them[^f21]. UltimaBase Master bypasses
  authorization only; validation, hooks and transactions still run, and every
  use is audited.
- **When server code runs.** Cloud Firestore triggers run after the
  write[^f27]. UltimaBase hooks run inside the write's transaction and can
  refuse or extend it; `afterCommit` handles effects that must wait for the
  commit.
- **Where the code runs.** Firebase clients talk to Google services directly,
  and Cloud Functions deployments need the Blaze plan[^f26]. UltimaBase is your
  own Node.js server; clients use its REST or GraphQL API.
- **Hosting and cost.** Firebase runs on Google Cloud only[^f45], and Cloud
  Storage requires the Blaze plan[^f12]. UltimaBase is Apache-2.0 software you
  host yourself, which also means you operate it.

## What UltimaBase does not offer yet

| Firebase capability                               | UltimaBase status                                                                                       |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Realtime listeners (`onSnapshot`)[^f9]            | Planned: [Realtime](/docs/1.0.0/project/roadmap#application-capabilities)                               |
| Cloud Storage for Firebase[^f11]                  | Planned: [File fields](/docs/1.0.0/project/roadmap#next-priorities)                                     |
| Social sign-in providers[^f14]                    | Planned: [More authentication](/docs/1.0.0/project/roadmap#application-capabilities)                    |
| Multi-factor authentication[^f16]                 | Planned after OAuth, in [More authentication](/docs/1.0.0/project/roadmap#application-capabilities)     |
| Scheduled and task queue functions[^f39][^f40]    | Planned: [Background jobs](/docs/1.0.0/project/roadmap#application-capabilities)                        |
| Firebase console[^f20]                            | Planned: [Administration](/docs/1.0.0/project/roadmap#shipping-and-operations)                          |
| Client SDKs[^f50]                                 | Planned: [TypeScript SDK](/docs/1.0.0/project/roadmap#apis-and-developer-tools)                         |
| Vector search (`findNearest`)[^f43]               | Planned: [Vector search](https://github.com/MrEkinox/ultimadatabase/blob/main/ROADMAP.md#vector-search) |
| Cloud Messaging push notifications[^f35]          | Not on the roadmap                                                                                      |
| Email link sign-in, anonymous sign-in[^f15][^f14] | Not on the roadmap                                                                                      |
| Hosted service[^f45]                              | Not planned                                                                                             |

Planned is not shipped: the [Roadmap](/docs/1.0.0/project/roadmap) gives no
dates or order.
