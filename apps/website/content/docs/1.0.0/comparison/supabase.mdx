Supabase and UltimaBase both use PostgreSQL. Supabase builds a platform around
the database: you write SQL, policies and functions, and clients reach the
database through generated APIs. UltimaBase is a TypeScript library that runs
inside your Node.js server and treats PostgreSQL as storage: schemas, rules and
hooks live in TypeScript. This page maps Supabase concepts to UltimaBase.

This page compares with the hosted Supabase platform and supabase-js 2.118.0,
checked on 2026-10-17. See the [comparison overview](/docs/1.0.0/comparison/overview)
for every system side by side.

## Common tasks side by side

| Task                          | Supabase                                                     | UltimaBase                                                      |
| ----------------------------- | ------------------------------------------------------------ | --------------------------------------------------------------- |
| Define a table                | `create table` in a migration, or the Table Editor[^s1][^s2] | `App.Schema.define`, listed in the application                  |
| Read with a relation          | `select` with an embedded resource[^s4]                      | `findMany` with `include`                                       |
| Insert, update, delete        | `insert`, `update`, `delete` with filters[^s50]              | `createOne`, `updateOne`, `deleteOne` and their `Many` variants |
| Several writes atomically     | A SQL function called with `rpc`[^s3]                        | `ultimabase.transaction`                                        |
| Owner-only rows               | An RLS policy comparing `auth.uid()` with a column[^s18]     | An Access rule comparing the principal with a field             |
| Bypass policies on the server | The secret key[^s18]                                         | `useMasterKey: true`, audited                                   |
| Sign up and sign in           | `auth.signUp`, `auth.signInWithPassword`[^s9]                | `signUp`, `login`                                               |
| React to a write              | A Postgres trigger or a Database Webhook[^s23][^s24]         | Hooks in the transaction, `afterCommit` after it                |
| Types                         | `supabase gen types`, re-run after schema changes[^s39]      | Inferred from the declarations                                  |

## What works differently and why

- **Where the logic lives.** Supabase puts schema, policies, functions and
  triggers in PostgreSQL, and clients call the database through PostgREST[^s28].
  UltimaBase keeps schemas, rules, validation and hooks in TypeScript in one
  Node.js process. You do not write SQL, and UltimaBase exposes no raw SQL API,
  so every write goes through the same rules and hooks.
- **Authorization defaults.** RLS is not enabled on a table by default, and the
  secret key bypasses it[^s18]. From 2026-10-30, Supabase no longer exposes new
  public tables to its APIs without an explicit grant[^s20]. With the UltimaBase
  Access plugin installed, an operation without a rule is denied, and Master
  bypasses authorization only, with an audit callback.
- **Transactions.** The Supabase client library cannot group queries into a
  transaction[^s3]. Every UltimaBase mutation runs in one, and server code can
  group several.
- **Types without a generation step.** Supabase generates types from the
  database[^s39]; UltimaBase infers them from the declarations, so there is
  nothing to regenerate.
- **Platform or library.** Supabase is a hosted platform with Auth, Storage,
  Realtime, Edge Functions, Cron and a dashboard; self-hosting lacks some Cloud
  features[^s33][^s45]. UltimaBase is a library you deploy yourself and does
  not have those services yet.

## What UltimaBase does not offer yet

| Supabase capability                                    | UltimaBase status                                                                                                                  |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| Realtime[^s5]                                          | Planned: [Realtime](/docs/1.0.0/project/roadmap#application-capabilities)                                                          |
| Storage[^s7]                                           | Planned: [File fields](/docs/1.0.0/project/roadmap#next-priorities)                                                                |
| OAuth providers and SSO[^s10]                          | Planned: [More authentication](/docs/1.0.0/project/roadmap#application-capabilities)                                               |
| Multi-factor authentication[^s15]                      | Planned after OAuth, in [More authentication](/docs/1.0.0/project/roadmap#application-capabilities)                                |
| Cron and Queues[^s36][^s37]                            | Planned: [Background jobs](/docs/1.0.0/project/roadmap#application-capabilities)                                                   |
| Versioned migrations[^s2]                              | Planned: [PostgreSQL migrations](/docs/1.0.0/project/roadmap#next-priorities)                                                      |
| Studio[^s33]                                           | Planned: [Administration](/docs/1.0.0/project/roadmap#shipping-and-operations)                                                     |
| Client library (supabase-js)[^s3]                      | Planned: [TypeScript SDK](/docs/1.0.0/project/roadmap#apis-and-developer-tools)                                                    |
| Vector search with pgvector[^s38]                      | Planned: [Vector search](https://github.com/MrEkinox/ultimadatabase/blob/main/ROADMAP.md#vector-search)                            |
| PostGIS[^s48]                                          | Planned among the [advanced field plugins](https://github.com/MrEkinox/ultimadatabase/blob/main/ROADMAP.md#advanced-field-plugins) |
| Full-text search[^s47]                                 | Not on the roadmap                                                                                                                 |
| Magic links, email OTP, anonymous sign-ins[^s12][^s13] | Not on the roadmap                                                                                                                 |
| Hand-written SQL and Postgres extensions[^s42]         | Not planned: UltimaBase exposes no raw SQL API                                                                                     |
| Hosted service[^s16]                                   | Not planned                                                                                                                        |

Planned is not shipped: the [Roadmap](/docs/1.0.0/project/roadmap) gives no
dates or order.
