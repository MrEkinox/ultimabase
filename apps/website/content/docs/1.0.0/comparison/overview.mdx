UltimaBase is a TypeScript backend framework that runs inside your own Node.js
process on PostgreSQL. This page compares what it ships today with five
backends and one ORM, so you can decide whether it fits your application. Each
system also has a "Coming from" page that maps its vocabulary and common tasks
to UltimaBase.

<Callout title="Pre-release">
	UltimaBase has no npm release yet and its public APIs may still change. The
	comparison describes the repository as it is today. A capability marked
	_Planned_ is a direction listed on the [Roadmap](/docs/1.0.0/project/roadmap),
	not a commitment or a date.
</Callout>

## Who UltimaBase is for

UltimaBase fits you when most of these are true:

- You write TypeScript on Node.js 24 or newer and want PostgreSQL as your
  database.
- You want schemas, authorization rules, validation and hooks declared in
  TypeScript, with types inferred from those declarations and no generation
  step.
- You want the same rules to apply to every caller: server code, REST and
  GraphQL go through one operation pipeline.
- You host the backend yourself, as a library inside your own server.
- You know Parse Server and want a similar vocabulary (classes, pointers,
  relations, ACLs, roles, Master key) with a typed, PostgreSQL-first design.

## Who it is not for yet

Another system is a better choice today when you need any of the following:

- **A stable, supported release.** UltimaBase is pre-release, with no
  announced support window. Parse Server, Supabase, Firebase and Appwrite are
  mature products; PocketBase is also pre-1.0.
- **Built-in services beyond data and password sign-in.** Realtime
  subscriptions, file storage, OAuth sign-in, multi-factor authentication,
  background jobs, an admin dashboard and client SDKs are planned, not shipped.
  Push notifications, magic links, anonymous user accounts and full-text search
  are not on the roadmap. All five backends compared here ship several of
  these.
- **A managed hosted service.** UltimaBase is software you deploy. Supabase,
  Firebase and Appwrite offer hosted platforms.
- **Another database.** UltimaBase supports PostgreSQL only. Parse Server also
  supports MongoDB, PocketBase uses SQLite, and Appwrite can run on MariaDB or
  MongoDB.
- **Hand-written SQL.** UltimaBase exposes no raw SQL API; every operation goes
  through its pipeline. If your team thinks in SQL functions, triggers and
  policies, Supabase fits that style.
- **A drop-in Parse Server replacement.** UltimaBase is inspired by Parse
  Server but is not API-compatible. Parse SDK clients cannot connect to it, and
  there is no data migration tool.

## Where UltimaBase differs

Among the systems compared here:

- **Types come from the declarations.** Supabase, Appwrite and Prisma generate
  types with a command; Parse Server, Firebase and PocketBase rely on
  hand-written generics or converters. UltimaBase infers item, filter, relation
  and rule types from the TypeScript schema itself. Other TypeScript libraries
  outside this comparison also infer types.
- **Soft delete is built in.** The Soft Delete plugin adds tombstones, restore,
  purge and a separate permission to read deleted rows. The other systems
  document do-it-yourself patterns or nothing.
- **One policy stack.** Predicate row rules (Access), per-object ACLs and role
  hierarchies compose on the same schema. Parse Server has ACLs and roles but
  no general predicate rules; Supabase has predicate RLS but leaves ACLs and
  roles to you; PocketBase has predicate rules without ACLs or roles.
- **Hooks run inside the write's transaction.** A failing hook rolls the write
  back, and a separate after-commit stage handles external effects. Firebase
  triggers run after the write and Appwrite Functions are asynchronous;
  Supabase reaches the same guarantee with SQL triggers.
- **Master bypasses authorization only.** Validation, hooks, transactions and
  integrity still run, and every Master use is reported to an audit callback.
  The Firebase Admin SDK, by contrast, bypasses Security Rules and the
  validation written in them.
- **An OpenAPI document for your application.** The REST plugin describes your
  own schemas and operations in OpenAPI 3.1.

The other systems are stronger elsewhere: every backend here ships realtime,
file storage and OAuth today; Supabase, Firebase and Appwrite offer managed hosting; and Parse Server,
Supabase, Firebase and Appwrite are mature products with stable releases.
