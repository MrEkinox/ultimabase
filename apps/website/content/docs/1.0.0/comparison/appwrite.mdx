Appwrite is a multi-service platform, self-hosted with Docker or used as
Appwrite Cloud, that clients and servers call through its SDKs. UltimaBase is a
TypeScript library on PostgreSQL inside your own Node.js process, with schemas,
rules and hooks declared in code. This page maps Appwrite concepts to
UltimaBase.

This page compares with Appwrite 2.5.0 and its TablesDB database, checked on
2026-10-17. See the [comparison overview](/docs/1.0.0/comparison/overview) for
every system side by side.

## Common tasks side by side

| Task                      | Appwrite                                                             | UltimaBase                                                |
| ------------------------- | -------------------------------------------------------------------- | --------------------------------------------------------- |
| Create a table            | The Console, the server SDK, or `appwrite push tables`[^a2][^a4]     | `App.Schema.define`, listed in the application            |
| Create a row              | `tablesDB.createRow` with data and permissions[^a21]                 | `createOne`, with an ACL when the ACL plugin is installed |
| List rows                 | `tablesDB.listRows` with `Query` helpers[^a21][^a6]                  | `findMany` with `where` and `take`                        |
| Share a row               | `Permission` and `Role` helpers on the row[^a17]                     | ACL grants, or an Access rule with `hasRole`              |
| Several writes atomically | Create a transaction, pass its ID to each write, then commit it[^a8] | `ultimabase.transaction`                                  |
| Sign up and sign in       | `account.create`, `account.createEmailPasswordSession`[^a39]         | `signUp`, `login`                                         |
| Run server logic          | A Function triggered by an event or an execution[^a20]               | Hooks, or a custom operation                              |

## What works differently and why

- **Platform or library.** Appwrite is a set of services administered from a
  Console, with logic in isolated Functions[^a20][^a36]. UltimaBase is one
  library in your server process, so your code and its rules share one
  runtime.
- **When logic runs.** Appwrite Functions run on events, HTTP calls or a
  schedule, and no synchronous before-write hook is documented[^a20][^a3].
  UltimaBase hooks run inside the write's transaction and can refuse it, with a
  separate stage after commit.
- **Predicate rules.** Appwrite permissions list who may act on a table or
  row[^a16][^a17]. UltimaBase adds Access rules that are arbitrary TypeScript
  predicates, compiled into the query for reads.
- **Types.** Appwrite generates types with its CLI[^a32]. UltimaBase infers
  them from the declarations.
- **Breadth.** Appwrite ships realtime, storage, messaging, multi-factor
  authentication, OAuth and several database engines[^a9][^a11][^a26][^a13][^a12][^a37].
  UltimaBase covers data, authorization and password sign-in today.

## What UltimaBase does not offer yet

| Appwrite capability                            | UltimaBase status                                                                                       |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Realtime[^a9]                                  | Planned: [Realtime](/docs/1.0.0/project/roadmap#application-capabilities)                               |
| Storage buckets[^a11]                          | Planned: [File fields](/docs/1.0.0/project/roadmap#next-priorities)                                     |
| OAuth providers[^a12]                          | Planned: [More authentication](/docs/1.0.0/project/roadmap#application-capabilities)                    |
| Multi-factor authentication[^a13]              | Planned after OAuth, in [More authentication](/docs/1.0.0/project/roadmap#application-capabilities)     |
| Scheduled Function executions[^a29]            | Planned: [Background jobs](/docs/1.0.0/project/roadmap#application-capabilities)                        |
| Console[^a25]                                  | Planned: [Administration](/docs/1.0.0/project/roadmap#shipping-and-operations)                          |
| Client SDKs[^a38]                              | Planned: [TypeScript SDK](/docs/1.0.0/project/roadmap#apis-and-developer-tools)                         |
| Multi-tenancy pattern with teams[^a30]         | Planned: [Tenant isolation](/docs/1.0.0/project/roadmap#application-capabilities)                       |
| VectorsDB[^a31]                                | Planned: [Vector search](https://github.com/MrEkinox/ultimadatabase/blob/main/ROADMAP.md#vector-search) |
| Messaging: push, email and SMS[^a26]           | Not on the roadmap                                                                                      |
| Magic URL, email OTP, anonymous sessions[^a12] | Not on the roadmap                                                                                      |
| Full-text search[^a6]                          | Not on the roadmap                                                                                      |
| MariaDB or MongoDB[^a37]                       | Not on the roadmap                                                                                      |
| Appwrite Cloud hosting[^a36]                   | Not planned                                                                                             |

Planned is not shipped: the [Roadmap](/docs/1.0.0/project/roadmap) gives no
dates or order.
