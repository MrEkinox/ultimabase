## What you will build

You will create three source files: a `Task` schema, an application that installs
the PostgreSQL plugin, and an entry point that writes one record. The schema and
plugin configuration form the graph UltimaBase compiles at startup.

## Prerequisites

Complete [Installation](./installation). The database named by `DATABASE_URL`
must already exist and be reachable. Use only the disposable database you
prepared there: this tutorial enables direct schema synchronization.

## Steps

### Create the project files

Create the source directory from the project root:

```bash
mkdir src
```

The finished project has this shape:

<Files>
	<Folder name="src" defaultOpen>
		<File name="schema.ts" />
		<File name="ultimabase.ts" />
		<File name="main.ts" />
	</Folder>
	<File name=".env" />
	<File name=".gitignore" />
	<File name="package.json" />
	<File name="tsconfig.json" />
</Files>

`schema.ts` owns data declarations, `ultimabase.ts` owns the application graph,
and `main.ts` owns this process's lifecycle. `.env` supplies the local database
URL without becoming part of the application graph. You do not need generated
declarations to run this application.

### Define the Task schema

Define the data model. Field factories preserve the exact TypeScript shape and
Core validates the same structure at Runtime.

```ts title="src/schema.ts"
import { Schema } from '@ultimabase/core'

export const Task = Schema.define({
	className: 'Task',
	fields: (field) => ({
		done: field.boolean({ default: false }),
		title: field.string({ required: true }),
	}),
})
```

### Configure the application

Create the application. `schemaPolicy: 'override'` is convenient for this
disposable database: it creates missing structures and applies supported
changes, but it is not a replacement for reviewed production migrations.

```ts title="src/ultimabase.ts"
import { UltimaBase } from '@ultimabase/core'
import { postgresPlugin } from '@ultimabase/postgres-plugin'

import { Task } from './schema.js'

const databaseUrl = process.env.DATABASE_URL

if (databaseUrl === undefined) {
	throw new TypeError('DATABASE_URL is required')
}

export const ultimabase = new UltimaBase({
	plugins: [
		postgresPlugin({
			schemaPolicy: 'override',
			url: databaseUrl,
		}),
	],
	schemas: [Task],
})
```

The local imports below end in `.js` even though the source files are `.ts`.
With the `NodeNext` configuration from Installation, TypeScript resolves them
and emits paths that Node.js can execute.

### Start and verify

Start the application, create one record through the shared Runtime, and always
release resources:

```ts title="src/main.ts"
import { Task } from './schema.js'
import { ultimabase } from './ultimabase.js'

try {
	await ultimabase.start()

	const task = await Task.createOne(
		{ data: { title: 'Write the documentation' } },
		{ ultimabase },
	)

	console.log(task.toJSON())
} finally {
	await ultimabase.dispose()
}
```

Run the complete local check:

```bash tab="npm" tab-group="package-manager"
npm run typecheck
npm run build
npm start
```

```bash tab="yarn"
yarn typecheck
yarn build
yarn start
```

```bash tab="pnpm"
pnpm typecheck
pnpm build
pnpm start
```

## Expected result

The default logger first reports the installed plugin and its requested
privileges. The process then prints a JavaScript object like this (the
generated ID and timestamps vary):

```text
{
  done: false,
  title: 'Write the documentation',
  id: 'generated-id',
  createdAt: 'generated-timestamp',
  updatedAt: 'generated-timestamp'
}
```

`done` is `false` because the schema supplies that default. The successful
`createOne` call confirms that PostgreSQL accepted the write. The process then
exits after closing the application-owned connection pool. UltimaBase has also
prepared the `Task` table in this disposable database.

If startup fails, first confirm that `DATABASE_URL` is loaded and that the
database accepts a connection from the same terminal.
