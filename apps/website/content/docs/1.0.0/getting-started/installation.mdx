## What you will build

You will prepare an ESM TypeScript project with Core and the PostgreSQL plugin.
The packages are shown through their intended npm registry names even while the
framework remains pre-release.

## Prerequisites

- Node.js 24 or newer. Confirm with `node --version`.
- npm, Yarn, or pnpm. Use one package manager for the whole project.
- A reachable PostgreSQL database dedicated to this exercise. UltimaBase's
  integration suite currently verifies PostgreSQL 17.

<Callout type="warn" title="Use a disposable development database">
	The first application uses direct schema synchronization with the `override`
	policy. Point it at an empty local database, not shared or production data.
</Callout>

## Steps

Create the project directory and initialize its package metadata:

```bash tab="npm" tab-group="package-manager"
mkdir ultimabase-first-app
cd ultimabase-first-app
npm init -y
```

```bash tab="yarn"
mkdir ultimabase-first-app
cd ultimabase-first-app
yarn init -y
```

```bash tab="pnpm"
mkdir ultimabase-first-app
cd ultimabase-first-app
pnpm init
```

Install the Runtime packages:

```bash tab="npm" tab-group="package-manager"
npm install @ultimabase/core @ultimabase/postgres-plugin
```

```bash tab="yarn"
yarn add @ultimabase/core @ultimabase/postgres-plugin
```

```bash tab="pnpm"
pnpm add @ultimabase/core @ultimabase/postgres-plugin
```

Install TypeScript and the Node.js declarations as development dependencies:

```bash tab="npm" tab-group="package-manager"
npm install --save-dev typescript @types/node
```

```bash tab="yarn"
yarn add --dev typescript @types/node
```

```bash tab="pnpm"
pnpm add --save-dev typescript @types/node
```

Create a strict compiler configuration:

```json title="tsconfig.json"
{
	"compilerOptions": {
		"module": "NodeNext",
		"moduleResolution": "NodeNext",
		"outDir": "dist",
		"rootDir": "src",
		"skipLibCheck": true,
		"strict": true,
		"target": "ES2024",
		"types": ["node"]
	},
	"include": ["src"]
}
```

`skipLibCheck` leaves strict checking enabled for your source while avoiding
diagnostics inside installed packages' declaration files.

Set ESM mode and add these scripts to the generated `package.json`. Keep its
other existing fields:

```json title="package.json"
{
	"type": "module",
	"scripts": {
		"build": "tsc",
		"start": "node --env-file=.env dist/main.js",
		"typecheck": "tsc --noEmit"
	}
}
```

Create a local environment file. Replace the example credentials and database
name with a reachable, disposable PostgreSQL database:

```dotenv title=".env"
DATABASE_URL=postgres://postgres:postgres@localhost:5432/ultimabase_first_app
```

Keep secrets and generated output out of source control:

```text title=".gitignore"
.env
dist/
node_modules/
```

If you do not already have a development database, create one with your local
PostgreSQL installation or a disposable container before continuing. The
connection URL must name a database that already exists; the first application
prepares its tables, not the database itself.

## Expected result

Confirm that the TypeScript executable is installed:

```bash tab="npm" tab-group="package-manager"
npx tsc --version
```

```bash tab="yarn"
yarn tsc --version
```

```bash tab="pnpm"
pnpm exec tsc --version
```

You should see a TypeScript version. Do not run `typecheck` yet: `src/` has no
source files, so TypeScript would correctly report that it found no inputs.
The database connection is checked when the application starts.
