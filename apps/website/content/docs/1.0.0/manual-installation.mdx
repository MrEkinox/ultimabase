## What you will build

You will set up an ESM TypeScript project, install Core and the PostgreSQL plugin,
define a `Task` schema, and save one record. The packages are shown through
their intended npm registry names even while the framework remains pre-release.

## Prerequisites

- Node.js 24 or newer. Confirm with `node --version`.
- npm, Yarn, or pnpm. Use one package manager for the whole project.
- A reachable PostgreSQL database dedicated to this exercise. UltimaBase's
  integration suite currently verifies PostgreSQL 17.

<Callout type="warn" title="Use a disposable development database">
	The first application uses direct schema synchronization with the `override`
	policy. Point it at an empty local database, not shared or production data.
</Callout>

## Steps

Create the project directory and initialize its package metadata:

```bash tab="npm" tab-group="package-manager"
mkdir ultimabase-first-app
cd ultimabase-first-app
npm init -y
```

```bash tab="yarn"
mkdir ultimabase-first-app
cd ultimabase-first-app
yarn init -y
```

```bash tab="pnpm"
mkdir ultimabase-first-app
cd ultimabase-first-app
pnpm init
```

Install the Runtime packages:

```bash tab="npm" tab-group="package-manager"
npm install @ultimabase/core @ultimabase/postgres-plugin
```

```bash tab="yarn"
yarn add @ultimabase/core @ultimabase/postgres-plugin
```

```bash tab="pnpm"
pnpm add @ultimabase/core @ultimabase/postgres-plugin
```

Install TypeScript and the Node.js declarations as development dependencies:

```bash tab="npm" tab-group="package-manager"
npm install --save-dev typescript @types/node
```

```bash tab="yarn"
yarn add --dev typescript @types/node
```

```bash tab="pnpm"
pnpm add --save-dev typescript @types/node
```

Create a strict compiler configuration:

```json title="tsconfig.json"
{
	"compilerOptions": {
		"module": "NodeNext",
		"moduleResolution": "NodeNext",
		"outDir": "dist",
		"rootDir": "src",
		"skipLibCheck": true,
		"strict": true,
		"target": "ES2024",
		"types": ["node"]
	},
	"include": ["src"]
}
```

`skipLibCheck` leaves strict checking enabled for your source while avoiding
diagnostics inside installed packages' declaration files.

Set ESM mode and add these scripts to the generated `package.json`. Keep its
other existing fields:

```json title="package.json"
{
	"type": "module",
	"scripts": {
		"build": "tsc",
		"start": "node --env-file=.env dist/main.js",
		"typecheck": "tsc --noEmit"
	}
}
```

Create a local environment file. Replace the example credentials and database
name with a reachable, disposable PostgreSQL database:

```dotenv title=".env"
DATABASE_URL=postgres://postgres:postgres@localhost:5432/ultimabase_first_app
```

Keep secrets and generated output out of source control:

```text title=".gitignore"
.env
dist/
node_modules/
```

If you do not already have a development database, create one with your local
PostgreSQL installation or a disposable container before continuing. The
connection URL must name a database that already exists; the first application
prepares its tables, not the database itself.

### Check the toolchain

Confirm that the TypeScript executable is installed:

```bash tab="npm" tab-group="package-manager"
npx tsc --version
```

```bash tab="yarn"
yarn tsc --version
```

```bash tab="pnpm"
pnpm exec tsc --version
```

You should see a TypeScript version. Do not run `typecheck` yet: `src/` has no
source files, so TypeScript would correctly report that it found no inputs.
The database connection is checked when the application starts.

### Create the project files

Create the source directory from the project root:

```bash
mkdir src
```

The finished project has this shape:

<Files>
	<Folder name="src" defaultOpen>
		<File name="schema.ts" />
		<File name="ultimabase.ts" />
		<File name="main.ts" />
	</Folder>
	<File name=".env" />
	<File name=".gitignore" />
	<File name="package.json" />
	<File name="tsconfig.json" />
</Files>

`schema.ts` owns data declarations, `ultimabase.ts` owns the application graph,
and `main.ts` owns this process's lifecycle. `.env` supplies the local database
URL without becoming part of the application graph. You do not need generated
declarations to run this application.

### Define the Task schema

Define the data model. Field factories preserve the exact TypeScript shape and
Core validates the same structure at Runtime.

```ts title="src/schema.ts"
import { Schema } from '@ultimabase/core'

export const Task = Schema.define({
	className: 'Task',
	fields: (f) => ({
		done: f.boolean({ default: false }),
		title: f.string({ required: true }),
	}),
})
```

### Configure the application

Create the application. `schemaPolicy: 'override'` is convenient for this
disposable database: it creates missing structures and applies supported
changes, but it is not a replacement for reviewed production migrations.

```ts title="src/ultimabase.ts"
import { UltimaBase } from '@ultimabase/core'
import { postgresPlugin } from '@ultimabase/postgres-plugin'

import { Task } from './schema.js'

const databaseUrl = process.env.DATABASE_URL

if (databaseUrl === undefined) {
	throw new TypeError('DATABASE_URL is required')
}

export const ultimabase = new UltimaBase({
	plugins: [
		postgresPlugin({
			schemaPolicy: 'override',
			url: databaseUrl,
		}),
	],
	schemas: [Task],
})
```

The local imports end in `.js` even though the source files are `.ts`. With
the `NodeNext` configuration above, TypeScript resolves them and emits paths
that Node.js can execute.

### Start and verify

Start the application, create one record through the shared Runtime, and always
release resources:

```ts title="src/main.ts"
import { Task } from './schema.js'
import { ultimabase } from './ultimabase.js'

try {
	await ultimabase.start()

	const task = await Task.createOne(
		{ data: { title: 'Write the documentation' } },
		{ ultimabase },
	)

	console.log(task.toJSON())
} finally {
	await ultimabase.dispose()
}
```

Run the complete local check:

```bash tab="npm" tab-group="package-manager"
npm run typecheck
npm run build
npm start
```

```bash tab="yarn"
yarn typecheck
yarn build
yarn start
```

```bash tab="pnpm"
pnpm typecheck
pnpm build
pnpm start
```

## Expected result

The default logger first reports the installed plugin and its requested
privileges. The process then prints a JavaScript object like this (the
generated ID and timestamps vary):

```text
{
  done: false,
  title: 'Write the documentation',
  id: 'generated-id',
  createdAt: 'generated-timestamp',
  updatedAt: 'generated-timestamp'
}
```

`done` is `false` because the schema supplies that default. The successful
`createOne` call confirms that PostgreSQL accepted the write. The process then
exits after closing the application-owned connection pool. UltimaBase has also
prepared the `Task` table in this disposable database.

If startup fails, first confirm that `DATABASE_URL` is loaded and that the
database accepts a connection from the same terminal.
