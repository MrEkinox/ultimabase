## What you will build

You will set up an ESM TypeScript project, install Core and the PostgreSQL plugin,
define a `Task` schema, and save one record. The project has the same four
source files as one generated by [Quick Start](/docs/1.0.0/quick-start). The packages are shown through
their intended npm registry names even while the framework remains pre-release.

<Callout type="warn" title="Packages are not published yet">
	The registry commands below describe the intended installation after release.
	For a runnable evaluation now, use the [modeling
	example](https://github.com/MrEkinox/ultimadatabase/blob/main/examples/modeling/README.md#run-and-verify-it)
	with locally built workspace packages. It has the layout of this tutorial with
	the same two packages, and its README gives the database and start commands.
</Callout>

## Prerequisites

- Node.js 24 or newer. Confirm with `node --version`.
- npm, Yarn, or pnpm. Use one package manager for the whole project.
- A reachable PostgreSQL database dedicated to this exercise. UltimaBase's
  integration suite currently verifies PostgreSQL 17.

<Callout type="warn" title="Use a disposable development database">
	The first application uses direct schema synchronization with the `override`
	policy. Point it at an empty local database, not shared or production data.
</Callout>

## Steps

Create the project directory and initialize its package metadata:

```bash tab="npm" tab-group="package-manager"
mkdir ultimabase-first-app
cd ultimabase-first-app
npm init -y
```

```bash tab="yarn"
mkdir ultimabase-first-app
cd ultimabase-first-app
yarn init -y
```

```bash tab="pnpm"
mkdir ultimabase-first-app
cd ultimabase-first-app
pnpm init
```

Install the Runtime packages:

```bash tab="npm" tab-group="package-manager"
npm install @ultimabase/core @ultimabase/postgres-plugin
```

```bash tab="yarn"
yarn add @ultimabase/core @ultimabase/postgres-plugin
```

```bash tab="pnpm"
pnpm add @ultimabase/core @ultimabase/postgres-plugin
```

Install TypeScript and the Node.js declarations as development dependencies:

```bash tab="npm" tab-group="package-manager"
npm install --save-dev typescript @types/node
```

```bash tab="yarn"
yarn add --dev typescript @types/node
```

```bash tab="pnpm"
pnpm add --save-dev typescript @types/node
```

Create a strict compiler configuration:

```json title="tsconfig.json"
{
	"compilerOptions": {
		"erasableSyntaxOnly": true,
		"module": "NodeNext",
		"moduleResolution": "NodeNext",
		"outDir": "dist",
		"rewriteRelativeImportExtensions": true,
		"rootDir": "src",
		"skipLibCheck": true,
		"strict": true,
		"target": "ES2024",
		"types": ["node"],
		"verbatimModuleSyntax": true
	},
	"include": ["src"]
}
```

`skipLibCheck` leaves strict checking enabled for your source while avoiding
diagnostics inside installed packages' declaration files. Local imports name
the `.ts` source files: Node.js 24 runs them directly in development
(`erasableSyntaxOnly` keeps to the syntax it can strip), and
`rewriteRelativeImportExtensions` makes `tsc` emit `.js` paths for the build.

Set ESM mode and add these scripts to the generated `package.json`. Keep its
other existing fields:

```json title="package.json"
{
	"type": "module",
	"scripts": {
		"dev": "node --watch --env-file=.env src/main.ts",
		"build": "tsc",
		"start": "node --env-file=.env dist/main.js",
		"typecheck": "tsc --noEmit"
	}
}
```

Create a local environment file. Replace the example credentials and database
name with a reachable, disposable PostgreSQL database:

```dotenv title=".env"
DATABASE_URL=postgres://postgres:postgres@localhost:5432/ultimabase_first_app
```

Keep secrets and generated output out of source control:

```text title=".gitignore"
.env
dist/
node_modules/
```

If you do not already have a development database, create one with your local
PostgreSQL installation or a disposable container before continuing. The
connection URL must name a database that already exists; the first application
prepares its tables, not the database itself.

### Check the toolchain

Confirm that the TypeScript executable is installed:

```bash tab="npm" tab-group="package-manager"
npx tsc --version
```

```bash tab="yarn"
yarn tsc --version
```

```bash tab="pnpm"
pnpm exec tsc --version
```

You should see a TypeScript version. Do not run `typecheck` yet: `src/` has no
source files, so TypeScript would correctly report that it found no inputs.
The database connection is checked when the application starts.

### Create the project files

Create the source directories from the project root:

```bash
mkdir -p src/schemas
```

The finished project has this shape:

<Files>
	<Folder name="src" defaultOpen>
		<File name="app.ts" />
		<Folder name="schemas" defaultOpen>
			<File name="task.ts" />
		</Folder>
		<File name="ultimabase.ts" />
		<File name="main.ts" />
	</Folder>
	<File name=".env" />
	<File name=".gitignore" />
	<File name="package.json" />
	<File name="tsconfig.json" />
</Files>

Each file has one role, in the order they depend on each other: `app.ts`
installs the plugins, `schemas/` declares the data from them, `ultimabase.ts`
creates the application, and `main.ts` owns this process's lifecycle. `.env`
supplies the local database URL without becoming part of the application
graph. There is no generation step: TypeScript types come from these
declarations themselves. [Project Layout](/docs/1.0.0/project-layout)
explains why `app.ts` imports no schema.

### Install the plugins

Create the application factory `App` from the plugins. `postgresPlugin()`
reads `DATABASE_URL` when the application starts, so the project type-checks
without it. Outside production, its schema policy is `override`: convenient
for this disposable database, it creates missing structures and applies
supported changes, but it is not a replacement for reviewed production
migrations. `NODE_ENV=production` selects `fail`.

```ts twoslash title="src/app.ts"
import { UltimaBase } from '@ultimabase/core'
import { postgresPlugin } from '@ultimabase/postgres-plugin'

// Every plugin, in one list. Schemas are declared from App in src/schemas/,
// so this module imports none of them.
export const App = UltimaBase.use(postgresPlugin())
```

### Define the Task schema

Define the data model from `App`. Field factories preserve the exact
TypeScript shape and Core validates the same structure at Runtime. When you
add a plugin to `App`, its options become available on this declaration.

```ts twoslash title="src/schemas/task.ts"
// @filename: app.ts
import { UltimaBase } from '@ultimabase/core'
import { postgresPlugin } from '@ultimabase/postgres-plugin'

export const App = UltimaBase.use(postgresPlugin())
// @filename: schemas/task.ts
// ---cut---
import { App } from '../app.ts'

export const Task = App.Schema.define({
	className: 'Task',
	fields: (f) => ({
		done: f.boolean({ default: false }),
		title: f.string({ required: true }),
	}),
})
```

### Create the application

Create the application `ultimabase` with its schemas. A schema belongs to the
application only when it is listed here.

```ts twoslash title="src/ultimabase.ts"
// @filename: app.ts
import { UltimaBase } from '@ultimabase/core'
import { postgresPlugin } from '@ultimabase/postgres-plugin'

export const App = UltimaBase.use(postgresPlugin())
// @filename: schemas/task.ts
import { App } from '../app.ts'

export const Task = App.Schema.define({
	className: 'Task',
	fields: (f) => ({
		done: f.boolean({ default: false }),
		title: f.string({ required: true }),
	}),
})
// @filename: ultimabase.ts
// ---cut---
import { App } from './app.ts'
import { Task } from './schemas/task.ts'

export const ultimabase = new App({
	schemas: [Task],
})

// Required once per application: it gives name-keyed editor types.
declare module '@ultimabase/core' {
	interface Register {
		readonly app: typeof ultimabase
	}
}
```

### Start and verify

Start the application, create one record through the shared Runtime, and always
release resources. `start()` resolves to `ultimabase` itself once started; the
`started` binding lets `await using` dispose it when the scope exits, even
after a failure:

```ts twoslash title="src/main.ts"
// @filename: app.ts
import { UltimaBase } from '@ultimabase/core'
import { postgresPlugin } from '@ultimabase/postgres-plugin'

export const App = UltimaBase.use(postgresPlugin())
// @filename: schemas/task.ts
import { App } from '../app.ts'

export const Task = App.Schema.define({
	className: 'Task',
	fields: (f) => ({
		done: f.boolean({ default: false }),
		title: f.string({ required: true }),
	}),
})
// @filename: ultimabase.ts
import { App } from './app.ts'
import { Task } from './schemas/task.ts'

export const ultimabase = new App({
	schemas: [Task],
})

// Required once per application: it gives name-keyed editor types.
declare module '@ultimabase/core' {
	interface Register {
		readonly app: typeof ultimabase
	}
}
// @filename: main.ts
// ---cut---
import { toJSON } from '@ultimabase/core'

import { Task } from './schemas/task.ts'
import { ultimabase } from './ultimabase.ts'

await using started = await ultimabase.start()

const task = await Task.createOne({
	data: { title: 'Write the documentation' },
})

console.log(toJSON(task), started.state)
```

A long-running server keeps the scope open until it is asked to stop, for
example by awaiting a promise resolved on `SIGTERM`.

Run the complete local check:

```bash tab="npm" tab-group="package-manager"
npm run typecheck
npm run build
npm start
```

```bash tab="yarn"
yarn typecheck
yarn build
yarn start
```

```bash tab="pnpm"
pnpm typecheck
pnpm build
pnpm start
```

## Expected result

The default logger first prints one line naming the schemas, the installed
plugin, and any critical privilege (`logLevel: 'debug'` prints the complete
privilege report). The process then prints the created record and the
application state, like this (the generated ID and timestamps vary):

```text
{
  done: false,
  title: 'Write the documentation',
  id: 'generated-id',
  createdAt: 'generated-timestamp',
  updatedAt: 'generated-timestamp'
} started
```

`done` is `false` because the schema supplies that default. The successful
`createOne` call confirms that PostgreSQL accepted the write. The process then
exits after closing the application-owned connection pool. UltimaBase has also
prepared the `Task` table in this disposable database.

If startup fails, first confirm that `DATABASE_URL` is loaded and that the
database accepts a connection from the same terminal.
