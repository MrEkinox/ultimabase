Use `Post.updateOne()` to change one persisted record. The `data` object names
only the fields you want to change; omitted fields keep their stored values.

This page continues with a `Post` like the one in [Create Records](./create).
The examples also assume a unique `slug`, an optional `summary`, and an integer
`editCount` initialized to `0`. Start the application with a persistence plugin
before running them.

## Update by ID

```ts title="src/update-post.ts"
import { Post } from './schemas.js'
import { ultimabase } from './ultimabase.js'

export const renamePost = (postId: string, title: string) =>
	Post.updateOne(
		{
			id: postId,
			data: { title },
			select: { title: true },
		},
		{ ultimabase },
	)
```

`id` is shorthand for `where: { id: { eq: postId } }`. Pass **either** `id`
**or** `where`, never both. To target a declared unique slug instead, use
`where: { slug: { eq: slug } }`; an arbitrary multi-match filter is not a
valid `updateOne` target.

## Verify the result

If a visible post matches, `renamePost()` returns a new immutable `Post` with
the same `id` and the updated `title`. The old model, if you loaded one, does
not change. Other post fields are absent from this selected result, not deleted
from storage. Without `select`, the command returns the complete visible model.

If no visible post matches, schema-level `updateOne()` returns `null`. Handle
that case before reading the result. A previously loaded model's `update()`
command is different: it targets that model's protected identity and throws
`NOT_FOUND` if the target has disappeared or become inaccessible. See
[Models](/docs/1.0.0/core/data-modeling/models) for instance commands.

## Replace, clear, or increment fields

Direct values replace stored values. `unset()` is another spelling for `null`
and can clear only an optional field. `increment()` and `decrement()` operate on
mutable numeric fields without a separate read-and-write cycle.

```ts title="src/update-post.ts"
import { increment, unset } from '@ultimabase/core'

import { Post } from './schemas.js'
import { ultimabase } from './ultimabase.js'

export const clearSummary = (postId: string) =>
	Post.updateOne(
		{
			id: postId,
			data: { summary: unset(), editCount: increment(1) },
			select: { summary: true, editCount: true },
		},
		{ ultimabase },
	)
```

This clears `summary` to `null` and increases `editCount` by one. Core checks
the complete projected numeric value against the field's rules while the
target is locked; the database still applies the delta atomically. An invalid
value, installed policy or hook failure, or persistence error rolls back the
whole update.

`select` shapes only the returned model. To return related data after an
update, add `include`, for example
`include: { author: { select: { displayName: true } } }`. The included target
is read inside the same transaction and remains subject to its read policy.
To change a pointer or relation rather than include it in the result, see
[Nested Writes](./nested-writes).
