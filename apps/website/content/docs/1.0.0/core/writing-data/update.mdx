Use `Post.updateOne()` to change one persisted record. The `data` object names
only the fields you want to change; omitted fields keep their stored values.

This page continues with a `Post` like the one in [Create Records](./create).
The examples also assume a unique `slug`, an optional `summary`, and an integer
`editCount` initialized to `0`. Start the application with a persistence plugin
before running them.

## Update by ID

```ts title="src/update-post.ts"
import { Post } from './schemas.js'

export const renamePost = (postId: string, title: string) =>
	Post.updateOne({
		where: { id: postId },
		data: { title },
		select: { title: true },
	})
```

`where` is the only target of `updateOne`, `deleteOne`, and `upsertOne`;
`{ id: postId }` is the equality shorthand of `{ id: { eq: postId } }`. To
target a declared unique slug instead, use `where: { slug }`; an arbitrary
multi-match filter is not a valid `updateOne` target. Its type is
`UniqueWhereInput<'Post'>`, so a wrong target fails to compile; see
[Choose a valid target](/docs/1.0.0/core/writing-data/upserts#choose-a-valid-target).

## Verify the result

If a visible post matches, `renamePost()` returns a new frozen plain result with
the same `id` and the updated `title`. A result you loaded earlier does not
change. Other post fields are absent from this selected result, not deleted
from storage. Without `select`, the command returns the complete visible row.

If no visible post matches, `updateOne()` returns `null`. Handle that case
before reading the result. Results have no `update()` method: to update a row
you loaded, pass its `id` as the target (ADR-0310). See
[Models](/docs/1.0.0/core/data-modeling/models) for the result contract.

## Replace, clear, or increment fields

Direct values replace stored values, and `null` clears an optional field. On a
numeric field, `{ increment: n }` and `{ decrement: n }` apply an atomic delta
without a separate read-and-write cycle, as in Prisma.

```ts title="src/update-post.ts"
import { Post } from './schemas.js'
import { ultimabase } from './ultimabase.js'

export const clearSummary = (postId: string) =>
	Post.updateOne({
		where: { id: postId },
		data: { summary: null, editCount: { increment: 1 } },
		select: { summary: true, editCount: true },
	})
```

This clears `summary` to `null` and increases `editCount` by one. Core checks
the complete projected numeric value against the field's rules while the
target is locked; the database still applies the delta atomically. An invalid
value, installed policy or hook failure, or persistence error rolls back the
whole update.

The delta uses the field's value type; do not convert exact values to a
JavaScript `number` merely to update them:

| Field kind | `increment` / `decrement` operand | Example                 |
| ---------- | --------------------------------- | ----------------------- |
| `int`      | Safe integer `number`             | `{ increment: 2 }`      |
| `float`    | Finite `number`                   | `{ decrement: 0.25 }`   |
| `decimal`  | Exact decimal `string`            | `{ increment: '1.25' }` |
| `bigint`   | Native JavaScript `bigint`        | `{ decrement: 1n }`     |

These operations work only on mutable scalar numeric fields, not numeric
lists or immutable fields, and take exactly one of `increment` or `decrement`.
They are accepted wherever update data is: root and nested updates and the
`update` branch of an upsert; create data has no atomic operations. Core validates both the operand and the projected
result; for example, an integer update cannot produce an unsafe integer and a
decimal update must fit its declared precision and scale. Use a direct value
when you intend to replace the field rather than apply an atomic delta.

`select` shapes only the returned model. To return related data after an
update, add `include`, for example
`include: { author: { select: { displayName: true } } }`. The included target
is read inside the same transaction and remains subject to its read policy.
To change a pointer or relation rather than include it in the result, see
[Nested Writes](./nested-writes).
