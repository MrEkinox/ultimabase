Every root mutation opens one automatic database transaction. Nested writes and
database work started by Hooks inherit it. A validation, policy, Hook, adapter,
or commit failure rolls back the mutation and discards its buffered events.

Use `RequestEngine.transaction()` when several root commands must share one
larger atomic unit:

```ts title="src/publish.ts"
import { requestSources } from '@ultimabase/core'

import { Account, Post } from './schemas.js'
import { ultimabase } from './ultimabase.js'

export const createPostAndRenameAuthor = (
	authorId: string,
	slug: string,
	title: string,
) => {
	const request = ultimabase.engine.anonymous({
		requestId: `publish:${slug}`,
		source: requestSources.internal,
	})

	return request.transaction(async () => {
		const post = await Post.createOne({
			data: { author: { connect: authorId }, slug, title },
		})

		await Account.updateOne({
			data: { displayName: 'Published author' },
			id: authorId,
		})

		return post
	})
}
```

The request engine carries the exact application, authority, request metadata,
and transaction. Nested explicit transactions and savepoints are not part of
the public contract.

Business Hooks run before commit and may abort it. Post-commit side effects use
named events buffered with `context.emit()`; subscribers run only after a
successful outer commit. There are no public schema `beforeCommit` or
`afterCommit` callback options. The Hooks package README remains the canonical
detailed contract until its dedicated guide is published.
