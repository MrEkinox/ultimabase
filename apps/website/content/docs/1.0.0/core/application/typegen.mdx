Typegen turns one compiled static application graph into precise TypeScript
declarations. It improves completion and catches invalid schema, operation,
filter, selection, plugin-field, and application-handle usage before Runtime.

```text
developer declarations + configured plugin graph
                       ↓ static compilation
             immutable application snapshot
                 ↙                    ↘
       Runtime behavior        Typegen declarations
```

## What the generated file is

The output is a deterministic, replaceable `.d.ts` artifact. It contains inert
types and explicitly owned inert plugin outputs, with a fingerprint covering
the application identity and relevant graph contracts. Writes replace the file
atomically.

It contains no callbacks, credentials, infrastructure handles, adapter state,
or executable Runtime client. Structured Typegen contributions cannot inject
arbitrary TypeScript or JavaScript.

## What remains authoritative

Developer schema declarations plus authorized deterministic plugin
contributions define the compiled graph. JavaScript applications execute that
same graph when generated declarations are absent. A stale file may mislead the
editor, but it cannot change Runtime visibility, validation, or relationship
behavior.

Automatic development generation runs after static compilation and before
infrastructure connects. If your build relies on generated types, arrange for
the artifact to exist before that build's typecheck and include it in the
deployed build. A dedicated Typegen CLI and watch workflow are not yet shipped.

## Enable it in the first application

The [First Application](/docs/1.0.0/getting-started/first-application) runs
without Typegen. To add generated editor declarations to that same project,
install the optional package:

```bash tab="npm" tab-group="package-manager"
npm install @ultimabase/typegen
```

```bash tab="yarn"
yarn add @ultimabase/typegen
```

```bash tab="pnpm"
pnpm add @ultimabase/typegen
```

Add `typegenPlugin()` to the existing application graph. Keep the PostgreSQL
plugin and the same `Task` schema; do not create a second Typegen-only
application:

```ts title="src/ultimabase.ts"
import { UltimaBase } from '@ultimabase/core'
import { postgresPlugin } from '@ultimabase/postgres-plugin'
import { typegenPlugin } from '@ultimabase/typegen'

import { Task } from './schema.js'

const databaseUrl = process.env.DATABASE_URL

if (databaseUrl === undefined) {
	throw new TypeError('DATABASE_URL is required')
}

export const ultimabase = new UltimaBase({
	plugins: [
		typegenPlugin(),
		postgresPlugin({ schemaPolicy: 'override', url: databaseUrl }),
	],
	schemas: [Task],
})
```

Include the generated declaration as well as your source files in TypeScript:

```json title="tsconfig.json"
{
	"compilerOptions": {
		"module": "NodeNext",
		"moduleResolution": "NodeNext",
		"outDir": "dist",
		"rootDir": "src",
		"skipLibCheck": true,
		"strict": true,
		"target": "ES2024",
		"types": ["node"]
	},
	"include": ["src", ".ultimabase/**/*.d.ts"]
}
```

Build and start the first application once with its existing scripts. Typegen
writes `.ultimabase/schema.generated.d.ts` during setup, before PostgreSQL
connects. The first application's `main.ts` also creates a `Task` on each run,
so keep using a disposable database. Then run `typecheck` to verify that
TypeScript reads the generated file:

```bash tab="npm" tab-group="package-manager"
npm run build
npm start
npm run typecheck
```

```bash tab="yarn"
yarn build
yarn start
yarn typecheck
```

```bash tab="pnpm"
pnpm build
pnpm start
pnpm typecheck
```

Do not import the `.d.ts` file as a Runtime client. It is replaceable editor
output, not a second source of application behavior. See
[Troubleshoot Typegen](/docs/1.0.0/operations/application-troubleshooting#typegen)
if generation fails, or [Schema Reference](/docs/1.0.0/reference/core-api/schema)
for the public declaration surface.
