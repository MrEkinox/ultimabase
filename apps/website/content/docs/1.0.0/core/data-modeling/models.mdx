`App.Schema.define()` returns a schema: a value that carries every command
(`findMany`, `createOne`, `updateOne`, `deleteOne`, and the others). Every read
and mutation returns frozen plain objects. A result is data, not a mutable row,
an open database connection, or an object with methods.

## Results are data

The example uses the `Product` schema from [Fields](./fields). Its application
must be started with a persistence plugin, as in
[Manual Installation](/docs/1.0.0/manual-installation).

```ts title="src/product-model.ts"
import { toJSON } from '@ultimabase/core'

import { Product } from './product.js'

const created = await Product.createOne({
	data: { name: 'Notebook', price: '19.90', tags: ['typescript'] },
	select: { name: true },
})
const updated = await Product.updateOne({
	where: { id: { eq: created.id } },
	data: { price: '24.90' },
	select: { name: true, price: true },
})

console.log(toJSON(updated))
```

`created` contains `name` and the implicitly selected `id`, but not `price` or
`tags`. Each result is a separate frozen object whose prototype is
`Object.prototype`: property reads, enumeration, spreading, and structural
comparison work as for any plain object, and no property can be reassigned.
The earlier `created` value keeps its earlier values; read again when you need
a fresh one.

A result holds:

- field values, with `bigint` and `Uint8Array` values for those field kinds;
- a `Pointer` for an unincluded pointer field;
- a plain object or `null` for an included pointer;
- an array of plain objects for an included relation.

Schemas are not constructible: `new Product(data)` throws, and a result has no
`create()`, `update()`, `fetch()`, `delete()`, `toPointer()`, or `relation()`.
Write through the schema
(`Product.updateOne({ where: { id: { eq: product.id } }, data })`), read related
rows with `include` or a relation filter, and link rows with nested writes such
as `{ tags: { connect: [tagId] } }`. A `Pointer` keeps `id`, `schema`,
`equals()` and `toJSON()`; read its target with the target schema.

## Visible fields and identity

Every result includes `id`, even when `select` does not name it. This also
applies to included related rows. `id: false` is invalid. Other fields may be
narrowed by the selection and by an installed output policy. See
[Selections](/docs/1.0.0/core/reading-data/selections) for inclusion and
exclusion rules.

## Named types

`Model<T>`, `CreateInput<T>`, `UpdateInput<T>` and `UniqueWhereInput<T>` name
the result, the write data and the unique target of one schema. `T` is a registered schema name, such as `Model<'Product'>`,
or a schema type, such as `Model<typeof Product>`.

```ts title="src/product-types.ts"
import type { CreateInput, Model } from '@ultimabase/core'

import { Product } from './product.js'

export const describe = (product: Model<typeof Product>): string =>
	`${product.name}: ${product.price}`

export const draft: CreateInput<typeof Product> = {
	name: 'Notebook',
	price: '19.90',
}
```

`Model<T>` is the result of `findOne` without `select` or `include`.
`CreateInput<T>` is the `data` of `createOne`, nested writes included.
`UniqueWhereInput<T>` is the `where` of `updateOne`, `deleteOne`, and
`upsertOne`: `{ id }`, each unique field, or each unique index of `define`
without `where`, with all of its fields.

## Serialize with toJSON

`JSON.stringify` on a raw result throws on `bigint` values. `toJSON(value)`
serializes a result, a list of results, or any value inside them exactly as REST
responses do: `bigint` as a decimal string, binary as
`{ type: 'binary', encoding: 'base64', data }`, a `Pointer` as
`{ type: 'pointer', className, id }`, and included rows and embedded objects
recursively. Its return type, `JsonOf<T>`, describes that JSON shape. Use it in
custom routes, logs, and responses: `Response.json(toJSON(product))`.

`toJSON` is strict: it throws on `undefined`, non-finite numbers, circular
values, and objects it cannot represent.
