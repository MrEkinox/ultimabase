Master is trusted server-side authority for work that must bypass
authorization. It belongs to one exact application and requires a successful
audit before an elevated command runs. It is not a role, authenticated user,
transport flag, or substitute for an ordinary application policy.

## Configure a trusted server command

The example assumes `DATABASE_URL` and `ULTIMABASE_MASTER_KEY` are supplied by
the server environment. It uses PostgreSQL for persistence and the optional
Access plugin with its default-deny policy; an ordinary anonymous create would
be denied. Keep the code on the server, never in a browser bundle.

```ts title="src/maintenance.ts"
import { accessPlugin } from '@ultimabase/access-plugin'
import { MasterAuthority, Schema, UltimaBase } from '@ultimabase/core'
import { postgresPlugin } from '@ultimabase/postgres-plugin'

const databaseUrl = process.env.DATABASE_URL
const masterKey = process.env.ULTIMABASE_MASTER_KEY

if (!databaseUrl || !masterKey) {
	throw new TypeError('DATABASE_URL and ULTIMABASE_MASTER_KEY are required')
}

const Post = Schema.define({
	className: 'Post',
	fields: (f) => ({ title: f.string({ required: true }) }),
})

const masterAuthority = new MasterAuthority({
	keys: [{ id: 'maintenance', value: masterKey }],
	onUse: (event) => {
		console.info('Master use', {
			keyId: event.keyId,
			reason: event.reason,
			requestId: event.requestId,
		})
	},
})

export const ultimabase = new UltimaBase({
	masterAuthority,
	plugins: [accessPlugin(), postgresPlugin({ url: databaseUrl })],
	schemas: [Post],
})

await ultimabase.start()

export const createMaintenancePost = (title: string) =>
	Post.createOne({ data: { title } }, { ultimabase, useMasterKey: true })
```

Calling `createMaintenancePost('Rebuild complete')` from trusted server code
returns the created model and emits one audit event before the write. If the
audit callback throws, elevation fails and no post is written. `console.info`
is only a local demonstration; use an audit sink with appropriate durability,
access controls, and failure handling for production.

## Choose the entry path

`useMasterKey: true` is the concise, trusted direct-server option. It uses the
first configured key ID for the audit and does not verify a raw key at that
call. When a trusted boundary receives a raw key, `MasterAuthority.authorize()`
verifies it and returns an opaque grant; `RequestEngine.useMasterKey(grant,
reason)` then audits and binds the elevation to its exact application. A
grant or Master context from another application is rejected, even if both
applications reuse the same `MasterAuthority` object in sequential lifetimes.
Disposing an application does not make its grants or contexts reusable: obtain
a fresh grant for its replacement. This does not revoke persisted user sessions.

The optional HTTP Master header works only when explicitly enabled. The
public application ID selects one application first; only that application's
authority may verify and audit the raw key. A client-supplied `useMasterKey`
flag, shaped context, foreign grant, or alternative header cannot select
Master. See [HTTP](/docs/1.0.0/plugins/official/http) for that
separate transport setup.

## Know what Master bypasses

Master bypasses authorization owned by Access and ACL. It does **not** bypass:

- Core structural validation or installed application validation;
- Hooks, input resolution, or prepared-operation transforms;
- automatic transactions, database constraints, or rollback;
- reference maintenance, lifecycle work, or integrity checks.

<Callout type="warn" title="Keep credentials out of public output">
	Client `useMasterKey` flags, shaped contexts, metadata, grants, and
	alternative headers never create Master. Never log a raw key or place it in
	request metadata, a schema field, a browser bundle, or an error response.
</Callout>

A public application ID identifies the expected active application; it is public data,
not a secret or authorization proof. For ordinary user requests, use
[Access](/docs/1.0.0/plugins/official/access)
or [ACL](/docs/1.0.0/plugins/official/acl-permissions)
instead of Master.
