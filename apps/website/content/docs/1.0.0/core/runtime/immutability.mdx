UltimaBase's query builders and schema models are immutable. A builder method
returns a new branch; a model command returns a new snapshot. Neither changes
the value you already hold.

## Branch a read without shared state

Assume `Post` declares a `published` boolean and a `title` string. Build a
reusable selection, then branch its filter:

```ts title="src/post-queries.ts"
import { QueryBuilder } from '@ultimabase/core'

import { Post } from './schemas.js'

const base = new QueryBuilder(Post).select({ title: true })

export const publishedInput = base.where({ published: { eq: true } }).build()

export const draftInput = base.where({ published: { eq: false } }).build()
```

Both inputs select `title`, but each has its own filter. `base` still has no
`where` clause. `build()` returns the ordinary input for `Post.findMany()`;
building and branching perform no I/O and retain no request, application, or
authority. Execution binds the input to a started application or the current
request scope.

## Keep model snapshots separate

A `new Post(data)` draft is detached and performs no I/O. A model returned by
Runtime is a persisted snapshot of exactly its visible selected fields. A
persisted model's `update()` writes through the normal validation, policy, Hook,
and transaction path, then returns a new model with the same identity. The
earlier model still shows its earlier values; use `fetch()` when you need a
fresh read.

`get()` and `toJSON()` only inspect the snapshot. They do not lazy-load missing
fields, and `get()` rejects a field that was not selected. There is no dirty
tracking, mutable `save()`, or direct adapter persistence path.

## Related values and tasks

Optional ACL and Role domain values follow the same replacement pattern:
adding an entry or membership returns a new value. They do not change an
earlier value held by another request.

Use [Query Overview](/docs/1.0.0/core/reading-data/overview) for execution,
[Models](/docs/1.0.0/core/data-modeling/models) for draft and persisted
commands, and [ACL](/docs/1.0.0/plugins/official/acl-permissions)
for immutable object policy.
