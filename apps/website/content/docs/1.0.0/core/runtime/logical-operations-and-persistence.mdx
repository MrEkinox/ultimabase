## Meaning before mechanics

The logical operation records application meaning: create, read, update,
delete, or a declared plugin operation against a schema. Policy, Hooks, audit,
results, and relationships reason about that stable meaning.

The persistence plan describes how the adapter fulfills it. A plugin with the
exact privilege may rewrite that physical plan without changing the logical
operation seen by the rest of Runtime.

## Protected constraints stay protected

Row filters and adapter constraints accumulated by policy do not enter the
replaceable plan. Core carries them beside it and the adapter combines every
constraint with `AND`. A persistence rewrite therefore cannot drop an ACL
filter, bypass tenant-like restrictions, or turn a denied target into a visible
one.

Transports remain outside both layers. They normalize requests and serialize
results; they never issue SQL or receive a raw adapter. Database-specific
compilation stays in the database plugin.

[Access](/docs/1.0.0/plugins/official/authentication-and-authorization/access) for logical policy, and
[PostgreSQL](/docs/1.0.0/plugins/official/data-and-persistence/postgresql) for adapter ownership.
