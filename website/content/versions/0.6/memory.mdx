title: memory()
description: The database kept in the process, for a first application and the tests.
---

`memory()` keeps the rows in the Node process: nothing to install or run.
It ships with `ultimabase`, so a first application and every test start on
it. The rows last until the application stops.

```ts title="src/app.ts"
import { graphqlPlugin } from '@ultimabase/graphql'
import { httpPlugin } from '@ultimabase/http'
import { defineApp, memory } from 'ultimabase'
import { Contact } from './models.ts'

export const app = defineApp({
	// Nothing to install or run: the rows live in the process.
	database: memory(),
	plugins: [httpPlugin(), graphqlPlugin()],
	models: [Contact],
})
```

The full example, with its tests: [`examples/memory`](https://github.com/MrEkinox/ultimabase/tree/main/examples/memory).

For data that must outlive the process, use [PostgreSQL](/docs/next/postgres):
the models, the queries and the errors stay the same.

## Empty at each start

Each `start` begins on an empty database. `testApplication` starts the
application around each test, so each test begins without rows:

```ts title="src/app.test.ts"
it('writes a note', async () => {
	await Note.create({ data: { text: 'Milk', ownerId: 'ada' } }, { as: master })
	expect(await Note.count({}, { as: master })).toBe(1)
})

it('starts on an empty database', async () => {
	expect(await Note.count({}, { as: master })).toBe(0)
})
```

`ultimabase dev` restarts the application when a file changes: the rows
written before are gone.

## A write is whole or not at all

A write that fails puts back every row it changed, so it changes nothing, as
a PostgreSQL statement does:

```ts title="src/app.test.ts"
const ada = { name: 'Ada', email: 'ada@example.com' }
// The second has the first's email: the whole write is refused.
const data = [ada, { ...ada, name: 'Ada L.' }]
await expect(Contact.createMany({ data }, as)).rejects.toMatchObject({
	code: 'UNIQUE_VIOLATION',
})
expect(await Contact.count({}, as)).toBe(0)
```

- Writes run one at a time; an open [transaction](/docs/next/transactions)
  holds the others until it ends.
- A query that fails inside a transaction rolls it back, as on PostgreSQL.

## What it shares with PostgreSQL

A test on `memory()` passes on PostgreSQL: both adapters run the same suite
of tests.

### Sort order

Strings sort by their bytes, as PostgreSQL's `"C"` collation does:

```ts title="src/app.test.ts"
const names = ['adam', 'Émile', 'Zoe', 'Ada']
const data = names.map((name) => ({ name, email: `${name}@example.com` }))
await Contact.createMany({ data }, as)
const sorted = await Contact.findMany({ orderBy: { name: 'asc' } }, as)
// Capitals first, then small letters, then letters with accents.
expect(sorted.map((contact) => contact.name)).toEqual([
	'Ada',
	'Zoe',
	'adam',
	'Émile',
])
```

### Search

`_search` reads words as PostgreSQL's `'simple'` configuration does:

- a word is a run of letters and digits, in any case;
- there are no stems and no stop words;
- relevance follows PostgreSQL's `ts_rank`.

```ts title="src/app.test.ts"
// With the contacts 'Émile Zola' and 'Jean-Paul Sartre'.
const search = async (words: string) =>
	(await Contact.findMany({ where: { _search: words } }, as)).map(
		(contact) => contact.name,
	)
// Words ignore case, a hyphen separates them, an accent counts.
expect(await search('ZOLA')).toEqual(['Émile Zola'])
expect(await search('paul')).toEqual(['Jean-Paul Sartre'])
expect(await search('emile')).toEqual([])
```

### Realtime

Changes reach the clients after the write, as PostgreSQL's notifications
do (see [Realtime](/docs/next/realtime)).

## What it does not do

- It has no tables to migrate: `sync`, `reset` and each `migrate` command
  refuse it.
- One process holds the rows: two instances of the application share
  nothing.
- `postgres({ searchLanguage })` stems words in a language; `memory()` reads
  them as `'simple'` only.
- Raw SQL, a database tool, a dump: test those on PostgreSQL, in a
  `*.postgres.test.ts` file (see [Testing](/docs/next/testing#on-postgresql)).

## Reference

### `memory()`

It takes no options, and returns the database for `defineApp`'s `database`.

### Errors

| Message                                                               | When                                                   |
| --------------------------------------------------------------------- | ------------------------------------------------------ |
| `This database starts empty every time: it has no tables to migrate.` | `ultimabase sync`, `reset` or `migrate` on `memory()`. |

The errors of a query are those of every database: see
[Errors](/docs/next/errors).

### Limits

- The rows live as long as the process: a stop, a crash or a restart loses
  them.
- Each write copies the rows: keep it to tests and development, with the
  rows they need.
- Writes run one at a time, in the order they came.
