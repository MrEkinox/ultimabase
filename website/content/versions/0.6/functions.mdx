---
title: Functions
description: Declare a server operation with a validated input, a typed output and an access rule, served by every transport.
---

A function is an operation the server runs: search the books, borrow one,
merge two accounts. `defineFunction` names it, validates its input, types its
output, and every transport serves it:

```ts title="src/search.ts"
import { allow, defineFunction } from 'ultimabase'
import { z } from 'zod'
import { Book } from './models.ts'

// A query: served over GraphQL's Query and REST's GET.
export const searchBooks = defineFunction({
	name: 'searchBooks',
	query: true,
	input: z.object({ text: z.string().min(1), available: z.boolean() }),
	output: [Book],
	run: ({ input, caller }) =>
		Book.findMany(
			{
				where: {
					_search: input.text,
					...(input.available ? { borrowedBy: null } : {}),
				},
			},
			{ as: caller },
		),
}).with({ access: allow.public })
```

The full example, with its tests: [`examples/functions`](https://github.com/MrEkinox/ultimabase/tree/main/examples/functions).

- GraphQL serves it as a query, on `POST /graphql`, and REST as
  `GET /api/functions/searchBooks`.
- `input` is a Standard Schema (Zod, Valibot, ArkType…). The examples use Zod,
  a package of its own.
- `output` types the answer: here a list of `Book`.
- `run` receives the validated `input` and the `caller`.

```npm
npm install zod
```

The functions read and write `Book`, a model with a searchable `title` and
an optional `borrowedBy`. Clients may only read it:

```ts title="src/models.ts"
import { graphql } from '@ultimabase/graphql'
import { rest } from '@ultimabase/rest'
import { allow, defineModel } from 'ultimabase'

export const Book = defineModel({
	name: 'Book',
	use: [graphql(), rest()],
	fields: (f) => ({
		title: f.string({ search: true }),
		borrowedBy: f.string({ optional: true }),
	}),
}).with({ access: allow.readOnly })
```

The tests write two books, Emma and Dune, as Master.

| To                             | Use                                                      |
| ------------------------------ | -------------------------------------------------------- |
| serve it                       | [`defineApp({ functions })`](#add-it-to-the-application) |
| write rows no client may write | [`{ as: master }`](#write-as-the-server)                 |
| call it from server code       | [`fn.run`](#call-it-from-server-code)                    |
| refuse a caller                | [`.with({ access })`](#access-and-validation)            |
| read data, over GET too        | [`query: true`](#queries-and-outputs)                    |
| return nothing, or a shape     | [`output`](#queries-and-outputs)                         |
| rename it in a transport       | [`.with({ graphql: { name } })`](#queries-and-outputs)   |
| return a page of rows          | [`Book.paginated()`](#pages)                             |

## Add it to the application

`defineApp({ functions: [...] })` lists every function:

```ts title="src/app.ts"
import { graphqlPlugin } from '@ultimabase/graphql'
import { httpPlugin } from '@ultimabase/http'
import { restPlugin } from '@ultimabase/rest'
import { defineApp, memory } from 'ultimabase'
import { borrowBook, returnBooks, shelf } from './functions.ts'
import { Book } from './models.ts'
import { searchBooks } from './search.ts'

export const app = defineApp({
	// Kept in memory, so the example needs no database.
	database: memory(),
	// Listens on PORT, or 3000.
	plugins: [httpPlugin(), restPlugin(), graphqlPlugin()],
	models: [Book],
	functions: [borrowBook, searchBooks, returnBooks, shelf],
})
```

## Write as the server

A function is trusted server code. Its queries pass `{ as: caller }` to keep
the caller's rules, or `{ as: master }` to write what no client writes, as
`Book` here. The function below returns a `Loan`, a named object that holds a
model and data:

```ts title="src/functions.ts"
// A named object: a model and data together.
export const Loan = defineType({
	name: 'Loan',
	fields: { book: Book, dueOn: z.iso.date() },
})
```

```ts title="src/functions.ts"
export const borrowBook = defineFunction({
	name: 'borrowBook',
	input: z.object({ book: z.string(), days: z.int().min(1).max(30) }),
	output: Loan,
	// `user` is the signed-in caller's record; the access rule lets in no one
	// else.
	run: signedInRun(async ({ input, caller, user }) => {
		const book = await Book.findUniqueOrThrow(
			{ where: { id: input.book } },
			{ as: caller },
		)
		if (book.borrowedBy !== null) {
			throw new PublicError('BOOK_BORROWED', `${book.title} is out.`)
		}
		// Book is read-only for clients: the function writes as the server.
		const lent = await Book.update(
			{ where: { id: book.id }, data: { borrowedBy: user.id } },
			{ as: master },
		)
		const due = new Date(Date.now() + input.days * 86_400_000)
		return { book: lent, dueOn: due.toISOString().slice(0, 10) }
	}),
}).with({ access: isAuthenticated })
```

- `signedInRun`, from [`@ultimabase/auth`](/docs/next/auth), wraps a `run` for
  signed-in users and adds `user`, the caller's record, typed.
- The rule `isAuthenticated`, from `@ultimabase/auth` too, refuses a visitor with `ACCESS_DENIED` before
  `run`.
- Master passes every rule, so the wrapper refuses Master, and anyone a wider
  rule lets in, with `UNAUTHENTICATED`.
- A check that needs the input, or another row, throws from `run`. A
  `PublicError` reaches the client with its code, message and details: see
  [Errors](/docs/next/errors).

## Call it from server code

`fn.run(input, { as })` does what a transport does: it checks the access rule,
validates the input, then runs the function and returns its output, typed.
In the tests, `ada` and `grace` stand for `{ as: asUser({ id: 'ada' }) }` and
`{ as: asUser({ id: 'grace' }) }`, and `dune` for the id of the book Dune:

```ts title="src/app.test.ts"
const loan = await borrowBook.run({ book: dune, days: 14 }, ada)
expect(loan.book.borrowedBy).toBe('ada')
expect(loan.dueOn).toMatch(/^\d{4}-\d{2}-\d{2}$/)
```

```ts title="src/app.test.ts"
// A PublicError thrown by `run` reaches the caller.
await expect(
	borrowBook.run({ book: dune, days: 7 }, grace),
).rejects.toMatchObject({ code: 'BOOK_BORROWED', message: 'Dune is out.' })
```

A function without an input takes only `{ as }`:

```ts title="src/app.test.ts"
// A function without an input takes only `{ as }`.
await returnBooks.run(ada)
const available = await searchBooks.run({ text: 'dune', available: true }, ada)
expect(available.map((book) => book.title)).toEqual(['Dune'])
```

A function that calls another uses `run` too, so the other's rule and
validation apply.

## Access and validation

`.with({ access })` takes one rule, which receives `{ caller }` only. A
function without one is closed to all but Master. The rule runs before the
input is validated, so a refused caller learns nothing of what the input
should be:

```ts title="src/app.test.ts"
// Without `as`, the caller is anonymous.
await expect(borrowBook.run({ book: dune, days: 14 })).rejects.toMatchObject({
	code: 'ACCESS_DENIED',
	message: 'borrowBook refused.',
	details: { function: 'borrowBook' },
})
```

An input that does not match is refused after the rule:

```ts title="src/app.test.ts"
await expect(
	borrowBook.run({ book: dune, days: 90 }, ada),
).rejects.toMatchObject({
	code: 'VALIDATION_FAILED',
	message: 'Invalid input.',
	details: { issues: [{ path: ['days'] }] },
})
```

## Queries and outputs

`query: true` makes a function a query: GraphQL serves it under `Query`, over
GET and POST, and REST over GET. A function is a mutation otherwise.

The output is one of:

- a model (`Book`), a list (`[Book]`), or a model or `null` (`Book.nullable()`);
- a [`defineType`](/docs/next/models#object-types) holding models and data
  (`Loan` above);
- a Standard Schema, for data alone.

Without an output, `run` returns nothing and GraphQL answers `true`.
`use` names the transports whose key `.with` sets (`graphql` comes from
`@ultimabase/graphql`), and a function takes `{ name }` there, to rename it in
that transport:

```ts title="src/functions.ts"
// No input and no output: GraphQL answers `true`.
export const returnBooks = defineFunction({
	name: 'returnBooks',
	// The transports whose key `.with` sets.
	use: [graphql()],
	run: signedInRun(async ({ user }) => {
		await Book.updateMany(
			{ where: { borrowedBy: user.id }, data: { borrowedBy: null } },
			{ as: master },
		)
	}),
}).with({
	access: isAuthenticated,
	// Named `giveBack` in GraphQL; REST keeps `returnBooks`.
	graphql: { name: 'giveBack' },
})
```

The output is typed, not validated: `run` must return what it declares. A
string returned for an enum takes `as const`, as in
`{ result: 'passed' as const }`. TypeScript reads the literal as a `string`
otherwise, since it checks `run` before it knows the output's type.

## Over the transports

An object input gives GraphQL one argument per property. REST gives one query
parameter per property on a GET, or a JSON body on a POST. Both answer with the
same output.

GraphQL:

```graphql title="Request"
query {
	searchBooks(text: "dune", available: true) {
		title
	}
}
```

```json title="Response"
{ "data": { "searchBooks": [{ "title": "Dune" }] } }
```

REST, a GET with the input in the query string:

```http title="Request"
GET /api/functions/searchBooks?text=dune&available=true
```

```json title="Response"
[
	{
		"id": "…",
		"createdAt": "…",
		"updatedAt": "…",
		"title": "Dune",
		"borrowedBy": null
	}
]
```

A mutation is a POST with its input in the body. `$id` stands for the id of
Dune, which the test fills in. This request has no session, so the rule refuses
it with a `403`:

```http title="Request"
POST /api/functions/borrowBook
content-type: application/json

{ "book": "$id", "days": 14 }
```

```json title="Response"
{
	"code": "ACCESS_DENIED",
	"message": "borrowBook refused.",
	"details": { "function": "borrowBook" }
}
```

`returnBooks` above is named `giveBack` in GraphQL, and keeps `returnBooks` in
REST. Called without a session on `POST /graphql`, it answers `ACCESS_DENIED`:

```graphql title="Request"
mutation {
	giveBack
}
```

```json title="Response"
{
	"errors": [
		{
			"message": "returnBooks refused.",
			"locations": [{ "line": 2, "column": 2 }],
			"path": ["giveBack"],
			"extensions": {
				"code": "ACCESS_DENIED",
				"details": { "function": "returnBooks" }
			}
		}
	],
	"data": null
}
```

- A client selecting a relation under a returned row gets it read again as the
  caller, with its rules.
- The row's fields and [virtual fields](/docs/next/models#virtual-fields) are
  those `run` returned, over REST and GraphQL as from server code.
- A function opens no transaction: see
  [Transactions](/docs/next/transactions) to write all or nothing.

## Pages

A query whose output is `Book.paginated()` returns `Book.paginate(...)`: the
rows its `where` and `orderBy` keep, read as the caller. Nothing is read until
a transport, or server code, asks for the rows or the count:

```ts title="src/functions.ts"
// A page: a client pages it as Book's generated list, and counts it.
export const shelf = defineFunction({
	name: 'shelf',
	query: true,
	output: Book.paginated(),
	run: ({ caller }) =>
		Book.paginate(
			{ where: { borrowedBy: null }, orderBy: { title: 'asc' } },
			{ as: caller },
		),
}).with({ access: allow.public })
```

From server code, `run` returns the page:

```ts title="src/app.test.ts"
// From server code, `run` returns the page: rows and a count, read when asked.
const page = await shelf.run(ada)
expect(await page.count()).toBe(2)
const [first] = await page.findMany({ take: 1 })
expect(first?.title).toBe('Dune')
```

Each transport pages it as the model's generated list: the same arguments, the
same `maxTake`, the same answer. `totalCount` is counted only when a client
asks for it.

- The arguments are `first`, `after`, `last`, `before`, or `take` and `skip`
  with `pagination: 'list'`.

Both books are on the shelf. A page of one holds Dune, and `totalCount` is 2:

```graphql title="Request"
query {
	shelf(first: 1) {
		edges {
			node {
				title
			}
		}
		totalCount
	}
}
```

```json title="Response"
{
	"data": {
		"shelf": { "edges": [{ "node": { "title": "Dune" } }], "totalCount": 2 }
	}
}
```

REST answers as `GET /api/books` does, with the same parameters. With one book
asked, `hasNextPage` is `true`:

```http title="Request"
GET /api/functions/shelf?first=1&totalCount=true
```

```json title="Response"
{
	"edges": [
		{
			"cursor": "…",
			"node": {
				"id": "…",
				"createdAt": "…",
				"updatedAt": "…",
				"title": "Dune",
				"borrowedBy": null
			}
		}
	],
	"pageInfo": {
		"hasNextPage": true,
		"hasPreviousPage": false,
		"startCursor": "…",
		"endCursor": "…"
	},
	"totalCount": 2
}
```

## Details

- A `defineType` field can be a page too, at any depth. In GraphQL that field
  takes the page arguments.
- In REST, one JSON parameter named by the field's path takes them, as
  `profile.posts={"first":20,"totalCount":true}`.
- A schema given `.meta({ id: 'Line' })` is the shared GraphQL type `Line`,
  and `LineInput` as an input.
- `z.uuid()` is an `ID` in GraphQL, as a row's `id`, and a `string` of format
  `uuid` in OpenAPI. A client passes a row's `id` to a function with the
  variable type it reads it with, `$id: ID!`.

## Reference

### `defineFunction(definition)`

| Key           | Type                       | Default  | Effect                                                                                                             |
| ------------- | -------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------ |
| `name`        | `string`                   | required | The GraphQL field's name and the REST route's.                                                                     |
| `run`         | `(facts) => output`        | required | The operation; may be `async`.                                                                                     |
| `input`       | a Standard Schema          | none     | Validates the input; without it, `run` receives none.                                                              |
| `output`      | see below                  | none     | The output's type; without it, `run` returns nothing.                                                              |
| `query`       | `boolean`                  | `false`  | A query, over GET too; a mutation otherwise.                                                                       |
| `use`         | `[graphql()]`, `[rest()]`… | `[]`     | The transports whose key `.with` sets. Every transport serves it.                                                  |
| `description` | `string`                   | none     | Shown in the GraphQL schema and the OpenAPI document.                                                              |
| `deprecated`  | `string`                   | none     | Why clients should stop calling it, and what replaces it: `@deprecated` in GraphQL, `deprecated: true` in OpenAPI. |

`.with({ access, graphql, rest })` sets its rule and, for a transport of
`use`, `{ name }` to rename it there or `false` to hide it.

### What `run` receives

| Fact     | Value                                                                  |
| -------- | ---------------------------------------------------------------------- |
| `input`  | the validated input, with the schema's defaults and transforms         |
| `caller` | who calls: see [Access rules](/docs/next/access)                       |
| `client` | over a transport, `{ address, cookies }`; `undefined` from server code |

`client.cookies` has `get(name)`, `set(name, value, options?)` and
`clear(name, options?)`, written on the HTTP response.

### Outputs

| Output             | `run` returns           | GraphQL              |
| ------------------ | ----------------------- | -------------------- |
| none               | nothing                 | `Boolean!`           |
| `Book`             | a row                   | `Book!`              |
| `[Book]`           | rows                    | `[Book!]!`           |
| `Book.nullable()`  | a row or `null`         | `Book`               |
| `Book.paginated()` | `Book.paginate(...)`    | `BookConnection!`    |
| a `defineType`     | an object of its fields | the type             |
| a Standard Schema  | the schema's type       | from its JSON Schema |

### Errors

| Code                | When                                       | `details`                         |
| ------------------- | ------------------------------------------ | --------------------------------- |
| `ACCESS_DENIED`     | The rule refused: `borrowBook refused.`    | `{ function }`                    |
| `VALIDATION_FAILED` | The input does not match: `Invalid input.` | `{ issues: [{ path, message }] }` |

### Limits

- The access rule is synchronous and receives no input.
- A schema without a JSON Schema export, as `z.date()`, stops startup:
  `z.iso.datetime()` is a `DateTime` in GraphQL.
- A name another function or a model's generated query already takes stops
  startup, naming both.
- A page is a query's output, never under a list, in a virtual or live. An
  input property named as a page argument stops startup.
