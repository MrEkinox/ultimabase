title: Files
description: Upload files to S3-compatible storage, attach them to rows, and never leave an orphan.
---

`@ultimabase/files` stores files in S3 or any S3-compatible storage, and adds
the field type `file()`.

```npm
npm install @ultimabase/files
```

`filesPlugin()` goes in the application's plugins, after `httpPlugin()`, which
it requires. It takes the storage, and who may upload:

```ts
import { filesPlugin } from '@ultimabase/files'
import { graphqlPlugin } from '@ultimabase/graphql'
import { httpPlugin } from '@ultimabase/http'
import { allow, defineApp, memory } from 'ultimabase'
import { Post } from './models.ts'
import { chooseStorage } from './storage.ts'

export const app = defineApp({
	database: memory(),
	plugins: [
		httpPlugin(),
		graphqlPlugin(),
		// A signed-in user uploads by default; here, anyone.
		filesPlugin({ storage: chooseStorage(), access: { upload: allow.public } }),
	],
	models: [Post],
})
```

The full example, with its tests: [`examples/files`](https://github.com/MrEkinox/ultimabase/tree/main/examples/files).

| To                                    | Use                                                 |
| ------------------------------------- | --------------------------------------------------- |
| attach a file to a row                | [`file()`, then `POST /files`](#add-a-file-field)   |
| upload from a browser                 | [`uploader()`](#upload-then-write-the-id)           |
| attach several files, in order        | [`list: true`](#lists-of-files)                     |
| accept some types, limit the size     | [`accept`, `maxSize`](#types-and-sizes)             |
| read a width, a thumbnail             | [`inline`, `variants`](#inline-values-and-variants) |
| serve a file from a CDN, or privately | [`public`](#public-and-private-files)               |
| upload from server code               | [`files.upload`, `files.check`](#from-server-code)  |
| choose S3, a directory or memory      | [`s3()`, `diskFiles()`, `memoryFiles()`](#storage)  |

A client uploads a file first, then writes its id in a row, as any other
value. A replaced or deleted file leaves the storage after the commit, so no
object is left without a row.

## Add a file field

`file()` is a field type. The model's file starts with these imports. It has
`use: [graphql()]` and ends with `.with({ access: allow.public })`: the model
is open to every client, to keep the example on files.

```ts
import { file } from '@ultimabase/files'
import { graphql } from '@ultimabase/graphql'
import { allow, defineModel } from 'ultimabase'
import { z } from 'zod'
```

A post here has a public cover image, which takes PNG files of 5 MB at most:

```ts
cover: file({
	optional: true,
	accept: ['image/png'],
	maxSize: 5_000_000,
	// A stable URL, which a CDN may cache.
	public: true,
	// Computed once at upload, and read with the post.
	inline: {
		size: {
			run: ({ body }) => pngSize(body),
			schema: z.object({ width: z.int(), height: z.int() }).nullable(),
		},
	},
}),
```

Its width and height are read once at upload, by `inline`, which
[a later section](#inline-values-and-variants) shows. `file()`'s options are
in the [reference](#fileoptions).

## Upload, then write the id

A client sends the file to `POST /files` with the field it is for, and gets
its `id` back. In a browser, `uploader()` from `@ultimabase/files/client` does
it, then the client writes the id in the post, over GraphQL or REST:

```ts
const client = uploader({ url: running.url })
const cover = new File([png], 'cover.png', { type: 'image/png' })
const id = await client.upload(cover, { for: 'Post.cover' })
```

The Request writes the id the upload returned, as `$cover`:

```graphql
mutation ($cover: JSON) {
	createPost(data: { title: "Hello", cover: $cover }) {
		cover {
			id
			name
			type
			size
			inline {
				size {
					width
					height
				}
			}
		}
	}
}
```

```json
{
	"data": {
		"createPost": {
			"cover": {
				"id": "…",
				"name": "cover.png",
				"type": "image/png",
				"size": 68,
				"inline": { "size": { "width": 1, "height": 1 } }
			}
		}
	}
}
```

`uploader()` imports nothing of the server, and takes a `File` or a list of
them, such as an input's `FileList`. The client reads the file back with its
`url` and its `inline` values; a public file's `url` is stable. The Request
reads it:

```graphql
query {
	posts {
		edges {
			node {
				cover {
					name
					url
				}
			}
		}
	}
}
```

The `url` is the storage's own: here `http://localhost:<port>/files/public/…`,
which the application serves for `memoryFiles()`.

- An upload is pending for one hour: written in a row by then, it is
  attached; otherwise it is deleted.
- Only its uploader may write it, and only in the field it was uploaded for.
  Master writes any.
- A visitor's upload has no uploader, so any caller may write it, as in this
  example.

## Lists of files

A field with `list: true` holds files in order, each once, and reads `[]` when
empty. The attachments of a post are private text files:

```ts
attachments: file({
	list: true,
	// Text is not detected from its bytes: these types are taken as
	// declared, and served as downloads.
	accept: ['text/plain', 'text/csv'],
	maxSize: 100_000,
	// A file of its own, made at upload: the first 100 bytes.
	variants: {
		preview: ({ body }) => ({
			body: body.slice(0, 100),
			type: 'text/plain',
		}),
	},
}),
```

A write gives the new list of ids, or one of the list operations of a kernel
[list](/docs/next/models):

| Write                      | Effect                             |
| -------------------------- | ---------------------------------- |
| `["<id>", "<id>"]`         | Replaces the list.                 |
| `{ set: ["<id>"] }`        | Replaces the list.                 |
| `{ push: ["<id>"] }`       | Adds the files at the end.         |
| `{ pushUnique: ["<id>"] }` | Adds those the list does not hold. |
| `{ remove: ["<id>"] }`     | Removes the files.                 |

Pushing a file. The post holds `notes.txt`, a 17-byte text file; the request
pushes `prices.txt`, and the test passes `$id` as the post's id and `$attachments`
as `{ push: [<id of prices.txt>] }`:

```graphql
mutation ($id: ID!, $attachments: JSON) {
	updatePost(where: { id: $id }, data: { attachments: $attachments }) {
		attachments {
			name
			variants {
				preview {
					type
					size
				}
			}
		}
	}
}
```

```json
{
	"data": {
		"updatePost": {
			"attachments": [
				{
					"name": "notes.txt",
					"variants": { "preview": { "type": "text/plain", "size": 17 } }
				},
				{
					"name": "prices.txt",
					"variants": { "preview": { "type": "text/plain", "size": 18 } }
				}
			]
		}
	}
}
```

Two clients pushing at once keep both files: the list is computed on the row
the write has locked. A private file's `url` is signed:
`/files/private/…?expires=…&signature=…`. The request above does not select
it.

## Types and sizes

The type is read from the file's first bytes, never trusted from the client.
`accept` lists the types a field takes, and an upload of another type is
refused:

```ts
const client = uploader({ url: running.url })
const text = new File(['Not a picture.'], 'cover.txt', {
	type: 'text/plain',
})
const refused: unknown = await client
	.upload(text, { for: 'Post.cover' })
	.catch((error: unknown) => error)
expect(refused).toBeInstanceOf(FileError)
expect(refused).toMatchObject({
	code: 'UNSUPPORTED_MEDIA_TYPE',
	message: 'text/plain is not accepted.',
})
```

- A type it detects must match `accept`.
- A type it does not detect, such as text, is taken as declared only when
  `accept` lists it as is, as `text/plain`, and the file is then served as a
  download.
- An SVG is served as a download too, so a browser never runs it.

`maxSize` limits each field before the body is read:

```ts
const large = new File(['x'.repeat(100_001)], 'big.txt', {
	type: 'text/plain',
})
await expect(
	uploader({ url: running.url }).upload(large, { for: 'Post.attachments' }),
).rejects.toMatchObject({
	code: 'PAYLOAD_TOO_LARGE',
	message: 'The file is over 100000 bytes.',
})
```

- A field that sets none takes `filesPlugin({ maxSize })`, 50 MB by default.
- It is the counterpart of `httpPlugin()`'s `bodyLimit` for JSON bodies, whose
  1 MB does not apply to `POST /files`.
- Check the size in the browser too: a client still sending a large body may
  see the connection close before the `413`.

## Inline values and variants

`inline` names values computed once at upload, and read with the row without a
second request: a blurred placeholder, a page count, an image's size. Each is
a function of `{ body, type, name }`, or `{ run, schema }` to type it in
GraphQL and OpenAPI. Here the size of a PNG comes from its header:

```ts
const signature = [0x89, 0x50, 0x4e, 0x47, 0x0d, 0x0a, 0x1a, 0x0a]

/** A PNG's width and height, from its header; `null` for other bytes. */
function pngSize(body: Uint8Array) {
	// `accept` lists image/png as is, so a body declared image/png whose
	// type is not detected comes in too, and is served as a download.
	const isPng =
		body.length >= 24 && signature.every((byte, i) => body[i] === byte)
	if (!isPng) return null
	const view = new DataView(body.buffer, body.byteOffset, body.byteLength)
	return { width: view.getUint32(16), height: view.getUint32(20) }
}
```

`variants` names other files made from the upload, such as a thumbnail. The
attachments above have a `preview` of their first 100 bytes:

- Each variant is a function of `{ body, type, name }`.
- It returns `{ body, type }`, and reads as `{ type, size, url }`.
- Variants are made in parallel at upload, and one that throws fails the
  upload.
- A field with `inline` or `variants` holds the file in memory during the
  upload; any other field streams it to the storage.

## Public and private files

A public file has a stable URL, which a CDN may cache. A private one, the
default, reads with a signed URL. Either way the URL is the storage's, not the
application's, so a file cannot read the application's cookies. The read and
access rules of the row decide who gets the URL.

A private file's URL stays the same for 15 minutes:

- Every read in one window of UTC time, :00 to :15, :15 to :30 and so on,
  returns it, and it works until the end of the next window.
- A URL is valid 15 to 30 minutes after the read that gave it.
- A row sent again by a live read keeps its URLs, so the client neither
  downloads its images again nor sees its values change.

## From server code

`files.upload(body, { for, name, as })` stores a file as `POST /files` does;
without `as`, it uploads as a visitor. `files.check()` compares the storage
with the database:

```ts
const as = { as: master }
const { id } = await files.upload(png, { for: 'Post.cover', name: 'a.png' })
const post = await Post.create({ data: { title: 'Hi', cover: id } }, as)
expect(post.cover?.inline.size).toEqual({ width: 1, height: 1 })
// The earlier tests' objects outlive their database, which each test
// resets: they have no row, and `delete: true` deletes them.
const { rows } = await files.check({ delete: true })
expect(rows).toEqual([])
// Now the storage and the database agree.
expect(await files.check()).toEqual({ objects: [], rows: [] })
```

- The plugin sweeps at start and every ten minutes, deleting the expired
  uploads and any file a crash left released.
- `files.check({ delete: true })` also deletes the objects that have no row.

## Storage

The example's `chooseStorage()` picks one by environment: S3 under
`NODE_ENV=production`, a directory when `FILES_DIR` is set, memory otherwise,
so neither the example's server nor its tests write to a real storage.

`s3()` takes a bucket on S3 or on any S3-compatible storage: DigitalOcean
Spaces, Cloudflare R2, MinIO, SeaweedFS:

```ts
if (process.env.NODE_ENV === 'production') {
	return s3({
		bucket: process.env.S3_BUCKET,
		region: process.env.S3_REGION,
		endpoint: process.env.S3_ENDPOINT,
		accessKeyId: process.env.S3_ACCESS_KEY_ID,
		secretAccessKey: process.env.S3_SECRET_ACCESS_KEY,
		// Spaces serves a public file only with a public-read ACL.
		publicAcl: true,
		// A CDN in front of the bucket; the storage's own URL without it.
		publicUrl: 'https://cdn.example.com',
	})
}
```

`diskFiles()` keeps the files in a directory, for a single server whose
directory is a persistent volume, as a staging server without S3:

```ts
if (process.env.FILES_DIR !== undefined) {
	return diskFiles({
		// A persistent volume: the files outlive a deploy.
		dir: process.env.FILES_DIR,
		// Signs the private files' URLs, the same on every start.
		secret: process.env.FILES_SECRET,
		// The address clients reach, behind a proxy; the server's otherwise.
		servedAt: process.env.PUBLIC_URL,
	})
}
```

`memoryFiles()` keeps them in memory, for tests and development:

```ts
return memoryFiles()
```

The application serves the files of `diskFiles()` and `memoryFiles()` at
`GET /files/<key>`, so a front end shows them as it would from S3: a public
file at a stable URL, a private one at a URL signed for 15 to 30 minutes.

## Details

- Each option of `s3()` and `diskFiles()` takes `undefined`, so the environment
  fills it directly; a missing one throws at start.
- A served file is answered with its type, `X-Content-Type-Options: nosniff`
  and `Content-Security-Policy: sandbox`, so an HTML or SVG file opened from
  the application's origin runs no script there.
- A key added to `inline` or `variants` later reads `null` for the files
  stored before it.

## Reference

### `file(options)`

| Option        | Type                                 | Default      | Effect                                                                       |
| ------------- | ------------------------------------ | ------------ | ---------------------------------------------------------------------------- |
| `optional`    | boolean                              | `false`      | The field may be `null`.                                                     |
| `list`        | boolean                              | `false`      | A list of files, `[]` when empty.                                            |
| `maxSize`     | number of bytes                      | the plugin's | The largest file the field takes, larger or smaller than the plugin's.       |
| `accept`      | MIME types or patterns               | any          | `['image/*', 'application/pdf']`; an undetected type must be listed as is.   |
| `public`      | boolean                              | `false`      | A stable URL; a private file's URL is signed, the same for 15 minutes.       |
| `inline`      | `{ [name]: run \| { run, schema } }` | none         | Values computed at upload, each JSON of 2 KB at most, read with the row.     |
| `variants`    | `{ [name]: run }`                    | none         | Other files made at upload, each `({ body, type, name }) => { body, type }`. |
| `description` | string                               | none         | The field's description in GraphQL and OpenAPI.                              |

A key added to `inline` or `variants` later reads `null` for the files
stored before it.

### What a file reads as

| Key        | Type                                      | Effect                                                           |
| ---------- | ----------------------------------------- | ---------------------------------------------------------------- |
| `id`       | string                                    | What a write takes.                                              |
| `name`     | string                                    | The name given at upload.                                        |
| `type`     | string                                    | The detected MIME type, or the declared one.                     |
| `size`     | number                                    | In bytes.                                                        |
| `url`      | string                                    | Stable for a public file, signed for 15 to 30 minutes otherwise. |
| `inline`   | object                                    | The `inline` values.                                             |
| `variants` | `{ [name]: { type, size, url } \| null }` | The variants.                                                    |

In GraphQL the field is typed, as `PostCover`; a write takes the `JSON`
scalar, an id or a list operation.

### `filesPlugin(options)`

| Option          | Type                                     | Default          | Effect                                              |
| --------------- | ---------------------------------------- | ---------------- | --------------------------------------------------- |
| `storage`       | `s3()`, `diskFiles()` or `memoryFiles()` | required         | Where the files go.                                 |
| `access.upload` | a rule                                   | a signed-in user | Who may upload; Master always may.                  |
| `maxSize`       | number of bytes                          | 50 MB            | The largest file of a field that sets no `maxSize`. |

It requires `httpPlugin()`, and mounts `POST /files`, and `GET /files/<key>`
for `diskFiles()` and `memoryFiles()`.

### `s3(options)`

| Option            | Effect                                                                 |
| ----------------- | ---------------------------------------------------------------------- |
| `bucket`          | The bucket's name.                                                     |
| `region`          | Its region, as `fra1` or `auto`.                                       |
| `endpoint`        | The storage's URL, as `https://fra1.digitaloceanspaces.com`.           |
| `accessKeyId`     | The key's id.                                                          |
| `secretAccessKey` | The key's secret.                                                      |
| `publicAcl`       | Sends `x-amz-acl: public-read` with a public file, which Spaces needs. |
| `publicUrl`       | The base of a public file's URL, a CDN; the storage's own otherwise.   |

The first five are required. Each option but `publicAcl` takes `undefined`,
so it can be read from the environment as it is. URLs are
path-style, `${endpoint}/${bucket}/${key}`; requests are signed with SigV4.

### `diskFiles(options)` and `memoryFiles(options)`

| Option     | Of            | Effect                                                                       |
| ---------- | ------------- | ---------------------------------------------------------------------------- |
| `dir`      | `diskFiles()` | The directory, made when missing. Required.                                  |
| `secret`   | `diskFiles()` | Signs the private URLs: 32 characters at least, the same on every start.     |
| `servedAt` | both          | The origin of the URLs, behind a proxy; the HTTP server's address otherwise. |

`memoryFiles()` draws its secret at random, so its private URLs end with
the process, as its files do.
`diskFiles()` is for one server: two servers do not share a directory.

### `GET /files/<key>`

| Status | Code        | When                                                    |
| ------ | ----------- | ------------------------------------------------------- |
| 200    |             | The file, cached a year if public, until expiry if not. |
| 403    | `FORBIDDEN` | A private file's signature is wrong or expired.         |
| 404    | `NOT_FOUND` | No file at this key.                                    |

### `POST /files`

| Query  | Effect                                |
| ------ | ------------------------------------- |
| `for`  | The field, as `Post.cover`. Required. |
| `name` | The file's name. Required.            |

The body is the file; `Content-Length` is required and `Content-Type` is
the declared type. The answer is `201` with `{ id }`.

| Status | Code                     | When                                                                    |
| ------ | ------------------------ | ----------------------------------------------------------------------- |
| 400    | `VALIDATION_FAILED`      | `Invalid upload.`: no field or an unknown one, or no name.              |
| 403    | `ACCESS_DENIED`          | A caller `access.upload` refuses.                                       |
| 411    | `LENGTH_REQUIRED`        | `Content-Length is required.`                                           |
| 413    | `PAYLOAD_TOO_LARGE`      | `The file is over 100000 bytes.`                                        |
| 415    | `UNSUPPORTED_MEDIA_TYPE` | `text/plain is not accepted.`, or `An undetected type is not accepted.` |

### `uploader(options)`

From `@ultimabase/files/client`, for a browser.

| Option    | Effect                                                                              |
| --------- | ----------------------------------------------------------------------------------- |
| `url`     | The server's address; uploads go to its `/files`.                                   |
| `headers` | The headers of each upload, such as a session's, or a function read at each upload. |

| Function                         | Returns             | Effect                                                                                          |
| -------------------------------- | ------------------- | ----------------------------------------------------------------------------------------------- |
| `upload(file, { for, signal })`  | `Promise<string>`   | Uploads a `File` for the field `for`, as `Post.cover`; resolves to its id.                      |
| `upload(files, { for, signal })` | `Promise<string[]>` | Uploads the files at once; resolves to their ids in order. The first failure aborts the others. |

A failed upload rejects with a `FileError`, whose `code`, `message` and
`details` are:

| Failure               | `code`       | `message`                              |
| --------------------- | ------------ | -------------------------------------- |
| refused by the server | the server's | the server's, as in the table above    |
| another answer        | `INTERNAL`   | `The upload failed.`                   |
| no server reached     | `NETWORK`    | `The upload did not reach the server.` |

- An upload aborted by `signal` rejects with the signal's reason.
- A file a failed list had already stored is never written in a row, so it
  leaves the storage within the hour.

### `files`

| Function                                | Returns             | Effect                                                                                       |
| --------------------------------------- | ------------------- | -------------------------------------------------------------------------------------------- |
| `files.upload(body, { for, name, as })` | `{ id }`            | Uploads a `Uint8Array` or a `Blob`, as a visitor without `as`.                               |
| `files.check({ delete })`               | `{ objects, rows }` | The objects without a row, and the rows without an object; `delete: true` deletes the first. |

### Errors in a write

A write's `VALIDATION_FAILED`, `Invalid data.`, names the field in its
issue's path:

- `<id> is not a file uploaded for Post.cover.`: an unknown id, another
  field's, another caller's, or one already attached.
- `The list holds <id> already.`: a `push` of a file the list holds.
- `A file expired or was attached elsewhere.`: between the check and the
  commit.

At start:

- `s3() needs bucket, region: undefined or empty.`
- `A file list is empty, never null: list or optional.`
- `A file field’s maxSize is a number of bytes.`, `filesPlugin’s maxSize is a
number of bytes.`
- `A file field’s accept lists MIME types or patterns: image/png, image/*.`
- `A file field’s inline size is a function.`, `A file field’s variant
preview is a function.`

At upload, an `inline` value that is not JSON of 2 KB at most, or not of its
schema, and a variant that throws, fail the upload with a server error.

### Limits

- One file per request: no multipart upload, and no upload inside a
  GraphQL or REST write.
- A pending upload expires after one hour; the sweep runs every ten
  minutes. Neither delay is an option.
- A [soft-deleted](/docs/next/soft-delete) row keeps its files.
