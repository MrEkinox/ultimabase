title: Password
description: Sign up and sign in with an email and a password, reset a forgotten one, and verify or change the email.
---

`@ultimabase/password` is a sign-in method for
[Authentication](/docs/next/auth): a user signs up and signs in with an
email and a password. `password()` goes in the user model's `use`:

```ts
import { defineUser, isAuthenticated, isSelf } from '@ultimabase/auth'
import { graphql } from '@ultimabase/graphql'
import { password } from '@ultimabase/password'
import { allow } from 'ultimabase'
import { Post } from './models.ts'

export const User = defineUser({
	name: 'User',
	use: [graphql(), password()],
	fields: (f) => ({
		name: f.string(),
		// Only the server makes an editor: no client writes this field.
		editor: f.boolean({ default: false }).with({ access: allow.readOnly }),
		posts: f.many(() => Post, { inverse: 'author' }),
	}),
}).with({
	// Signed-in users read each other's names; each user changes their own.
	access: { read: isAuthenticated, update: isSelf },
})
```

The full example, with its tests: [`examples/password-sign-in`](https://github.com/MrEkinox/ultimabase/tree/main/examples/password-sign-in).

`passwordPlugin()` goes after `authPlugin()`. `signUp` lists the user fields
a sign-up takes besides the email and the password; `sendEmail` sends the
emails; `breached` refuses a password that appears in a data breach:

```ts
plugins: [
	// Listens on PORT, or 3000.
	httpPlugin(),
	graphqlPlugin(),
	// Sessions, and the caller of each request.
	authPlugin(),
	// A user signs up with an email, a password and a name, and receives
	// the reset and verification emails sendEmail sends. A new password
	// in a known data breach is refused.
	passwordPlugin({ signUp: ['name'], sendEmail, breached: true }),
],
```

| To                                | Use                                                                    |
| --------------------------------- | ---------------------------------------------------------------------- |
| sign up and sign in               | [`signUp`, `signIn`](#sign-up-and-sign-in)                             |
| send the emails                   | [`sendEmail`](#send-the-emails)                                        |
| reset a forgotten password        | [`requestPasswordReset`, `resetPassword`](#reset-a-forgotten-password) |
| verify the email                  | [`verifyEmail`](#verify-the-email)                                     |
| change the password               | [`changePassword`](#change-the-password)                               |
| change the email                  | [`requestEmailChange`, `confirmEmailChange`](#change-the-email)        |
| do it from server code            | [`User.signUp` and the other commands](#from-server-code)              |
| ask for the password again        | [`User.checkPassword`](#check-the-password-again)                      |
| refuse weak or breached passwords | [`breached`](#new-passwords)                                           |
| limit failed sign-ins             | [the 11th is refused](#failed-sign-ins)                                |

## Sign up and sign in

A client signs up, then signs in, with the functions the plugin adds. Each
returns the session's `token`, its `expiresAt` and the `user`. The `$input` of
the sign-up is `{ email: 'ada@example.com', password: 'correct horse', name: 'Ada' }`:

```graphql
mutation ($input: SignUpInput!) {
	signUp(input: $input) {
		token
		expiresAt
		user {
			name
		}
	}
}
```

The `$input` of the sign-in is `{ email: 'ada@example.com', password: 'correct
horse' }`. This request selects only `user`:

```graphql
mutation ($input: SignInInput!) {
	signIn(input: $input) {
		user {
			name
		}
	}
}
```

```json
{ "data": { "signIn": { "user": { "name": "Ada" } } } }
```

[Authentication](/docs/next/auth) shows how the token and the cookie carry
the session.

- Passwords are hashed with Argon2id.
- The email is stored trimmed and lowercased, so `Ada@Example.com ` signs in
  as `ada@example.com`.
- The user model's `email` field holds it: the user and Master read it,
  other callers never do, and only Master writes it.

## Send the emails

`sendEmail` receives each email to send: its `kind`, the address `to` and the
`userId`. The application writes the text and a link to its own page, which
sends the token back. The tests keep each email in a list, `outbox`:

```ts
const pages = {
	reset: 'reset-password',
	verify: 'verify-email',
	emailChange: 'confirm-email',
}

export async function sendEmail(email: Email): Promise<void> {
	if (email.kind === 'emailChanged') {
		// To the old address, which may not have asked for the change.
		const text = `Your email is now ${email.newEmail}. Not you? Contact us.`
		outbox.push({ ...email, text })
		return
	}
	if (email.kind === 'passwordChanged') {
		const text = 'Your password was changed. Not you? Reset it.'
		outbox.push({ ...email, text })
		return
	}
	// The link opens the application's page, which sends the token to
	// resetPassword, verifyEmail or confirmEmailChange.
	const link = `https://example.com/${pages[email.kind]}?token=${email.token}`
	// An application sends the text to `email.to` with its email provider.
	outbox.push({ ...email, text: `Open ${link}` })
}
```

- A `'reset'`, `'verify'` or `'emailChange'` email has a `token`.
- An `'emailChanged'` one, sent to the old address, has the `newEmail`.
- A `'passwordChanged'` one, sent once the password changed, has neither.
- The emails go out after the function answers: a slow provider never slows a
  sign-up, and a request cannot tell from the delay whether an email has an
  account.
- Without `sendEmail`, the six email functions do not exist, and the
  [commands](#from-server-code) that send an email throw.

`emailed` reads the token of the latest email of a kind from `outbox`:

```ts
/** The token of the latest email of `kind`, once `sendEmail` has it. */
export async function emailed(
	kind: 'reset' | 'verify' | 'emailChange',
): Promise<string> {
	for (let attempt = 0; attempt < 100; attempt += 1) {
		const found = outbox.findLast((email) => email.kind === kind)
		if (found !== undefined && 'token' in found) return found.token
		// The emails go out after the function answers.
		await new Promise((resolve) => setTimeout(resolve, 10))
	}
	throw new Error(`No ${kind} email was sent.`)
}
```

## Reset a forgotten password

`requestPasswordReset` emails a reset link, valid one hour, and answers
`true` whether or not the email has an account:

```graphql
mutation ($input: RequestPasswordResetInput!) {
	requestPasswordReset(input: $input)
}
```

```json
{ "data": { "requestPasswordReset": true } }
```

`resetPassword` takes the token the email carries, here `$input.token`, and the
new password. It ends every session of the user, and marks the email verified,
since the user received the email:

```graphql
mutation ($input: ResetPasswordInput!) {
	resetPassword(input: $input)
}
```

```json
{ "data": { "resetPassword": true } }
```

The new password then signs in. A link works once: sent again, the same request is answered with
`INVALID_CREDENTIALS` and `This link is invalid or has expired.`

## Verify the email

The `signUp` function sends a verification link, valid 24 hours. The
`emailVerified` field, which the plugin adds to the user model, is `false`
until `verifyEmail` receives its token. `sendVerificationEmail` sends the
link again to the signed-in user.

`verifyEmail` takes the token of the email and needs no session. A `viewer`
request with the session the sign-up opened reads `emailVerified`: `false`
before, `true` after:

```graphql
mutation ($input: VerifyEmailInput!) {
	verifyEmail(input: $input)
}
```

```json
{ "data": { "verifyEmail": true } }
```

```graphql
query {
	viewer {
		emailVerified
	}
}
```

```json
{ "data": { "viewer": { "emailVerified": true } } }
```

Nothing requires a verified email: a rule that needs one reads
`emailVerified` on the user's row. [Closing the account](/docs/next/auth#from-server-code)
deletes the password and the links sent, and sets `emailVerified` back to
`false`.

## Change the password

`changePassword` takes the current password and the new one. It ends every
session of the user and opens a new one, so a stolen session stops working.
The request carries the token of the signed-in user:

```graphql
mutation ($input: ChangePasswordInput!) {
	changePassword(input: $input) {
		token
		user {
			passwordSetAt
		}
	}
}
```

The answer holds the new session's `token` and `user.passwordSetAt`, now. The
old password, `correct horse`, stops working, and the account, `ada@example.com`,
is told:

```ts
// The account is told.
await vi.waitFor(() => {
	expect(outbox.at(-1)).toMatchObject({
		kind: 'passwordChanged',
		to: 'ada@example.com',
	})
})
```

From server code, `User.setPassword({ id, password }, { as })` replaces it,
as Master or as the user, and ends every session too. It asks no current
password: check the user's intent first.

The user model's `passwordSetAt` field holds when the password was last set.
The user and Master read it, as an account page that shows "password changed
on …".

- `signUp`, `changePassword`, `resetPassword` and `User.setPassword` set it.
- Closing the account sets it to `null`, and a rehash on sign-in keeps it.
- With `sendEmail`, each change but the sign-up's also sends a
  `'passwordChanged'` email to the account, once it is saved.
- A Master write of `passwordSetAt` itself, as an import from Parse, sends
  none.

## Change the email

`requestEmailChange` takes the new email and the current password, so a
stolen session cannot take the account. It emails a link, valid one hour, to the new address. `confirmEmailChange`
takes its token. The first request carries the token of the signed-in user;
the second, the token of the email sent to the new address:

```graphql
mutation ($input: RequestEmailChangeInput!) {
	requestEmailChange(input: $input)
}
```

```json
{ "data": { "requestEmailChange": true } }
```

```graphql
mutation ($input: ConfirmEmailChangeInput!) {
	confirmEmailChange(input: $input)
}
```

```json
{ "data": { "confirmEmailChange": true } }
```

The email changes and is verified, sessions stay open, and the old address
is told. Here Ada, `ada@example.com` with the password `correct horse`, asked
for `ada@new.example`:

```ts
// The email is verified, and the old address is told.
expect(
	await User.signIn({ email: 'ada@new.example', password: 'correct horse' }),
).toMatchObject({ user: { email: 'ada@new.example', emailVerified: true } })
await vi.waitFor(() => {
	expect(outbox.at(-1)).toMatchObject({
		kind: 'emailChanged',
		to: 'ada@example.com',
	})
})
```

An application without emails writes the field as Master. The tests write `as`
for `{ as: master }`, and `ada` is the row `User.signUp` returned for
`ada@example.com`, password `correct horse`. The account follows it, `emailVerified` goes back to `false` unless the write sets it,
and the links already sent stop working:

```ts
// As Master, without any email: the account follows the field.
const updated = await User.update(
	{ where: { id: ada.id }, data: { email: 'Ada@New.Example' } },
	as,
)
expect(updated).toMatchObject({
	email: 'ada@new.example',
	emailVerified: false,
})
await expect(
	User.signIn({ email: 'ada@new.example', password: 'correct horse' }),
).resolves.toMatchObject({ user: { name: 'Ada' } })
```

- The field never goes back to `null` while the user has a password:
  [closing the account](/docs/next/auth#from-server-code) clears it.
- A user stored before the field reads `null` until a Master update writes
  its account's email.

## From server code

Each email function has a command on the user model, for a test or an
admin function: `User.requestPasswordReset`, `User.resetPassword`,
`User.verifyEmail`, `User.sendVerificationEmail`, `User.requestEmailChange`
and `User.confirmEmailChange`. A command runs the function's code, but
waits for the email: it resolves once `sendEmail` has, and rejects with its
error.

```ts
// Commands that name a user run as Master or as that user.
await User.sendVerificationEmail({ id: ada.id }, as)
await User.verifyEmail({ token: await emailed('verify') })
// The email has left once the command resolves.
await User.requestPasswordReset({ email: 'ada@example.com' })
const token = await emailed('reset')
await User.resetPassword({ token, password: 'new secret!' })
await expect(
	User.signIn({ email: 'ada@example.com', password: 'new secret!' }),
).resolves.toMatchObject({ user: { name: 'Ada', emailVerified: true } })
```

- The commands that take a token, and `requestPasswordReset`, take any caller,
  as their functions are public.
- `sendVerificationEmail({ id })` and `requestEmailChange({ id, newEmail })`
  run as Master or as that user.
- `requestEmailChange` asks no current password, so check the user's intent
  first, with `User.checkPassword`.
- A command has no client: no address limit applies, but the account's three
  emails per hour do, `requestPasswordReset` included.

## Check the password again

Before a sensitive action, such as closing the account, a function asks for
the password again, so a stolen session is not enough.
`User.checkPassword({ id, password }, { as, client })` throws
`Wrong password.` for a wrong one, and opens no session:

```ts
// As the user; a function's run passes its own caller and client.
const self = { as: asUser(ada) }
await User.checkPassword({ id: ada.id, password: 'correct horse' }, self)
await expect(
	User.checkPassword({ id: ada.id, password: 'wrong password' }, self),
).rejects.toMatchObject({
	code: 'INVALID_CREDENTIALS',
	message: 'Wrong password.',
})
```

It runs as Master or as the user, and is always counted: with the `client`,
as `changePassword`; without it, the 11th failure on the user within 15
minutes is refused.

## New passwords

A new password, at sign-up, on a change or a reset, has 8 to 256 characters
and is not the account's email, nor the part before its `@`. Here `signUp` holds
the new user's email and name, and `as` is still `{ as: master }`:

```ts
const signUp = { email: 'ada@example.com', data: { name: 'Ada' } }
await expect(
	User.signUp({ ...signUp, password: 'Ada@Example.com' }, as),
).rejects.toMatchObject({
	code: 'VALIDATION_FAILED',
	message: 'password: A password cannot be the email.',
})
```

Each refusal is a `VALIDATION_FAILED` with one issue, whose `code` a client
tests: `PASSWORD_LENGTH`, `PASSWORD_IS_EMAIL` or `PASSWORD_BREACHED`, the union
[`IssueCodeOf<typeof app>`](/docs/next/errors) gives. Its path is the field's:
`['password']` for `User.signUp`, and `['input', 'newPassword']` for the
`changePassword` function.

`breached: true`, as in the example's `passwordPlugin` above, also refuses a
password that appears in a known data breach: `password123` and the other
common ones are among them. See the [details](#details) for how it asks.

## Failed sign-ins

Within 15 minutes, the 11th failed sign-in from one address on one account
is refused, even with the right password, until enough failures are 15
minutes old. `details.retryAfter` gives the seconds to wait; over REST it is
also the `Retry-After` header.

Ada fails 10 times: each answer is `INVALID_CREDENTIALS`. The 11th attempt, even
with the right password, is refused before the password is checked, with
`TOO_MANY_ATTEMPTS` and `details.retryAfter`.

A successful sign-in clears its address's failures. A wrong email and a wrong
password give the same answer, in the same time.

## Details

### Breached passwords

- The plugin asks
  [Have I Been Pwned](https://haveibeenpwned.com/API/v3#PwnedPasswords) with
  the first 5 characters of the password's SHA-1 only, and the password never
  leaves the server.
- It is off by default, so the plugin calls no third party unless the
  application chooses to.
- In production, a start without the option warns `Breached passwords are
accepted: passwordPlugin({ breached: true }) refuses them.`, and
  `breached: false` silences it.
- When the service does not answer within 2 seconds, the password is accepted
  and the logger warns: an outage never closes sign-up.
- Under `NODE_ENV=test`, as Vitest and Jest set it, nothing is asked.
- A refused reset leaves its link valid for another try.

### Length

The minimum stays 8 characters, as in OWASP ASVS 5. NIST SP 800-63B rev. 4
asks for 15 when the password is the only factor: an application that wants
more checks the length in its own form.

## Reference

### `passwordPlugin(options)`

| Option      | Type                              | Default | Effect                                                                              |
| ----------- | --------------------------------- | ------- | ----------------------------------------------------------------------------------- |
| `signUp`    | user field names, or `false`      | `[]`    | The fields `signUp` takes besides `email` and `password`; `false` removes `signUp`. |
| `sendEmail` | `(email: Email) => Promise<void>` | none    | Sends the emails; without it, the email functions do not exist.                     |
| `breached`  | `boolean`                         | `false` | Refuses a new password that appears in a known data breach.                         |

It requires `authPlugin()`. `password()` in the user model's `use` adds the
fields `email` (unique, `null` without a password), `emailVerified`
(`false` by default) and `passwordSetAt` (`null` without a password), and the
commands below. A user model with its own `email` or `passwordSetAt` field
stops startup: `User.email: password adds a field User already has.`

### Functions

| Function                | Input                                    | Returns    | Needs                         |
| ----------------------- | ---------------------------------------- | ---------- | ----------------------------- |
| `signUp`                | `email`, `password`, the `signUp` fields | `SignedIn` |                               |
| `signIn`                | `email`, `password`                      | `SignedIn` |                               |
| `changePassword`        | `currentPassword`, `newPassword`         | `SignedIn` | a signed-in user              |
| `requestPasswordReset`  | `email`                                  | `true`     | `sendEmail`                   |
| `resetPassword`         | `token`, `password`                      | `true`     | `sendEmail`                   |
| `verifyEmail`           | `token`                                  | `true`     | `sendEmail`                   |
| `sendVerificationEmail` | none                                     | `true`     | `sendEmail`, a signed-in user |
| `requestEmailChange`    | `newEmail`, `currentPassword`            | `true`     | `sendEmail`, a signed-in user |
| `confirmEmailChange`    | `token`                                  | `true`     | `sendEmail`                   |

Each is public. In GraphQL, a function's input is one `input` argument of
type `SignUpInput`, `SignInInput`… `SignedIn` is `{ token, expiresAt, user }`;
over HTTP, `signUp`, `signIn` and `changePassword` also set the cookie.

### Commands

| Command                                                | Effect                                                                          |
| ------------------------------------------------------ | ------------------------------------------------------------------------------- |
| `User.signUp({ email, password, data }, { as })`       | Creates the user; opens no session and sends no email. Master writes any field. |
| `User.signIn({ email, password })`                     | Opens a session; `SignedIn`. Not limited without a `client`.                    |
| `User.setPassword({ id, password }, { as })`           | Replaces the password and ends every session; Master or the user.               |
| `User.checkPassword({ id, password }, { as, client })` | Checks the current password; no session. Master or the user, always counted.    |
| `User.requestPasswordReset({ email })`                 | Sends the reset link; nothing to an email without an account.                   |
| `User.resetPassword({ token, password })`              | Sets the password and verifies the email, as `resetPassword`.                   |
| `User.verifyEmail({ token })`                          | Verifies the email.                                                             |
| `User.sendVerificationEmail({ id }, { as })`           | Sends the verification link; Master or the user.                                |
| `User.requestEmailChange({ id, newEmail }, { as })`    | Sends the email-change link, without the current password; Master or the user.  |
| `User.confirmEmailChange({ token })`                   | Writes the new email, verified.                                                 |

### Values

| Value    | Rule                                                                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| email    | trimmed, lowercased, NFC; at most 254 characters, with one `@`                                                                                   |
| password | 8 to 256 characters after NFKC normalization; not the email nor its local part; with `breached`, in no known breach                              |
| token    | single use; reset and email change: one hour, verification: 24 hours; a new password ends the reset and email-change ones; stored as its SHA-256 |

### Limits

| What                    | Limit                                                                       |
| ----------------------- | --------------------------------------------------------------------------- |
| failed sign-ins         | 10 per account and address, 100 per account, 100 per address, in 15 minutes |
| `signUp`                | 10 per address and hour                                                     |
| `requestPasswordReset`  | 10 per address and hour                                                     |
| `sendVerificationEmail` | 10 per address and hour                                                     |
| emails                  | 3 per account and hour, of any kind with a link                             |
| hashing                 | one per CPU at once, 64 waiting, then `The server is busy: try again.`      |

An IPv6 address counts as its /64 network. `changePassword` and
`User.checkPassword` count the failed current passwords of each user the
same way, together; `User.checkPassword` without a `client` refuses the 11th
on the user, from anywhere.

### Errors

| Code                  | Message                                                                                                                                                                                                                                                  |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `INVALID_CREDENTIALS` | `Wrong email or password.`                                                                                                                                                                                                                               |
| `INVALID_CREDENTIALS` | `Wrong password.`, from `changePassword`, `requestEmailChange` and `User.checkPassword`                                                                                                                                                                  |
| `INVALID_CREDENTIALS` | `This link is invalid or has expired.`                                                                                                                                                                                                                   |
| `UNAUTHENTICATED`     | `This function needs a signed-in user.`, from `changePassword`, `sendVerificationEmail` and `requestEmailChange`                                                                                                                                         |
| `TOO_MANY_ATTEMPTS`   | `Too many attempts: try again later.`, with `details.retryAfter` in seconds                                                                                                                                                                              |
| `VALIDATION_FAILED`   | `password: A password has 8 to 256 characters.`, `password: A password cannot be the email.`, `password: This password appears in a data breach: choose another.`, `Sign-up takes the listed fields only.`, `email: A password account keeps its email.` |
| `UNIQUE_VIOLATION`    | A sign-up or an email change to an email that has an account, both with `details: { model, fields: ['email'] }`: `This email has an account.` from `requestEmailChange`                                                                                  |
| `ACCESS_DENIED`       | `Sign-up is closed.` for `User.signUp` without Master, when `signUp: false`; `User.setPassword runs as Master or as the user.`, and the same for `User.checkPassword`, `User.sendVerificationEmail` and `User.requestEmailChange`                        |

At start, `signUp` naming a field the user model lacks throws
`passwordPlugin({ signUp }): User.nickname is not a field sign-up may take.`,
and leaving out a required field throws `passwordPlugin({ signUp }): User
needs name to be created; list them.`

A sign-up with a taken email answers `UNIQUE_VIOLATION`, which tells that
the email has an account. A hundred failures on one account lock it for
everyone for 15 minutes.
