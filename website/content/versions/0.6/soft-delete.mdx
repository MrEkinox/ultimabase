---
title: Soft delete
description: Keep deleted rows in a trash, dated, and bring them back.
---

`@ultimabase/soft-delete` keeps the rows a delete removes: a deleted row
gets a `deletedAt` date and leaves every ordinary read, and the model's
trash still finds it. `softDelete()` goes in a model's `use`:

```npm
npm install @ultimabase/soft-delete
```

```ts
import { graphql } from '@ultimabase/graphql'
import { softDelete } from '@ultimabase/soft-delete'
import { allow, defineModel } from 'ultimabase'

export const Post = defineModel({
	name: 'Post',
	// Adds `deletedAt`, `Post.trash` and `Post.restore`.
	use: [graphql(), softDelete()],
	fields: (f) => ({ title: f.string() }),
	// A title is unique among the kept posts: a deleted one gives it back.
	indexes: [{ fields: ['title'], unique: true, where: { deletedAt: null } }],
	// Open to every client, to keep the example on soft delete.
}).with({ access: allow.public })
```

The full example, with its tests: [`examples/soft-delete`](https://github.com/MrEkinox/ultimabase/tree/main/examples/soft-delete).

| To                                      | Use                                               |
| --------------------------------------- | ------------------------------------------------- |
| turn on the trash                       | [`softDeletePlugin()`](#set-it-up)                |
| delete a row and keep it                | [`deletePost`, or `delete`](#delete-a-row)        |
| let clients read the trash and restore  | [a function](#over-graphql)                       |
| read the trash, restore, from your code | [`Post.trash`, `Post.restore`](#from-server-code) |
| reuse the value of a deleted row        | [an index with `where`](#unique-values)           |
| know which rules and hooks run          | [Rules](#rules)                                   |

## Set it up

`softDeletePlugin()` goes in the application's plugins:

```ts
// Listens on PORT, or 3000.
plugins: [httpPlugin(), graphqlPlugin(), softDeletePlugin()],
```

## Delete a row

The server holds two posts, `Kept` and `Draft`. A client deletes `Draft` as
usual, with `deletePost`; `$id` is its id:

```graphql
mutation ($id: ID!) {
	deletePost(where: { id: $id }) {
		id
	}
}
```

```json
{ "data": { "deletePost": { "id": "…" } } }
```

`Draft` leaves `posts`, and `Kept` stays:

```graphql
query {
	posts {
		edges {
			node {
				title
			}
		}
	}
}
```

```json
{ "data": { "posts": { "edges": [{ "node": { "title": "Kept" } }] } } }
```

## Over GraphQL

No transport exposes the trash or `restore` by themselves: a function gives
them to clients, with the rules it chooses. Each command runs as the caller,
so the model's rules apply:

```ts
export const trash = defineFunction({
	name: 'trash',
	query: true,
	output: [Post],
	run: ({ caller }) => Post.trash.findMany({}, { as: caller }),
}).with({ access: allow.public })

export const restorePost = defineFunction({
	name: 'restorePost',
	// `z.uuid()` is an `ID` in GraphQL, as the post's own `id`.
	input: z.object({ id: z.uuid() }),
	output: Post,
	run: ({ caller, input }) =>
		Post.restore({ where: { id: input.id } }, { as: caller }),
}).with({ access: allow.public })
```

The trash has `Draft`, the deleted post:

```graphql
query {
	trash {
		title
	}
}
```

```json
{ "data": { "trash": [{ "title": "Draft" }] } }
```

`restorePost` brings `Draft` back, by its id, with `deletedAt` set to `null`:

```graphql
mutation ($id: ID!) {
	restorePost(id: $id) {
		title
		deletedAt
	}
}
```

```json
{ "data": { "restorePost": { "title": "Draft", "deletedAt": null } } }
```

Restoring a post that is not deleted fails with `NOT_FOUND`.

## From server code

The model gets two commands. The tests below write `as` for `{ as: master }`.
`Post.trash` reads the deleted rows with `findMany`, `findFirst`,
`findUnique` and `count`:

```ts
const post = await Post.create({ data: { title: 'Draft' } }, as)
const removed = await Post.delete({ where: { id: post.id } }, as)
expect(removed.deletedAt).toBeInstanceOf(Date)
// Gone for every read, Master's included; the trash still has it.
expect(await Post.findUnique({ where: { id: post.id } }, as)).toBeNull()
expect(await Post.trash.count({}, as)).toBe(1)
```

```ts
const found = await Post.trash.findUnique({ where: { id: post.id } }, as)
expect(found?.title).toBe('Draft')
```

A deleted row is gone for every other read, Master's included. `deleteMany`
keeps its rows too:

```ts
await Post.create({ data: { title: 'Old' } }, as)
expect(await Post.deleteMany({}, as)).toEqual({ count: 1 })
expect(await Post.trash.count({}, as)).toBe(2)
```

`Post.restore` brings one back and returns it:

```ts
const restored = await Post.restore({ where: { id: post.id } }, as)
expect(restored.deletedAt).toBeNull()
```

## Unique values

A deleted row keeps its values, unique ones included, so a new row cannot
take them. `Tag` has a plain unique `name`:

```ts
export const Tag = defineModel({
	name: 'Tag',
	use: [softDelete()],
	// A plain unique field: a deleted tag keeps its name.
	fields: (f) => ({ name: f.string({ unique: true }) }),
}).with({ access: allow.public })
```

Deleting the tag `news` does not free its name:

```ts
const tag = await Tag.create({ data: { name: 'news' } }, as)
await Tag.delete({ where: { id: tag.id } }, as)
await expect(Tag.create({ data: { name: 'news' } }, as)).rejects.toMatchObject({
	code: 'UNIQUE_VIOLATION',
	details: { model: 'Tag', fields: ['name'] },
})
```

An index whose `where` keeps only the rows not deleted, as `Post` has on its
title (`where: { deletedAt: null }`), frees the value of a deleted row.
Restoring that row is then a `UNIQUE_VIOLATION`:

```ts
const post = await Post.create({ data: { title: 'Draft' } }, as)
await Post.delete({ where: { id: post.id } }, as)
await Post.create({ data: { title: 'Draft' } }, as)
// The deleted post comes back only once its title is free again.
await expect(
	Post.restore({ where: { id: post.id } }, as),
).rejects.toMatchObject({ code: 'UNIQUE_VIOLATION' })
```

## Rules

- A delete still needs the model's `delete` rule.
- `beforeDelete` and `afterDelete` [hooks](/docs/next/hooks) run as for any
  delete.
- `trash` reads under the `read` rule, and `restore` writes under the
  `update` rule.

Only Master writes `deletedAt`: a client deletes through the `delete` rule and
never dates a row itself. The request is refused with `ACCESS_DENIED`:

```graphql
mutation {
	createPost(data: { title: "Old", deletedAt: "2026-01-01T00:00:00Z" }) {
		id
	}
}
```

```json
{
	"errors": [
		{
			"message": "Post create refused.",
			"locations": [{ "line": 2, "column": 2 }],
			"path": ["createPost"],
			"extensions": {
				"code": "ACCESS_DENIED",
				"details": {
					"model": "Post",
					"operation": "create",
					"field": "deletedAt"
				}
			}
		}
	],
	"data": null
}
```

## Details

- A deleted row's date is its `deletedAt`: `trash { title deletedAt }` reads it,
  and `Post.delete` returns it as a `Date`.
- The date is an update, written as Master. A delete also runs the model's
  `beforeUpdate`, `afterUpdate` and `afterUpdateCommit` hooks, and their
  `caller` is Master.
- A hook tells it from an edit by its `data.deletedAt`: a date for a delete,
  `null` for a `restore`.

## Reference

### `softDelete()` and `softDeletePlugin()`

Neither takes an option. `softDeletePlugin()` must be in plugins when a
model uses `softDelete()`. `softDelete()` adds:

| What    | Name                                                      | Effect                                                                     |
| ------- | --------------------------------------------------------- | -------------------------------------------------------------------------- |
| field   | `deletedAt`                                               | An optional `dateTime`: the delete's date, `null` for a kept row.          |
| command | `Post.trash.findMany`, `findFirst`, `findUnique`, `count` | The deleted rows, under the `read` rule.                                   |
| command | `Post.restore({ where }, { as })`                         | Sets `deletedAt` back to `null`, under the `update` rule; returns the row. |

### What a delete does

| Case                    | Result                                                                             |
| ----------------------- | ---------------------------------------------------------------------------------- |
| `delete`, `deleteMany`  | Dates the rows and returns them, as a delete does; no row is removed.              |
| the row's relations     | Stay: a soft-deleted row cascades nothing, and keeps its related rows.             |
| the row's unique values | Stay taken, unless an index's `where` is `{ deletedAt: null }`: see Unique values. |
| a read, a count         | Leaves the deleted rows out, for every caller.                                     |
| a relation to the row   | A `one` to it reads `null`, for every caller.                                      |

### Errors

| Code            | When                                                                                     |
| --------------- | ---------------------------------------------------------------------------------------- |
| `NOT_FOUND`     | `restore` of a row that is not deleted.                                                  |
| `ACCESS_DENIED` | A caller other than Master writes `deletedAt`; a `delete` or `restore` the rules refuse. |

### Limits

- The plugin has no command that removes a deleted row for good.
