A model is a table: `defineModel` names it and lists its fields. Its rows are
typed from them, in your code and in each transport.

```ts title="src/category.ts"
import { graphql } from '@ultimabase/graphql'
import { allow, defineModel } from 'ultimabase'

export const Category = defineModel({
	name: 'Category',
	use: [graphql()],
	fields: (f) => ({
		name: f.string({ unique: true }),
		position: f.number({ integer: true, default: 0 }),
	}),
}).with({ access: allow.public })
```

The full example, with its tests: [`examples/models-and-queries`](https://github.com/MrEkinox/ultimabase/tree/main/examples/models-and-queries).

The examples write their schemas with Zod, a package of its own:

```npm
npm install zod
```

Every row also has an `id` (a UUID v7 string), a `createdAt` and an
`updatedAt` (both `Date`), which the kernel writes:

```ts title="src/models.test.ts"
const books = await Category.create({ data: { name: 'Books' } }, { as: master })
expect(books).toMatchObject({ name: 'Books', position: 0 })
// The kernel writes the id (a UUID v7), createdAt and updatedAt.
expect(books.id).toMatch(/^[\da-f]{8}-[\da-f]{4}-7/u)
expect(books.createdAt).toBeInstanceOf(Date)
expect(books.updatedAt).toBeInstanceOf(Date)
```

## Field types

Each builder of `f` is a type: the [reference](#field-types-1) lists them
all. A price, exact, and a cost the server alone reads:

```ts title="src/models.ts"
// Exact: read and written as a string at its scale, '12.50'.
price: f.decimal({ precision: 10, scale: 2 }),
// Read by the server only.
cost: f
	.decimal({ precision: 10, scale: 2, optional: true })
	.with({ access: { read: allow.private } }),
```

- `f.decimal({ precision, scale })` is exact: read and written as a string at
  its scale, `'12.50'`.
- A field is required unless `optional: true`.

Days, instants, enums and lists:

```ts title="src/models.ts"
// A calendar day, '2026-07-31'; a dateTime is a Date.
releasedOn: f.date({ optional: true }),
restockedAt: f.dateTime({ optional: true }),
```

```ts title="src/models.ts"
status: f.enumOf(Status, { default: 'draft' }),
// Lists are [] when empty.
sizes: f.enumOf(['S', 'M', 'L'], { list: true }),
keywords: f.string({ list: true }),
```

- `f.date()` is a calendar day, `'2026-07-31'`; `f.dateTime()` is a `Date`.
- `f.enumOf(Status)` takes an array, or a [`defineEnum`](#shared-enums).
- `list: true` gives a list, `[]` when empty.

JSON, typed and validated by a schema:

```ts title="src/models.ts"
// A schema types the JSON and validates it.
specs: f.json({
	optional: true,
	validate: z.object({
		color: z.string(),
		materials: z.array(z.string()),
		// Added later: optional, as the rows stored before lack it.
		finish: z.string().optional(),
	}),
}),
```

## Defaults and optional fields

A field a write may leave out has a `default`, is `optional`, or is a list. A
function computes the default:

```ts title="src/models.ts"
// A function computes the default when the write leaves it out.
reference: f.string({ unique: true, default: () => randomUUID() }),
stock: f.number({ integer: true, default: 0 }),
weight: f.number({ optional: true }),
available: f.boolean({ default: true }),
```

- An optional field reads `null` when it is left out.
- A function that returns `undefined` gives no default. A field whose
  default is `() => undefined` stays required, but a create may leave it out
  for a [hook](/docs/next/hooks#number-rows-in-order) to fill.
- A list is never optional nor unique.

## Write and read the fields

Written from server code, the values come back typed and normalized: the
decimal at its scale, the defaults filled, the lists `[]` when empty, an
optional field `null`. A virtual field without `input` is returned without
`select`:

```ts title="src/models.test.ts"
const lamp = await Product.create(
	{ data: { name: 'Desk lamp', sku: 'LMP-001', price: '39.9' } },
	{ as: master },
)
// The decimal at its scale, an optional field `null`, a list `[]`.
expect(lamp).toMatchObject({ price: '39.90', summary: null, sizes: [] })
// A virtual field is returned without `select`.
expect(lamp.label).toBe('Desk lamp (LMP-001)')
// The defaults are filled.
expect(lamp).toMatchObject({ stock: 0, available: true, status: 'draft' })
```

A number takes `set`, `increment`, `decrement`, `multiply` or `divide`. A list
takes `set`, `push`, `pushUnique` or `remove`, with one element or a list of
them. A plain value sets the field. A lamp whose keywords are `light` and
`office`:

```ts title="src/models.test.ts"
const updated = await Product.update(
	{
		where: { sku: 'LMP-001' },
		data: { stock: { increment: 5 }, keywords: { push: 'desk' } },
	},
	{ as: master },
)
expect(updated.stock).toBe(5)
expect(updated.keywords).toEqual(['light', 'office', 'desk'])
```

Over GraphQL, the same fields:

- The enum's values are GraphQL enum values.
- The JSON field with a schema is an object type.
- The decimal is a string.
- A virtual field with an `input` takes it as arguments:
  `priceIn(currency: USD)`.

```graphql title="Request"
mutation {
	createProduct(
		data: {
			name: "Desk lamp"
			sku: "LMP-001"
			price: "39.90"
			status: published
			releasedOn: "2026-03-01"
			sizes: [S, M]
			specs: { color: "black", materials: ["steel"] }
		}
	) {
		price
		status
		specs {
			color
			materials
		}
		label
		priceIn(currency: USD) {
			amount
			currency
		}
	}
}
```

```json title="Response"
{
	"data": {
		"createProduct": {
			"price": "39.90",
			"status": "published",
			"specs": { "color": "black", "materials": ["steel"] },
			"label": "Desk lamp (LMP-001)",
			"priceIn": { "amount": "43.89", "currency": "USD" }
		}
	}
}
```

## Validation

Each field checks its type; `validate` adds a rule. It takes a Standard Schema
(Zod, Valibot, ArkType…), or a function that returns the value to store and
throws to refuse it:

`PublicError` comes from `ultimabase`.

```ts title="src/models.ts"
// Required unless `optional: true`; `search: true` makes it searchable.
name: f.string({
	search: true,
	// A function returns the value to store or throws to refuse it; a
	// PublicError's code reaches the client with its message.
	validate: (name) => {
		if (name.trim() === '') {
			throw new PublicError('NAME_BLANK', 'A product needs a name.')
		}
		return name
	},
}),
```

```ts title="src/models.ts"
sku: f.string({
	unique: true,
	validate: z.string().regex(/^[A-Z]{3}-\d{3}$/u),
	description: 'Three capitals, a dash and three digits.',
}),
```

A refused write writes nothing. This one holds a `sku` the schema refuses, and
the message of Zod reaches the client. The tests write `plain` for
`{ name: 'Lamp', sku: 'LMP-001', price: '10.00' }`:

```ts title="src/models.test.ts"
await expect(
	Product.create({ data: { ...plain, sku: 'lamp' } }, { as: master }),
).rejects.toMatchObject({
	details: {
		issues: [
			{
				path: ['sku'],
				message: 'Invalid string: must match pattern /^[A-Z]{3}-\\d{3}$/u',
			},
		],
	},
})
```

A function refuses by throwing. Its error's message becomes the issue's
message, and a `PublicError`'s code the issue's `code`, for the client to test:

```ts title="src/models.test.ts"
await expect(
	Product.create({ data: { ...plain, name: ' ' } }, { as: master }),
).rejects.toMatchObject({
	details: {
		issues: [{ path: ['name'], code: 'NAME_BLANK' }],
	},
})
```

- A refused write returns `VALIDATION_FAILED`, with one issue per refused field.
- A schema's issue keeps its code when it is in capitals, as `NAME_LENGTH`. A
  library's, as Zod's `too_small`, is left out.
- A second row with a unique value returns `UNIQUE_VIOLATION`; here `plain`
  is created twice:

```ts title="src/models.test.ts"
await Product.create({ data: plain }, { as: master })
await expect(
	Product.create({ data: { ...plain, price: '12.00' } }, { as: master }),
).rejects.toMatchObject({
	code: 'UNIQUE_VIOLATION',
	message: 'Unique constraint failed on Product (sku).',
	details: { model: 'Product', fields: ['sku'] },
})
```

With `unique: 'insensitive'`, a string clashes with another case of itself,
`Alice` with `alice`, while each row keeps the case it was given. An index
does the same with `mode: 'insensitive'`: see [Indexes](#indexes).

## Bounding a list

`size` sets the fewest and the most values a list holds. Either bound may be
left out:

```ts title="src/schedule.ts"
export const Shift = defineModel({
	name: 'Shift',
	use: [graphql()],
	fields: (f) => ({
		// At least one person, five at most.
		staff: f.string({ list: true, size: { min: 1, max: 5 } }),
	}),
}).with({ access: allow.public })
```

```ts title="src/models.test.ts"
await expect(
	Shift.create({ data: { staff: [] } }, { as: master }),
).rejects.toMatchObject({
	code: 'VALIDATION_FAILED',
	details: {
		issues: [{ path: ['staff'], message: 'Expected 1 to 5 values.' }],
	},
})
```

- The bound holds after the [hooks](/docs/next/hooks), so a `beforeCreate` may
  fill the list.
- It holds on what `push` or `remove` leaves.
- A write outside it fails with `VALIDATION_FAILED`, for every caller.
- PostgreSQL enforces it too, with a check that a
  [migration](/docs/next/postgres) adds. Fill the rows it would refuse first.
- The GraphQL schema and the OpenAPI document state it in the field's
  description.

## Field presets

A rule several fields share, a text that is trimmed and never blank, is a
function of your own that returns the field's options:

```ts title="src/presets.ts"
import type { StringOptions } from 'ultimabase'
import { z } from 'zod'

/** A text stored trimmed, never blank, of at most `max` characters. */
export const text = ({ max = 255 }: { readonly max?: number } = {}) =>
	({
		validate: z
			.string()
			.trim()
			.min(1, 'Never blank.')
			.max(max, `At most ${max} characters.`),
	}) satisfies StringOptions
```

- `satisfies StringOptions` checks the options as `f.string` does;
  `SingleOptions<number>` does the same for a number, `DecimalOptions` for a
  decimal.
- A preset that picks the builder itself, a string or a list of them, takes
  the model's builders instead: `text(f, { list: true })`, typed with
  `FieldBuilders<T>`.

A model passes the options to its builder, and completes them in place:

```ts title="src/models.ts"
// A preset of the app's: its options, completed in place.
summary: f.string({ ...text({ max: 280 }), optional: true }),
```

The field keeps everything `f.string` gives it: it is sorted and filtered as a
string, and its `.with` takes the rules of the model's plugins. Here `plain` is
the lamp of [Validation](#validation) again:

```ts title="src/models.test.ts"
const mug = await Product.create(
	{ data: { ...plain, summary: ' Blue. ' } },
	{ as: master },
)
expect(mug.summary).toBe('Blue.')
```

```ts title="src/models.test.ts"
await expect(
	Product.create(
		{ data: { ...plain, sku: 'CUP-001', summary: '  ' } },
		{ as: master },
	),
).rejects.toMatchObject({
	code: 'VALIDATION_FAILED',
	details: { issues: [{ path: ['summary'], message: 'Never blank.' }] },
})
```

## Change a JSON field's shape

The database keeps each JSON value as it was written: a new schema does not
rewrite the rows stored before it. Server code reads them as they are, typed by
the new schema. GraphQL fails the field of a row that does not fit it.

A change the old rows still fit needs nothing more: a new key, if it is
optional, or a new member of a union.

```ts title="src/models.test.ts"
// Without `finish`, as the rows stored before it was added.
const specs = { color: 'oak', materials: ['wood'] }
const chair = await Product.create(
	{ data: { name: 'Chair', sku: 'CHR-001', price: '80.00', specs } },
	{ as: master },
)
// Its type is `string | undefined`: the code handles both.
expect(chair.specs?.finish ?? 'raw').toBe('raw')
```

```ts title="src/models.test.ts"
const finished = await Product.update(
	{ where: { id: chair.id }, data: { specs: { ...specs, finish: 'matte' } } },
	{ as: master },
)
expect(finished.specs?.finish).toBe('matte')
```

- Make a new key optional rather than give it a `.default(...)`. A default
  fills the rows written after, and types the key as always there, which the
  rows stored before lack.
- The kernel does not convert an old shape when it reads it: filters, sorting
  and unique indexes compare the stored value, and would disagree with what
  the read returns.

A change the old rows do not fit (a renamed key, a key made required, a new
structure) rewrites them in the deploy that brings it:

- An `update` of the table with PostgreSQL's `jsonb` functions, such as
  `jsonb_set`, in a migration of your own (see
  [Your own SQL](/docs/next/postgres#your-own-sql)).
- While a deploy runs the old code and the new side by side, the old code
  still writes the old shape. Accept both for that deploy, with a union of the
  two schemas, and keep the new one alone in the next.

## Shared enums

`f.enumOf(['S', 'M', 'L'])` declares the values in place: GraphQL names the
enum after the model and the field, `ProductSizes`. `defineEnum` names one enum
that several fields, of several models, share:

```ts title="src/types.ts"
// One GraphQL enum and one OpenAPI schema, `Status`, for every field using it.
export const Status = defineEnum('Status', ['draft', 'published', 'archived'], {
	description: 'Where a product is in its life.',
})
```

- `defineEnum` names a GraphQL enum and an OpenAPI schema. It is not a
  TypeScript `enum`, which Node does not run (see the
  [Quickstart](/docs/next/quickstart)).
- `Status.values` lists the values, and `(typeof Status.values)[number]` is
  their type.

A Zod enum with the same values and the same name is the same type. That is how
a JSON field or a function's schema uses a shared enum, with `.meta({ id })`:

```ts title="src/schedule.ts"
const Weekday = defineEnum('Weekday', ['monday', 'tuesday', 'wednesday'])

// The same name and the same values: one type, wherever it is used.
const weekday = z.enum(Weekday.values).meta({ id: 'Weekday' })

export const Opening = defineModel({
	name: 'Opening',
	use: [graphql()],
	fields: (f) => ({
		availableOn: f.enumOf(Weekday, { list: true }),
		searchFilters: f.json({
			validate: z
				.object({ availableOn: z.array(weekday) })
				.meta({ id: 'SearchFilters' }),
		}),
	}),
}).with({ access: allow.public })
```

- GraphQL gives `SearchFilters.availableOn` the type `[Weekday!]!`, and
  OpenAPI references the one `Weekday` schema.
- The same name with other values stops the start, so a typo in the values
  cannot make a second type.
- A typo in the `id` makes a type of that name.

## Object types

`defineType` declares a shape that is not a table, with a Zod object's fields:
the output of a virtual field or of a [function](/docs/next/functions).

```ts title="src/types.ts"
// A shape that is not a table: a virtual field's or a function's output.
export const Price = defineType({
	name: 'Price',
	fields: { amount: z.string(), currency: z.string() },
})
```

## Virtual fields

`f.virtual(output, options)` is computed on read by `.with({ virtuals })`,
never stored. `needs` lists the fields `run` reads, which are read even when
the query does not select them:

```ts title="src/models.ts"
// Computed on read, from the fields `needs` lists.
label: f.virtual(z.string(), { needs: ['name', 'sku'] }),
priceIn: f.virtual(() => Price, {
	input: z.object({ currency: z.enum(['EUR', 'USD']) }),
	needs: ['price'],
}),
```

```ts title="src/models.ts"
.with({
	access: allow.public,
	virtuals: {
		label: { run: ({ record }) => `${record.name} (${record.sku})` },
		priceIn: {
			run: ({ record, input }) => ({
				amount:
					input.currency === 'EUR'
						? record.price
						: (Number(record.price) * 1.1).toFixed(2),
				currency: input.currency,
			}),
		},
	},
})
```

A virtual with an `input` takes arguments and is read only when selected.
Here the product is a mug priced `'12.00'`, with the `sku` `MUG-001`; the USD
rate of `priceIn` is 1.1, which gives `13.20`:

```ts title="src/models.test.ts"
const mug = await Product.findUniqueOrThrow(
	{
		where: { sku: 'MUG-001' },
		select: { label: true, priceIn: { currency: 'USD' } },
	},
	{ as: master },
)
expect(mug).toEqual({
	label: 'Mug (MUG-001)',
	priceIn: { amount: '13.20', currency: 'USD' },
})
```

- `run` computes one row's value and receives `{ record, input, caller }`.
- `runMany` receives `{ records, input, caller }` and returns one value per
  row, in order, to read a list of rows in one query.
- The output is a Standard Schema, or behind an arrow a model or a type:
  `() => Price`, `() => [Image]` for a list, `() => Image.nullable()` for a row
  that may be missing.
- A live read follows the rows a virtual read: a write that changes its value
  sends the row again ([realtime](/docs/next/realtime#virtual-fields)).

A stored `one` relation in `needs` gives its key, `{ id }` (or `null` when
optional), with no extra query, so a rule can compare `record.author.id` with
the caller:

- The virtual is hidden from a caller who cannot read the relation.
- A `many` is refused.
- A name that is no field of the model fails to compile on the virtual's line,
  with the closest name suggested (`Did you mean '"cover"'?`).
- `needs` offers no completion, since the model's fields are not known yet
  when it is written.

## A field only the server reads

A field's `.with({ access })` adds its own rules. `allow.private` leaves it to
Master: the transports leave it out of their schema, as `cost` is above.

```graphql title="Request"
query {
	products {
		edges {
			node {
				cost
			}
		}
	}
}
```

```json title="Response"
{
	"errors": [
		{
			"message": "Cannot query field \"cost\" on type \"Product\".",
			"locations": [{ "line": 5, "column": 5 }],
			"extensions": { "code": "BAD_USER_INPUT" }
		}
	]
}
```

[Access rules](/docs/next/access) lists the other rules.

## Indexes

`indexes` lists indexes over several fields:

```ts title="src/models.ts"
// Lists the products of a status by release day, fast.
indexes: [
	{ fields: ['status', 'releasedOn'] },
	// The newest products first; `id` breaks ties between equal dates.
	{ fields: ['createdAt', 'id'] },
	// One product of a name per release day, whatever its case.
	{ fields: ['name', 'releasedOn'], unique: true, mode: 'insensitive' },
],
```

- `unique: true` refuses two rows with the same values.
- `mode: 'insensitive'` with it compares their strings and enums regardless of
  case: `DESK` clashes with `Desk` on the same release day.
- `where` with it compares only the rows the filter keeps.
- `contains: true` makes `contains` and `mode: 'insensitive'` fast on one
  string field.
- `id`, `createdAt` and `updatedAt` fit in a non-unique index.

The last index above refuses a second `Desk` of the same day, whatever its case:

```ts title="src/models.test.ts"
const desk = { sku: 'DSK-001', price: '90.00', releasedOn: '2026-07-31' }
await Product.create({ data: { ...desk, name: 'Desk' } }, { as: master })
await expect(
	Product.create(
		{ data: { ...desk, name: 'DESK', sku: 'DSK-002' } },
		{ as: master },
	),
).rejects.toMatchObject({
	code: 'UNIQUE_VIOLATION',
	details: { model: 'Product', fields: ['name', 'releasedOn'] },
})
```

## Rename a column or deprecate a field

`dbName` keeps the stored column's name, and `deprecated` tells clients to stop
using the field:

```ts title="src/models.ts"
// The column keeps the name an older table gave it; clients see the
// field is deprecated.
legacyCode: f.string({
	optional: true,
	dbName: 'old_code',
	deprecated: 'Use sku.',
}),
```

## Commands

`.commands<T>(build)` adds the application's own operations to a model, next to
its queries. `T` is an interface with each command's signature and comment:

```ts title="src/models.ts"
interface ProductCommands {
	/** Adds `count` items to a product's stock: the new stock. */
	restock(id: string, count: number): Promise<number>
}
```

```ts title="src/models.ts"
// Server code only: no transport serves a command.
.commands<ProductCommands>(({ queries }) => ({
	restock: async (id, count) => {
		const { stock } = await queries.update(
			{
				where: { id },
				data: { stock: { increment: count }, restockedAt: new Date() },
			},
			{ as: master },
		)
		return stock
	},
}))
```

A command is called through the model. A new mug has no stock, so 12 then 3
make 15:

```ts title="src/models.test.ts"
const { id } = await Product.create(
	{ data: { name: 'Mug', sku: 'MUG-001', price: '12.00' } },
	{ as: master },
)
await expect(Product.restock(id, 12)).resolves.toBe(12)
await expect(Product.restock(id, 3)).resolves.toBe(15)
```

- Without `T`, `build` fails to compile on `name the commands type`, as a
  command that calls its model could not infer its own type.
- `build` receives `{ queries }`, the model's queries, and returns an object of
  functions. A command calls another through the model: `Product.other()`.
- A command runs on the server only: no transport serves it. A client calls a
  [function](/docs/next/functions).
- A test runs the real command on the memory database: the model is frozen, so
  a spy cannot replace it.

## Details

- `.commands` is called once, before `.with`: in a cycle of relations, a
  `.with` before it whose rules read a model of the cycle, as the signed-in
  user's, makes the model read itself in its own type (TS7022).
- When two models' commands call each other, the builder whose interface names
  the other model writes its return type:
  `({ queries }): SeatCommands => ({ ... })` for a
  `leave(games: WhereOf<typeof Game>)`.
- A command named after a model method (`findMany`, `with`, `paginate`…) or
  after a plugin's command stops the definition:
  `Product.with: the application adds a command named after a model method.`
- A list cannot be `optional`, `unique` or searched: each is a type error.
- `findUnique` matches a case-insensitive key exactly: `alice` does not find
  `Alice`. A `findFirst` with `mode: 'insensitive'` does.
- An index with `mode: 'insensitive'` is unique, has no `contains`, and holds a
  string field at least: another is a type error.
- A unique index cannot name `id`, `createdAt` or `updatedAt`, which the kernel
  sets: a type error, and `a unique index cannot name 'createdAt', which the
kernel sets.` at start.
- An index's `where` needs `unique: true` and no `contains`. Another `where` is
  a type error, and refused at start.
- Each key of an index's `where` names a field that is no list, `json`,
  relation or kernel field. It takes a value, `null`, `{ equals }` or
  `{ not }`, and the keys all hold.
- `{ not: 'x' }` leaves out the rows that are `null`.
- A partial index is no target of `findUnique`, `update` or `upsert`.
- A `defineEnum` name is a GraphQL name, letters, digits and `_`, not starting
  with `__`; another name throws when the module loads.

## Reference

### `defineModel(definition)`

| Key           | Type                                              | Default       | Effect                                                                                                                                                                                                                                                                                                                                                                                |
| ------------- | ------------------------------------------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`        | `string`                                          | required      | The model's name: `Product` gives `products` and `createProduct` in GraphQL.                                                                                                                                                                                                                                                                                                          |
| `fields`      | `(f) => ({ ... })`                                | required      | The fields, built with `f`.                                                                                                                                                                                                                                                                                                                                                           |
| `use`         | plugin uses                                       | `[]`          | The plugins the model uses: `graphql()`, `rest()`, `softDelete()`…                                                                                                                                                                                                                                                                                                                    |
| `indexes`     | `{ fields, unique?, contains?, mode?, where? }[]` | `[]`          | Indexes over several fields; `unique: true` refuses two rows with the same values, and `mode: 'insensitive'` with it compares their strings and enums regardless of case; `where` with it compares only the rows the filter keeps; `contains: true` makes `contains` and `mode: 'insensitive'` fast on one string field. `id`, `createdAt` and `updatedAt` fit in a non-unique index. |
| `description` | `string`                                          | none          | Shown in the GraphQL schema and the OpenAPI document.                                                                                                                                                                                                                                                                                                                                 |
| `dbName`      | `string`                                          | the adapter's | The stored table's name.                                                                                                                                                                                                                                                                                                                                                              |

`.with({ access, hooks, virtuals, relations })` adds the rules that read the
typed rows: [access](/docs/next/access), [hooks](/docs/next/hooks), the
virtuals' `run`, and [relation filters](/docs/next/relations). Each plugin of
`use` adds its own key. Given to `defineModel` instead, one stops the import:
`Note: the definition takes no hooks; access, hooks and plugin options go in .with().`
`.commands<T>(build)` adds the application's [commands](#commands).

### Field types

| Builder                           | Value in TypeScript             | Notes                                                                              |
| --------------------------------- | ------------------------------- | ---------------------------------------------------------------------------------- |
| `f.string()`                      | `string`                        | `search: true` adds it to the model's full-text search; `list: true`.              |
| `f.number()`                      | `number`                        | `integer: true`: whole numbers from -2,147,483,648 to 2,147,483,647; `list: true`. |
| `f.decimal({ precision, scale })` | `string`                        | Exact, at most `precision` digits, `scale` after the point: `'12.50'`.             |
| `f.boolean()`                     | `boolean`                       |                                                                                    |
| `f.dateTime()`                    | `Date`                          | An instant; ISO 8601 over the transports.                                          |
| `f.date()`                        | `string`                        | A calendar day, `'2026-07-31'`, without a time zone.                               |
| `f.json()`                        | `unknown`, or the schema's type | Any JSON; with a schema in `validate`, typed and validated.                        |
| `f.enumOf(values)`                | the values' union               | An array, or a `defineEnum`; `list: true`.                                         |
| `f.one(() => Model)`              | a row                           | See [Relations](/docs/next/relations).                                             |
| `f.many(() => Model)`             | rows                            | See [Relations](/docs/next/relations).                                             |
| `f.virtual(output, options?)`     | the output's type               | Computed on read; `input`, `needs`, `description`, `deprecated`.                   |

Plugins add their own types: `password()` and `file()`. See
[Write a plugin](/docs/next/plugins) for `defineFieldType`.

### Field options

| Option        | Type                                      | Default       | Effect                                                                                                                                                                                               |
| ------------- | ----------------------------------------- | ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `optional`    | `boolean`                                 | `false`       | The field may be `null`; a write may leave it out.                                                                                                                                                   |
| `unique`      | `boolean`, or `'insensitive'` on a string | `false`       | Two rows cannot hold the same value, regardless of case with `'insensitive'`; `null` is not compared.                                                                                                |
| `default`     | a value, or `({ caller }) => value`       | none          | Written when a create leaves the field out; a function returning `undefined` gives none.                                                                                                             |
| `validate`    | Standard Schema, or `(value) => value`    | none          | Refuses a value, or returns the value to store.                                                                                                                                                      |
| `list`        | `true`                                    | `false`       | Strings, numbers and enums: a list, `[]` when empty; never optional nor unique.                                                                                                                      |
| `size`        | `{ min?, max? }`                          | none          | With `list: true`: how many values the list holds. See [Bounding a list](#bounding-a-list).                                                                                                          |
| `description` | `string`                                  | none          | Shown in the GraphQL schema and the OpenAPI document.                                                                                                                                                |
| `deprecated`  | `string`                                  | none          | Why clients should stop using the field, and what replaces it: `@deprecated` in GraphQL, `deprecated: true` in OpenAPI. Only on a field a create may leave out: optional, with a default, or a list. |
| `dbName`      | `string`                                  | the adapter's | The stored column's name.                                                                                                                                                                            |
