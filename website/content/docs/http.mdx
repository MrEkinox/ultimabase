`@ultimabase/http` starts the application's HTTP server. GraphQL, REST,
auth and files mount their routes on it; the application adds its own,
such as a webhook, with [Hono](https://hono.dev).

```npm
npm install @ultimabase/http
```

plugins mount. The other options are on the same call:

## The caller

`c.var.caller` is the request's caller. Pass it as `{ as: c.var.caller }`,
so the model's rules apply to the route as to any client:

- Master, with the master key;
- the signed-in user, with [auth](/docs/next/auth);
- anonymous, otherwise.

`c.var.address` is the client's address, `''` when unknown:

<include cwd meta='title="src/routes.ts"'>
	../examples/http/src/routes.ts#whoami
</include>

Behind a proxy, as a load balancer, every connection comes from the proxy.
`proxies` is the number of proxies in front of the server. The client's
address is then the entry of `X-Forwarded-For` that many from the right,
which a client cannot forge. With `proxies: 1`, as in the application above:

## Rate limit

Each client address may send 600 requests a minute. `rateLimit` changes
the limit, or turns it off with `false` when a proxy limits in front. Past
the limit, before any session is read, the server answers:

| Part                 | Value                             |
| -------------------- | --------------------------------- |
| status               | 429                               |
| code                 | `TOO_MANY_ATTEMPTS`               |
| `Retry-After` header | the seconds until the minute ends |
| `details.retryAfter` | the same seconds                  |

The tests set `rateLimit` to 100 requests and send 100 from
`x-forwarded-for: 198.51.100.4`, so the 101st is refused:

<include cwd meta='title="src/app.test.ts"'>
	../examples/http/src/app.test.ts#limit
</include>

`refused` is the response to that 101st request.

- WebSocket upgrades and each operation sent over a socket count too.
- An operation over the limit on a GraphQL socket fails with the same
  `TOO_MANY_ATTEMPTS` and `details.retryAfter`; the socket stays open.
- The address is the one `proxies` reads. An IPv6 address counts by its
  /64, and a local or private address is never counted.
- The master key passes over the limit.
- Each instance counts in its own memory: behind a load balancer, the limit
  is per instance.
- A limit per person on a write is a
  [hook](/docs/next/hooks#limit-a-persons-writes).

## Errors

A route throws to refuse a request:

- a `PublicError`, as `NOT_FOUND` in the receipt above, is sent as
  `{ code, message, details }` with its code's status, as
  [Errors](/docs/next/errors) lists them; an application's own code is a
  `400`;
- Hono's `HTTPException` keeps its status, its code the status's name, as
  `UNAUTHORIZED` for the wrong secret above;
- any other error is `500` `INTERNAL`, `Internal error.`, with a
  `correlationId` the server logs beside the error.

The server answers some requests itself, before any route:

| Request                              | Status | Code                |
| ------------------------------------ | ------ | ------------------- |
| a body over `bodyLimit` (64 KB here) | 413    | `PAYLOAD_TOO_LARGE` |
| a path no route matches              | 404    | `NOT_FOUND`         |
| a form from another origin           | 403    | `ACCESS_DENIED`     |

A route with `validate('json')` also answers 415
`UNSUPPORTED_MEDIA_TYPE` to a body whose content type is not JSON
(`application/json`, or `application/*+json`). Their messages are in the
Errors table of the Reference.

## Health and readiness

| Path          | Answers                                                                                                                              |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /health` | 200 as long as the server answers: a platform restarts the instance when it does not.                                                |
| `GET /ready`  | 200 once every plugin started; 503 `UNAVAILABLE` while the application starts, once its stop began, or while a plugin's check fails. |

A load balancer sends traffic only to an instance that is ready.

<include cwd meta='title="Request"'>
	../examples/http/src/requests/health.http
</include>

<include cwd meta='title="Response"'>
	../examples/http/src/requests/health.json
</include>

`GET /ready` answers the same body, `{ "status": "ok" }`, with status 200.

On `stop`, `/ready` answers 503 first, and the server serves as before for
`drain` milliseconds, 5000 in production: the load balancer has the time to
see it and send no more traffic. Then the plugins stop.

## Details

- With auth, `Authorization: Bearer` carries a session on every route, the
  application's and the mounted ones alike. An unknown token there is
  refused with `UNAUTHENTICATED` (401) before the route runs.
- The caller is known before any route runs. A route that checks a token of
  its own reads another header, as `X-Maintenance-Token`; a request with
  neither a Bearer header nor a session cookie looks up no session.
- Without `proxies`, a request with `X-Forwarded-For` from a local network
  logs a warning once: every client would count as the proxy, and
  [password](/docs/next/password)'s limits would block them all at once.
- `/health` and `/ready` come before every route, the application's
  included: they read no caller, and no CORS applies.
- Until every plugin started, every other request and WebSocket upgrade
  answers 503 `UNAVAILABLE`, `The application is starting.`, Master's too: a
  plugin that has not started serves no request.
- `/ready` checks no database: when it fails, every instance would leave
  the load balancer at once.

## Reference

### `httpPlugin(options)`

| Option      | Type                              | Default                         | Effect                                                             |
| ----------- | --------------------------------- | ------------------------------- | ------------------------------------------------------------------ |
| `routes`    | `routes()[]`                      | none                            | Mounted at the root, in their order, before the plugins' own.      |
| `cors`      | origins                           | none                            | The origins a browser may call from, with its cookies.             |
| `port`      | number                            | `PORT`, then 3000               | Where the server listens.                                          |
| `bodyLimit` | whole number of bytes             | 1 MB                            | The largest request body; files take their own limit.              |
| `proxies`   | whole number                      | 0                               | The proxies in front of the server, read in `X-Forwarded-For`.     |
| `rateLimit` | `{ requests, window }` or `false` | 600 per 60 000 ms               | Each address's requests and upgrades in a window, in milliseconds. |
| `upgrade`   | function                          | none                            | Answers each WebSocket upgrade: a `Response` refuses it.           |
| `drain`     | milliseconds                      | 5000 in production, 0 otherwise | How long the stop waits once `/ready` answers 503.                 |

Outside production, local origins over `http:` are allowed besides `cors`,
and `POST /_ultimabase/reset` empties the database for the master key, for
[end-to-end tests](/docs/next/testing#end-to-end-tests).
On `stop`, after the `drain`, the server stops taking connections and waits
10 seconds at most for the requests still running.

### Readiness checks

From a plugin that requires the HTTP plugin:

| Member                      | Effect                                                                                                |
| --------------------------- | ----------------------------------------------------------------------------------------------------- |
| `plugins.http.ready(check)` | From the plugin's `api`: `/ready` runs `check()` on each request, and answers 503 when it is `false`. |

A check returns a boolean, or a promise of one. One that throws fails, and
its error is logged with `A readiness check failed.`

### Gates

A plugin answers requests before the caller is read and before any route,
as [maintenance](/docs/next/maintenance) does. From a plugin that requires
the HTTP plugin:

| Member                    | Effect                                                                                      |
| ------------------------- | ------------------------------------------------------------------------------------------- |
| `plugins.http.gate(gate)` | From the plugin's `api`: `gate(request)` answers each request and upgrade, or lets it pass. |

A gate returns a `Response`, which refuses the request, or `undefined`,
which lets it through; a promise of either too. It runs after CORS, so
that a browser reads the refusal, and never on a preflight, `/health` or
`/ready`. On an upgrade, it runs after `upgrade`. The gates run in the
plugins' order, and the first `Response` is the answer.

### WebSockets

A plugin takes the WebSocket upgrades of a path, as GraphQL takes those of
its own. An upgrade on a path no plugin takes is a 404, one from an origin
`cors` does not allow a 403; `upgrade` then answers the others, as during
[maintenance](/docs/next/realtime#maintenance). From a plugin that requires
the HTTP plugin:

| Member                                          | Effect                                                                                    |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `plugins.http.upgrade(path, accept, { close })` | Takes the upgrades of `path`, from the plugin's `api`; `close(code, reason)` closes them. |
| `plugins.http.closeUpgrades({ code, reason })`  | Closes the sockets open; with `path`, those of one path. Cuts those without `close`.      |

`accept` receives the upgrade: its `request`, the client's `address`, the
`socket`, and `limit()`, which counts one more request of the address and
returns the seconds to wait when it is over the limit, `undefined` within
it. A plugin that serves several operations on one socket calls it for
each.

`closeUpgrades` with a path no plugin takes throws `No plugin takes the
upgrades of /x.`; before the start and after the stop, it closes nothing.

### `routes()` and its context

`routes()` is a Hono application; every Hono feature works in it, as
middlewares and `streamSSE`.

| Value                    | Effect                                                   |
| ------------------------ | -------------------------------------------------------- |
| `c.var.caller`           | The request's caller, to pass as `{ as: c.var.caller }`. |
| `c.var.address`          | The client's address, `''` when unknown.                 |
| `c.req.valid(target)`    | What `validate(target, schema)` accepted, typed.         |
| `routes().request(path)` | A response, as an anonymous request, without the server. |

A middleware registered with `use` runs for every route after it, those
other plugins mount included: give it a path, as `use('/admin/*', …)`, to
keep it to some routes. A route added after `start` is not served.

### `validate(target, schema)`

| Argument | Values                                                           |
| -------- | ---------------------------------------------------------------- |
| `target` | `'json'`, `'query'`, `'param'`, `'header'`, `'form'`, `'cookie'` |
| `schema` | any Standard Schema                                              |

### Errors

| Status | Code                     | When                                                                                                                 |
| ------ | ------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| 400    | `VALIDATION_FAILED`      | `Invalid data.`: `validate` refused a value, with `details.issues`.                                                  |
| 400    | `BAD_REQUEST`            | `Malformed JSON in request body`, or `Malformed form data in request body`.                                          |
| 403    | `ACCESS_DENIED`          | `A form from another origin is refused.`, `The master key is wrong.`, or `Only the master key empties the database.` |
| 404    | `NOT_FOUND`              | `No route matches GET /nowhere.`                                                                                     |
| 413    | `PAYLOAD_TOO_LARGE`      | `The body is over 65536 bytes.`                                                                                      |
| 415    | `UNSUPPORTED_MEDIA_TYPE` | `The body is not JSON: send content-type: application/json.`                                                         |
| 429    | `TOO_MANY_ATTEMPTS`      | `Too many requests: try again later.`, with `details.retryAfter` and `Retry-After`.                                  |
| 500    | `INTERNAL`               | `Internal error.`, with `correlationId`.                                                                             |
| 503    | `UNAVAILABLE`            | `The application is starting.`, `The application is stopping.`, or `A readiness check failed.`, from `/ready`.       |
| any    | the status's name        | An `HTTPException`, as `401` `UNAUTHORIZED`.                                                                         |

A `PublicError` takes its code's status: `ACCESS_DENIED` 403, `NOT_FOUND`
404, `VALIDATION_FAILED` 400, `UNIQUE_VIOLATION`, `RELATION_RESTRICTED`,
`RELATION_SIZE` and `CONFLICT` 409, `UNAUTHENTICATED` and `INVALID_CREDENTIALS` 401, `TOO_MANY_ATTEMPTS`
429 with `Retry-After`, any other code 400.

At start: `proxies is 1.5, not a whole number of proxies in front of the
server.`, `rateLimit.requests is 0, not a whole number above 0.`,
`bodyLimit is NaN, not a whole number of bytes above 0.`, `drain is -1, not
a whole number of milliseconds.`, and `PORT is 80a, not a port between 0
and 65535.`

### The development log

Outside production, each request is logged once answered, as
`POST /webhooks/payment 200 3ms`; nothing is logged per request in
production. A client that leaves before its answer counts as `499`.

### Limits

- One server, HTTP/1.1, without TLS: a proxy or the host serves HTTPS.
- The `stop` delay of 10 seconds is not an option.
- The paths `/health` and `/ready` are not options.
