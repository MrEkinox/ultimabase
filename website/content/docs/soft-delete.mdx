title: Soft delete
description: Keep deleted rows in a trash, dated, and bring them back.

`@ultimabase/soft-delete` keeps the rows a delete removes: a deleted row
gets a `deletedAt` date and leaves every ordinary read, and the model's
trash still finds it. `softDelete()` goes in a model's `use`:

```npm
npm install @ultimabase/soft-delete
```

The full example, with its tests: [`examples/soft-delete`](https://github.com/MrEkinox/ultimabase/tree/main/examples/soft-delete).

| To                                      | Use                                               |
| --------------------------------------- | ------------------------------------------------- |
| turn on the trash                       | [`softDeletePlugin()`](#set-it-up)                |
| delete a row and keep it                | [`deletePost`, or `delete`](#delete-a-row)        |
| let clients read the trash and restore  | [a function](#over-graphql)                       |
| read the trash, restore, from your code | [`Post.trash`, `Post.restore`](#from-server-code) |
| reuse the value of a deleted row        | [an index with `where`](#unique-values)           |
| know which rules and hooks run          | [Rules](#rules)                                   |

## Rules

- A delete still needs the model's `delete` rule.
- `beforeDelete` and `afterDelete` [hooks](/docs/next/hooks) run as for any
  delete.
- `trash` reads under the `read` rule, and `restore` writes under the
  `update` rule.

Only Master writes `deletedAt`: a client deletes through the `delete` rule and
never dates a row itself. The request is refused with `ACCESS_DENIED`:

## Details

- A deleted row's date is its `deletedAt`: `trash { title deletedAt }` reads it,
  and `Post.delete` returns it as a `Date`.
- The date is an update, written as Master. A delete also runs the model's
  `beforeUpdate`, `afterUpdate` and `afterUpdateCommit` hooks, and their
  `caller` is Master.
- A hook tells it from an edit by its `data.deletedAt`: a date for a delete,
  `null` for a `restore`.

## Reference

### `softDelete()` and `softDeletePlugin()`

Neither takes an option. `softDeletePlugin()` must be in plugins when a
model uses `softDelete()`. `softDelete()` adds:

| What    | Name                                                      | Effect                                                                     |
| ------- | --------------------------------------------------------- | -------------------------------------------------------------------------- |
| field   | `deletedAt`                                               | An optional `dateTime`: the delete's date, `null` for a kept row.          |
| command | `Post.trash.findMany`, `findFirst`, `findUnique`, `count` | The deleted rows, under the `read` rule.                                   |
| command | `Post.restore({ where }, { as })`                         | Sets `deletedAt` back to `null`, under the `update` rule; returns the row. |

### What a delete does

| Case                    | Result                                                                             |
| ----------------------- | ---------------------------------------------------------------------------------- |
| `delete`, `deleteMany`  | Dates the rows and returns them, as a delete does; no row is removed.              |
| the row's relations     | Stay: a soft-deleted row cascades nothing, and keeps its related rows.             |
| the row's unique values | Stay taken, unless an index's `where` is `{ deletedAt: null }`: see Unique values. |
| a read, a count         | Leaves the deleted rows out, for every caller.                                     |
| a relation to the row   | A `one` to it reads `null`, for every caller.                                      |

### Errors

| Code            | When                                                                                     |
| --------------- | ---------------------------------------------------------------------------------------- |
| `NOT_FOUND`     | `restore` of a row that is not deleted.                                                  |
| `ACCESS_DENIED` | A caller other than Master writes `deletedAt`; a `delete` or `restore` the rules refuse. |

### Limits

- The plugin has no command that removes a deleted row for good.
