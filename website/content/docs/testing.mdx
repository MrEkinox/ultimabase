title: Testing
description: Run the application around each test, on a new database, as the caller of your choice.

`testApplication(app)` starts the application before each test of the file
and stops it after: on a new in-memory database, and an HTTP server on a
free port. Tests run with [Vitest](https://vitest.dev); install
`@ultimabase/testing` as a dev dependency:

```npm
npm install -D @ultimabase/testing vitest
```

<include cwd meta='title="src/app.test.ts"'>
	../examples/testing/src/app.test.ts#start
</include>

The full example, with its tests: [`examples/testing`](https://github.com/MrEkinox/ultimabase/tree/main/examples/testing).

| To                                       | Use                                                      |
| ---------------------------------------- | -------------------------------------------------------- |
| start each test without rows             | [`testApplication(app)`](#a-new-database-each-test)      |
| act as a signed-in user                  | [`asUser({ id })`](#as-a-signed-in-user)                 |
| call the API as a client                 | [`running.url`](#over-http)                              |
| prove which queries a call makes         | [`running.queries(callback)`](#the-queries-a-test-makes) |
| test on PostgreSQL                       | [`{ database: 'declared' }`](#on-postgresql)             |
| test a plugin's `missed`                 | [`running.feed.missed()`](#lost-changes)                 |
| empty the database between browser tests | [`POST /_ultimabase/reset`](#end-to-end-tests)           |

The application starts as it is declared, its plugins and functions
included, but without its info lines: warnings and errors still print.

## A new database each test

Each test starts on an empty database: a row one test writes is gone in the
next, so tests run in any order.

## As a signed-in user

`asUser({ id })` is the caller a session gives, without signing in: its
access rules apply, as in the application.

<include cwd meta='title="src/app.test.ts"'>
	../examples/testing/src/app.test.ts#as-user
</include>

- `{ as: master }` skips the rules, to seed rows or read them all.
- Without `as`, the caller is anonymous.

## The queries a test makes

`running.queries(callback)` lists the queries the callback sends to the
database, in their order. A test proves that a refusal reads nothing:

<include cwd meta='title="src/app.test.ts"'>
	../examples/testing/src/app.test.ts#no-queries
</include>

Or that a loop does not query once per row. An entry names the operation
and the model:

<include cwd meta='title="src/app.test.ts"'>
	../examples/testing/src/app.test.ts#queries
</include>

- The operation is `find`, `count`, `aggregate` or `write`; `exists` is a
  `find`.
- A write that changes several models names them all, as
  `write Invite, User`.
- The queries of a [transaction](/docs/next/transactions) are listed; its
  begin and its commit are not.

## On PostgreSQL

`{ database: 'declared' }` runs the tests on the application's own
database: on `postgres()`, in a schema of the test file's own, named
`ultimabase_test_<random>`.

<include cwd meta='title="src/tasks.postgres.test.ts"'>
	../examples/postgres/src/tasks.postgres.test.ts#declared
</include>

- A test writes a project with a task, deletes the project, and counts
  no task left: the task goes with its project, as the model says.
- The first test creates the tables in the schema, each later one starts
  with them emptied, and the schema is dropped after the file's last test.
- No other table is read or written.

A test on PostgreSQL checks what `memory()` cannot: raw SQL, a constraint,
the real column types. It is slower: keep most tests on `memory()`, and
name these `*.postgres.test.ts` to run them apart.

## End-to-end tests

A front end's end-to-end tests run against `ultimabase dev`.
`POST /_ultimabase/reset` with the master key empties the database: each
test starts from no rows and seeds its own through the API.

<include cwd meta='title="Request"'>
	../examples/testing/src/requests/reset.http
</include>

It answers 204 with no body. A [Playwright](https://playwright.dev) fixture
sends the same request before each test, then seeds the test's rows with
the master key.

- Every model's rows go, those of plugins included, as auth's users and
  sessions.
- The tables stay as `ultimabase dev` keeps them.
- No hook, cascade rule or soft delete runs, and stored files stay where
  their storage keeps them.
- Live reads read again, and find nothing.

The [HTTP plugin](/docs/next/http) serves the route outside production
only: under `ultimabase start` it answers 404, as any unknown path. Another
caller than Master gets 403 `ACCESS_DENIED`.

## Details

- The previous test's page may still be connected and saving: the reset
  waits for the requests already running, and holds the new ones until the
  database is empty, then lets them through.
- When requests still run after 5 seconds, the reset answers 500 `INTERNAL`
  and empties nothing; the server's log says how many were running.

## Reference

### `testApplication(app, options?)`

| Option     | Type         | Default    | Effect                                                    |
| ---------- | ------------ | ---------- | --------------------------------------------------------- |
| `database` | `'declared'` | `memory()` | The application's own database, in the file's own schema. |

It returns, read during a test:

| Key                 | Effect                                                       |
| ------------------- | ------------------------------------------------------------ |
| `url`               | The HTTP server's address, such as `http://localhost:54321`. |
| `feed.missed()`     | Calls each plugin's `missed`, as after a lost connection.    |
| `queries(callback)` | The queries the callback sends, such as `['find Note']`.     |

### `asUser(user)`

| Argument | Type                                                                           | Returns                                 |
| -------- | ------------------------------------------------------------------------------ | --------------------------------------- |
| `user`   | `{ id }`, or the registered user's row, as a sign-up or a Master read gives it | a caller of kind `'user'`, for `{ as }` |

### `runJobs()`

Runs, during a test, the [jobs](/docs/next/jobs#in-a-test) due now, and
the runs they enqueue.

### Errors

| Message                                                                                                                                                              | When                                          |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| `testApplication takes the value defineApp returned.`                                                                                                                | Another value was given.                      |
| `url is the address of httpPlugin(), read during a test: add httpPlugin() to the application.`                                                                       | `url` read outside a test, or without HTTP.   |
| `testApplication runs on the declared database when it gives a test file tables of its own, as postgres() does; this one does not: remove { database: 'declared' }.` | The database cannot give a schema per file.   |
| `feed.missed() runs during a test.`                                                                                                                                  | `feed.missed()` called outside a test.        |
| `queries() runs during a test.`                                                                                                                                      | `queries()` called outside a test.            |
| `queries() already records: do not nest it.`                                                                                                                         | `queries()` called inside another's callback. |

### Limits

- `testApplication` adds Vitest's `beforeEach` and `afterEach`: call it at
  the top of a file or a `describe`, never inside a test.
- A process killed during a test file leaves its schema behind.
- `queries()` lists the queries of the whole application while the callback
  runs, a plugin's included. `database.sql` is not listed.
