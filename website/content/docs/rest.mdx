`@ultimabase/rest` serves a REST API generated from the models and the
functions, on the [HTTP](/docs/next/http) server. It is the
[GraphQL](/docs/next/graphql) API in HTTP's grammar: the same names, the same
operators and the same answers. Each request runs as its caller, under the
models' [access rules](/docs/next/access). Every model and every function
of the application is served; listing `rest()` in a model's `use` lets its
`.with({ rest })` set its routes' name and its limits, or hide it:

```npm
npm install @ultimabase/rest
```

The API is under `/api`, and the server logs `REST on
http://localhost:3000/api.` outside production. A query parameter holds
JSON, unless it is a cursor; a body is JSON, sent with
`content-type: application/json`. The tests on this page call it with these
two helpers:

## What a model gets

`Post` gets six routes, each the twin of a GraphQL field:

| Route                   | Does                                           | Answers                      |
| ----------------------- | ---------------------------------------------- | ---------------------------- |
| `GET /api/posts`        | lists, as `posts`                              | `200`, a page                |
| `GET /api/posts/:id`    | reads one row, as `post`                       | `200`, or `404` when absent  |
| `POST /api/posts`       | creates, as `createPost`; the body is its data | `201`                        |
| `PUT /api/posts`        | upserts, as `upsertPost`                       | `201` created, `200` updated |
| `PATCH /api/posts/:id`  | updates, as `updatePost`; the body is its data | `200`                        |
| `DELETE /api/posts/:id` | deletes, as `deletePost`                       | `200`, the row as it was     |

A write's body nests its [relations](/docs/next/relations)' writes, as in
GraphQL: `connect`, `create` and `connectOrCreate`, and in an update
`update`, `disconnect`, `set` and `delete`. A write takes `select` or
`include` as query parameters, to shape its answer. Here a person is
created with three posts:

## Pages

A list answers a Relay connection, as GraphQL does: `edges`, each with its
`cursor` and its `node`, then `pageInfo`. `first` and `after` page forward,
`last` and `before` backward; `after` and `before` are cursors, sent as
they are, without JSON. `totalCount=true` adds the count of rows the
`where` matches:

## One row

`GET /api/posts/:id` reads a row by its id; a row that does not exist, or
that the caller may not read, is a `404`:

<include cwd meta='title="src/app.test.ts"'>
	../examples/rest/src/app.test.ts#row
</include>

Without `select` or `include`, a row holds its `id`, `createdAt` and
`updatedAt`, each field the caller may read, and the virtuals read by
default; no relation. A list's rows hold the same.

## Choose the fields

`select` names the fields a row holds; `include` adds relations to the
default fields. Both nest: a relation's value is `true`, or what to read
of it, with a many relation's own `where`, `orderBy`, `first` and
`totalCount`. A row takes one of the two, never both:

<include cwd meta='title="src/app.test.ts"'>

</include>

## Filters

`where` takes the operators of [queries](/docs/next/queries): `equals`,
`gt`, `startsWith`, `in` and the others on a field; `is` and `isNot` on a
relation to one row; `some`, `every` and `none` on a many relation; `AND`,
`OR` and `NOT` around them. `orderBy` takes a field, or a list of them:

## OpenAPI

`GET /api/openapi.json` is the API's [OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.0)
document: each route, its parameters, its bodies, its answers and its
errors, as JSON Schema. A client generator or a tool such as Swagger UI
reads it:

<include cwd meta='title="src/app.test.ts"'>
	../examples/rest/src/app.test.ts#openapi
</include>

Each operation is named as its GraphQL field, as `posts`, `post`,
`createPost`, `upsertPost`, `updatePost`, `deletePost`, and a function's
name. Its schemas are named as GraphQL's types, as `Post` and
`PostWhereInput`, with `PostSelect`, `PostInclude` and `Error`.

## Limits

A request from a caller other than Master is refused before it runs when
it nests deeper than `maxDepth`, its `orderBy` counted, or may return more
than `maxRows` rows, each list counting its `first` times the lists above
it. A list asking for more than its `maxTake` is refused as it runs:

<include cwd meta='title="src/app.test.ts"'>

## Live reads

With [`realtimePlugin()`](/docs/next/realtime), a list, a row or a query
function of a live model answers a stream of Server-Sent Events when the
request sends `Accept: text/event-stream`. The [Realtime](/docs/next/realtime)
page shows it.

## Reference

### `restPlugin(options)`

| Option       | Type                       | Default        | Effect                                                              |
| ------------ | -------------------------- | -------------- | ------------------------------------------------------------------- |
| `path`       | string                     | `'/api'`       | Where the routes and the OpenAPI document are served.               |
| `pagination` | `'connection'` or `'list'` | `'connection'` | Relay connections, or arrays with `take` and `skip`.                |
| `take`       | number                     | 100            | The rows a list returns without `first`, `last` or `take`.          |
| `maxTake`    | number                     | 100            | The most rows a list returns, unless the model sets its own.        |
| `maxDepth`   | number                     | 10             | The deepest a request nests, its fields and its `orderBy` counted.  |
| `maxRows`    | number                     | 20 000         | The most rows a request may return, each list times those above it. |

It requires `httpPlugin()`. With [`realtimePlugin()`](/docs/next/realtime),
it serves live reads over Server-Sent Events. Master is limited by neither
`maxTake`, `maxDepth` nor `maxRows`.

### `.with({ rest })`

| On         | Value         | Effect                                                          |
| ---------- | ------------- | --------------------------------------------------------------- |
It needs `rest()` in the model's or the function's `use`; without it, the
model or the function is served with the defaults.

| a model    | `{ plural }`  | The routes' name.                                               |
| a model    | `{ maxTake }` | The most rows its lists return.                                 |
| a model    | `false`       | No route; read through relations, and connected, never created. |
| a function | `{ name }`    | The route's name, under `/api/functions/`.                      |
| a function | `false`       | Not served over REST.                                           |

### Query parameters

| Parameter    | On                     | Value                                    |
| ------------ | ---------------------- | ---------------------------------------- |
| `where`      | a list                 | JSON, a filter                           |
| `orderBy`    | a list                 | JSON, a field's order, or a list of them |
| `first`      | a list, connection     | JSON, a number                           |
| `last`       | a list, connection     | JSON, a number                           |
| `after`      | a list, connection     | a cursor, as text                        |
| `before`     | a list, connection     | a cursor, as text                        |
| `totalCount` | a list, connection     | `true` or `false`                        |
| `take`       | a list, list mode      | JSON, a number                           |
| `skip`       | a list, list mode      | JSON, a number                           |
| `select`     | any route but `DELETE` | JSON, the fields to read                 |
| `include`    | any route but `DELETE` | JSON, the relations to add               |

`totalCount` is also a key inside `select` and `include`, on a many
relation, in connection mode. A query function takes its input's keys
instead.

### Types

A field reads as in GraphQL's JSON: `f.dateTime()` is ISO 8601 text, as
`'2026-07-31T09:00:00.000Z'`; `f.date()` a day, as `'2026-07-31'`;
`f.decimal()` text, as `'12.50'`; an enum its value's name, as
`'published'`; the id text.

### Errors

| Status | Code               | Message                                                                                                                      |
| ------ | ------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| 400    | `BAD_USER_INPUT`   | `The query parameter first is not JSON.`                                                                                     |
| 400    | `BAD_USER_INPUT`   | `The query parameter first is given twice.`                                                                                  |
| 400    | `BAD_USER_INPUT`   | `Unknown query parameter 'limit'; this route takes where, orderBy, select, include, first, last, totalCount, after, before.` |
| 400    | `BAD_USER_INPUT`   | `select and include cannot be used together.`                                                                                |
| 400    | `BAD_USER_INPUT`   | `select.title must be a boolean.`                                                                                            |
| 400    | `BAD_USER_INPUT`   | `Unknown key 'data.revisions.create' on Post.`, a nested write to a `rest: false` model.                                     |
| 400    | `BAD_USER_INPUT`   | `data.publishedAt must be an ISO 8601 DateTime, such as 2026-01-31T12:00:00.000Z.`                                           |
| 400    | `BAD_USER_INPUT`   | `data.likes must be a number.`, for a number operation.                                                                      |
| 400    | `BAD_USER_INPUT`   | `first is at most 20 on Post.`                                                                                               |
| 400    | `BAD_USER_INPUT`   | `The request is nested 5 levels deep, its orderBy included; the most is 4.`                                                  |
| 400    | `BAD_USER_INPUT`   | `The request asks for more than 2,000 rows. Ask for fewer with first or last.`, `take` in list mode.                         |
| 404    | `NOT_FOUND`        | `No Post matches.`                                                                                                           |
| 409    | `UNIQUE_VIOLATION` | `Unique constraint failed on Post (slug).`, with `details: { model, fields }`.                                               |
| any    | any kernel code    | as [Errors](/docs/next/errors) lists them, with `details`.                                                                   |
| 500    | `INTERNAL`         | `Internal error.`, with `correlationId`.                                                                                     |

At start:

- `Crate: the route boxes is Box's; set .with({ rest: { plural } }).`, and
  `Job: the route functions is the functions's; …`, a plural taken.
- `other: the route functions/twice is double's; set .with({ rest: { name } }).`,
  for a function.
- `books: the operation books is Book's; set .with({ rest: { name } }).`, an
  OpenAPI operation named twice.
- `Job: my-jobs is not a route name.`
- `Club.status: REST names a schema Person; give yours another name.`
- `Person.status and Club.status give the schema Status two shapes; name each once.`

As it runs, a function that returns `undefined` is refused:
`fn returned undefined; make its output .nullable() and return null.`

### Limits

- No batch route, no update or delete of many rows: a function does it.
- A row is found by its `id` in the path; any other unique field goes
  through `where` on the list, or `PUT`.
- A read is a `GET`: there is no `POST` route for a long query.
- The OpenAPI document declares no security scheme: the session cookie of
  [auth](/docs/next/auth) and the master key header are not in it.
