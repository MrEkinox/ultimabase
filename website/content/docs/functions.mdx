A function is an operation the server runs: search the books, borrow one,
merge two accounts. `defineFunction` names it, validates its input, types its
output, and every transport serves it:

<include cwd meta='title="src/search.ts"'>
	../examples/functions/src/search.ts#search
</include>

The full example, with its tests: [`examples/functions`](https://github.com/MrEkinox/ultimabase/tree/main/examples/functions).

- GraphQL serves it as a query, on `POST /graphql`, and REST as
  `GET /api/functions/searchBooks`.
- `input` is a Standard Schema (Zod, Valibot, ArkType…). The examples use Zod,
  a package of its own.
- `output` types the answer: here a list of `Book`.
- `run` receives the validated `input` and the `caller`.

```npm
npm install zod
```

The functions read and write `Book`, a model with a searchable `title` and
an optional `borrowedBy`. Clients may only read it:

<include cwd meta='title="src/models.ts"'>
	../examples/functions/src/models.ts#book
</include>

The tests write two books, Emma and Dune, as Master.

| To                             | Use                                                      |
| ------------------------------ | -------------------------------------------------------- |
| serve it                       | [`defineApp({ functions })`](#add-it-to-the-application) |
| write rows no client may write | [`{ as: master }`](#write-as-the-server)                 |
| call it from server code       | [`fn.run`](#call-it-from-server-code)                    |
| refuse a caller                | [`.with({ access })`](#access-and-validation)            |
| read data, over GET too        | [`query: true`](#queries-and-outputs)                    |
| return nothing, or a shape     | [`output`](#queries-and-outputs)                         |
| rename it in a transport       | [`.with({ graphql: { name } })`](#queries-and-outputs)   |
| return a page of rows          | [`Book.paginated()`](#pages)                             |

## Write as the server

A function is trusted server code. Its queries pass `{ as: caller }` to keep
the caller's rules, or `{ as: master }` to write what no client writes, as
`Book` here. The function below returns a `Loan`, a named object that holds a
model and data:

<include cwd meta='title="src/functions.ts"'>
	../examples/functions/src/functions.ts#loan
</include>

<include cwd meta='title="src/functions.ts"'>
	../examples/functions/src/functions.ts#borrow
</include>

- `signedInRun`, from [`@ultimabase/auth`](/docs/next/auth), wraps a `run` for
  signed-in users and adds `user`, the caller's record, typed.
- The rule `isAuthenticated`, from `@ultimabase/auth` too, refuses a visitor with `ACCESS_DENIED` before
  `run`.
- Master passes every rule, so the wrapper refuses Master, and anyone a wider
  rule lets in, with `UNAUTHENTICATED`.
- A check that needs the input, or another row, throws from `run`. A
  `PublicError` reaches the client with its code, message and details: see
  [Errors](/docs/next/errors).

## Access and validation

`.with({ access })` takes one rule, which receives `{ caller }` only. A

## Queries and outputs

`query: true` makes a function a query: GraphQL serves it under `Query`, over
GET and POST, and REST over GET. A function is a mutation otherwise.

The output is one of:

- a model (`Book`), a list (`[Book]`), or a model or `null` (`Book.nullable()`);
- a [`defineType`](/docs/next/models#object-types) holding models and data
  (`Loan` above);
- a Standard Schema, for data alone.

Without an output, `run` returns nothing and GraphQL answers `true`.
`use` names the transports whose key `.with` sets (`graphql` comes from
`@ultimabase/graphql`), and a function takes `{ name }` there, to rename it in
that transport:

<include cwd meta='title="src/functions.ts"'>
	../examples/functions/src/functions.ts#return
</include>

The output is typed, not validated: `run` must return what it declares. A
string returned for an enum takes `as const`, as in
`{ result: 'passed' as const }`. TypeScript reads the literal as a `string`
otherwise, since it checks `run` before it knows the output's type.

## Details

- A `defineType` field can be a page too, at any depth. In GraphQL that field
  takes the page arguments.
- In REST, one JSON parameter named by the field's path takes them, as
  `profile.posts={"first":20,"totalCount":true}`.
- A schema given `.meta({ id: 'Line' })` is the shared GraphQL type `Line`,
  and `LineInput` as an input.
- `z.uuid()` is an `ID` in GraphQL, as a row's `id`, and a `string` of format
  `uuid` in OpenAPI. A client passes a row's `id` to a function with the
  variable type it reads it with, `$id: ID!`.

## Reference

### `defineFunction(definition)`

| Key           | Type                       | Default  | Effect                                                                                                             |
| ------------- | -------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------ |
| `name`        | `string`                   | required | The GraphQL field's name and the REST route's.                                                                     |
| `run`         | `(facts) => output`        | required | The operation; may be `async`.                                                                                     |
| `input`       | a Standard Schema          | none     | Validates the input; without it, `run` receives none.                                                              |
| `output`      | see below                  | none     | The output's type; without it, `run` returns nothing.                                                              |
| `query`       | `boolean`                  | `false`  | A query, over GET too; a mutation otherwise.                                                                       |
| `use`         | `[graphql()]`, `[rest()]`… | `[]`     | The transports whose key `.with` sets. Every transport serves it.                                                  |
| `description` | `string`                   | none     | Shown in the GraphQL schema and the OpenAPI document.                                                              |
| `deprecated`  | `string`                   | none     | Why clients should stop calling it, and what replaces it: `@deprecated` in GraphQL, `deprecated: true` in OpenAPI. |

`.with({ access, graphql, rest })` sets its rule and, for a transport of
`use`, `{ name }` to rename it there or `false` to hide it.

### What `run` receives

| Fact     | Value                                                                  |
| -------- | ---------------------------------------------------------------------- |
| `input`  | the validated input, with the schema's defaults and transforms         |
| `caller` | who calls: see [Access rules](/docs/next/access)                       |
| `client` | over a transport, `{ address, cookies }`; `undefined` from server code |

`client.cookies` has `get(name)`, `set(name, value, options?)` and
`clear(name, options?)`, written on the HTTP response.

### Outputs

| Output             | `run` returns           | GraphQL              |
| ------------------ | ----------------------- | -------------------- |
| none               | nothing                 | `Boolean!`           |
| `Book`             | a row                   | `Book!`              |
| `[Book]`           | rows                    | `[Book!]!`           |
| `Book.nullable()`  | a row or `null`         | `Book`               |
| `Book.paginated()` | `Book.paginate(...)`    | `BookConnection!`    |
| a `defineType`     | an object of its fields | the type             |
| a Standard Schema  | the schema's type       | from its JSON Schema |

### Errors

| Code                | When                                       | `details`                         |
| ------------------- | ------------------------------------------ | --------------------------------- |
| `ACCESS_DENIED`     | The rule refused: `borrowBook refused.`    | `{ function }`                    |
| `VALIDATION_FAILED` | The input does not match: `Invalid input.` | `{ issues: [{ path, message }] }` |

### Limits

- The access rule is synchronous and receives no input.
- A schema without a JSON Schema export, as `z.date()`, stops startup:
  `z.iso.datetime()` is a `DateTime` in GraphQL.
- A name another function or a model's generated query already takes stops
  startup, naming both.
- A page is a query's output, never under a list, in a virtual or live. An
  input property named as a page argument stops startup.
