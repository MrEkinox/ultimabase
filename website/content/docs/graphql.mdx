`@ultimabase/graphql` serves a GraphQL API generated from your models and
functions, on the [HTTP](/docs/next/http) server. Each request runs as its
caller, under the models' [access rules](/docs/next/access).

```npm
npm install @ultimabase/graphql graphql
```

Every model and every function of the application is served. Listing `graphql()`
in a model's `use` lets its `.with({ graphql })` set its name and its limits,
or hide it:

	../examples/graphql/src/models.ts#post
</include>

The full example, with its tests: [`examples/graphql`](https://github.com/MrEkinox/ultimabase/tree/main/examples/graphql).

`graphqlPlugin()` goes in the application's plugins, after `httpPlugin()`, which
it requires:

	../examples/graphql/src/app.ts#plugins
</include>

The API is on `/graphql`. Outside production, a browser opening that URL gets
[GraphiQL](https://github.com/graphql/graphiql), and the server logs
`GraphiQL on http://localhost:3000/graphql.`.

## What a model gets

`Post` gives six root fields, each taking the arguments of its
[query](/docs/next/queries) in GraphQL's grammar:

| Field                               | Kind     | Returns                    |
| ----------------------------------- | -------- | -------------------------- |
| `post(where)`                       | query    | `Post`, `null` when absent |
| `posts(where, orderBy, first…)`     | query    | `PostConnection!`, a page  |
| `createPost(data)`                  | mutation | `Post!`                    |
| `updatePost(where, data)`           | mutation | `Post!`                    |
| `upsertPost(where, create, update)` | mutation | `Post!`                    |
| `deletePost(where)`                 | mutation | `DeletedPost!`, as it was  |

A row reads its `id`, `createdAt` and `updatedAt` besides its fields.

A write nests its [relations](/docs/next/relations)' writes: `connect`, `create`
and `connectOrCreate`, and in an update `update`, `disconnect`, `set` and
`delete`. Here a person is created with three posts:

## Pages

A list is a [Relay](https://relay.dev/graphql/connections.htm) connection: `first`
rows `after` a cursor, or `last` rows `before` one.

<include cwd meta='title="Request"'>
	../examples/graphql/src/requests/page.graphql
</include>

<include cwd meta='title="Response"'>
	../examples/graphql/src/requests/page.json
</include>

- `totalCount` counts every row the filter matches.
- `pageInfo.endCursor` is where the next page starts: sent as `$after`, here it
  returns the last post, `Sketch`.
- Without `first`, a list returns `take` rows, 100 by default.
- A client asks for `maxTake` at most, 100 by default, or the model's own:
  `.with({ graphql: { maxTake: 20 } })` above.
- A relation's list is a connection too, with its own `first`, `orderBy`, `where`
  and `totalCount`.

`pagination: 'list'` serves lists instead, with `take` and `skip`, at every depth:

## Filters

`where` takes an input per field:

| On                    | Operators                                                                |
| --------------------- | ------------------------------------------------------------------------ |
| every field           | `equals`, `not`, `in`, `notIn`                                           |
| numbers and dates     | `lt`, `lte`, `gt`, `gte`                                                 |
| text                  | `contains`, `startsWith`, `endsWith`, `mode: insensitive` to ignore case |
| a relation to one row | `is`, `isNot`                                                            |
| a relation to many    | `some`, `every`, `none`                                                  |
| filters               | `AND`, `OR`, `NOT` combine them                                          |

## Errors

A refused request answers its error in `errors`, with its code and details under
`extensions`, as [Errors](/docs/next/errors) lists them; the field is `null`. Here
a post takes a slug already used:

<include cwd meta='title="Request"'>
	../examples/graphql/src/requests/duplicate.graphql
</include>

<include cwd meta='title="Response"'>
	../examples/graphql/src/requests/duplicate.json
</include>

- A document the schema refuses, as an unknown field, has the code
  `BAD_USER_INPUT`, as REST's refused query: GraphQL's own message says what is
  wrong.
- A message never repeats the value it refused, so a password never comes back.
- A server error is `Internal error.`, with `INTERNAL` and a `correlationId` the
  server logs beside the error.

## A schema file for clients

With `generated: 'src/generated/schema.graphql'`, as in the application above,
the schema being served, `extend` applied, goes to that file:

| Command                           | What it does                                                                                                                                          |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ultimabase dev`                  | Writes it as it starts, only when its content changed, so a codegen watching it runs after a change only. Logs `Wrote src/generated/schema.graphql.`. |
| `npx ultimabase generate`         | Writes it without starting the application: no database, no port.                                                                                     |
| `npx ultimabase generate --check` | Writes nothing and exits 1 when the file is out of date, so CI catches a model change merged without its schema.                                      |

- The path is read from the directory the command runs in, and missing folders are
  created.
- Nothing writes it under `ultimabase start` or in tests, where `NODE_ENV` is
  `production` or `test`.
- The file is committed: a front end points
  [GraphQL Code Generator](https://the-guild.dev/graphql/codegen)'s `schema` at it,
  and types its operations without a running server, in CI too.

See [Starting it](/docs/next/application#starting-it).

## Limits

A caller other than Master meets five limits. A document over `maxDepth`,
`maxRows`, its values or the root fields' limit is refused before it runs; a list over its `maxTake` is refused as it
runs. With the application above:

| Over            | Asking for                                                      | Message                                                                                                     |
| --------------- | --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `maxTake: 20`   | `posts(first: 21)`                                              | `first is at most 20 on Post.`                                                                              |
| `maxDepth: 4`   | people, their posts, their author, their posts, each title      | `The document is nested 5 levels deep; the most is 4.`                                                      |
| `maxRows: 2000` | `people(first: 100)`, each with `posts(first: 20)`              | `The document asks for more than 2,000 rows. Ask for fewer with first or last.`                             |
| `maxRows: 2000` | `people(first: 50)`, each with `posts(first: 20)` of 100 fields | `The document returns more than 100,000 values. Select fewer fields, aliases or rows.`                      |
| 20 root fields  | 21 root fields, a `totalCount` counted as one more              | `The document asks for more than 20 root fields, a totalCount counted as one more. Send several documents.` |

Master, as a request with the `x-ultimabase-master-key` header, is not limited.
[Details](#what-counts-toward-the-limits) says what each one counts.

### A relation selected twice

A relation or a virtual is read once per row, so one selected twice with different
arguments, under two aliases or in two fragments, is refused before anything runs,
for every caller:

## Details

### Reading a relation or nothing

- A relation to one row reads `null` when the caller may not read it.
- A connection that selects `totalCount` without `edges` or `pageInfo`, or asks
  `first: 0` or `last: 0` without a cursor, counts its rows and reads none:
  `posts { totalCount }` costs one count, at any depth.
- Without a row, `hasNextPage` (or `hasPreviousPage` with `last`) says whether the
  count is above 0, and both cursors are null.

### Writes GraphQL leaves out

GraphQL has no empty input, so what would take one is left out:

- A relation to a model with nothing else to write, as a book that is only its
  shelf, is only connected.
- A model with no field is created with `createPing { id }`, and neither updated
  nor upserted.

### What counts toward the limits

- `maxRows` counts each list's `first` times the lists above it.
- A document returns at most 50 values a row of `maxRows`: each field, `edges`,
  `node` and `__typename` included, counts one value per row above it.
- A level of `maxDepth` is a field, root fields included, and each relation an
  `orderBy` goes through.
- The fields of a connection and of an edge, `edges`, `node`, `cursor`, `pageInfo`
  and `totalCount`, are none: `posts { edges { node { author { name } } } }` is 3
  levels deep.
- A model's own field named `node` or `edges` counts, and with
  `pagination: 'list'` every field does.
- A live function's subscription counts as its query; a live list counts in its
  [`maxLive`](/docs/next/realtime#reference) instead, and returns at most 50
  values a row it reads, the rows it nests included.
- Each document is also bounded for every caller, Master included: 2 000 tokens,
  and 1 000 pairs of fields sharing one name. The first is ten times the standard
  introspection query.

## Reference

### `graphqlPlugin(options)`

| Option          | Type                       | Default           | Effect                                                                                      |
| --------------- | -------------------------- | ----------------- | ------------------------------------------------------------------------------------------- |
| `path`          | string                     | `'/graphql'`      | Where the API, GraphiQL and subscriptions are served.                                       |
| `pagination`    | `'connection'` or `'list'` | `'connection'`    | Relay connections, or lists with `take` and `skip`.                                         |
| `take`          | number                     | 100               | The rows a list returns without `first` or `take`.                                          |
| `maxTake`       | number                     | 100               | The most rows a list returns, unless the model sets its own.                                |
| `maxDepth`      | number                     | 10                | The deepest a document nests; a connection's and an edge's fields are no level.             |
| `maxRows`       | number                     | 20 000            | The most rows a document may return, each list times those above it; 50 values a row of it. |
| `introspection` | boolean                    | off in production | Introspection, and the "Did you mean" suggestions of refused fields.                        |
| `extend`        | `(schema) => schema`       | none              | The schema to serve, built from the generated one.                                          |
| `generated`     | string                     | none              | The file `ultimabase generate` and `dev` write the served schema to, as SDL.                |

It requires `httpPlugin()`. With [`realtimePlugin()`](/docs/next/realtime),
it serves subscriptions over WebSocket on `path`. Master is limited by
neither `maxTake`, `maxDepth`, `maxRows`, its values, nor the 20 root fields.

### `.with({ graphql })`

It needs `graphql()` in the model's or the function's `use`; without it, the
model or the function is served with the defaults.

| On         | Value         | Effect                                                               |
| ---------- | ------------- | -------------------------------------------------------------------- |
| a model    | `{ plural }`  | The list field's name.                                               |
| a model    | `{ maxTake }` | The most rows its lists return.                                      |
| a model    | `false`       | No root field; read through relations, and connected, never created. |
| a function | `{ name }`    | The field's name.                                                    |
| a function | `false`       | Not served over GraphQL.                                             |

### Types

| Field                                   | GraphQL type                                                                                       |
| --------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `f.string()`                            | `String`                                                                                           |
| `f.number()`                            | `Float`; `Int` with `integer: true`                                                                |
| `f.boolean()`                           | `Boolean`                                                                                          |
| `f.dateTime()`                          | `DateTime`, an ISO 8601 instant                                                                    |
| `f.date()`                              | `Date`, a day, as `'2026-07-31'`                                                                   |
| `f.decimal()`                           | `Decimal`, a string, as `'12.50'`                                                                  |
| `f.json()`                              | `JSON`; a typed JSON field gets its own types                                                      |
| `.meta({ scalar: true })` on its schema | a scalar read and written whole, named by its `id` as `RichText`, or by its path as `NoteSettings` |
| `f.enumOf([...])`                       | an enum, as `PostStatus`                                                                           |
| `list: true`                            | a list, as `[String!]!`                                                                            |
| the id                                  | `ID!`                                                                                              |
| `f.one()`, `f.many()`                   | the row's type, or its connection                                                                  |
| `f.virtual(output)`                     | its output's type; its input's properties are arguments                                            |

- A required field is non-null in its output, unless a field rule may hide it,
  and in `createPost`'s `data` unless it has a default.
- A row's types are `Post`, `PostConnection`, `PostEdge`, `PostWhereInput`,
  `PostWhereUniqueInput`, `PostOrderByInput`, `PostCreateInput`,
  `PostUpdateInput` and `DeletedPost`.
- A nested write's inputs name their relation, as
  `PostCreateWithoutAuthorInput`.
- The number operations of [queries](/docs/next/queries), as `increment`, are
  for server code: a GraphQL write sets values.
- A client's codegen maps a scalar by its name: give the schema an `id` so the
  name stays when the field or the model is renamed.

### Errors

| Code             | Message                                                                                                                    |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `BAD_USER_INPUT` | `The document is nested 5 levels deep; the most is 4.`                                                                     |
| `BAD_USER_INPUT` | `posts is selected twice with different arguments, at people.edges.node.latest and people.edges.node.posts; read it once.` |
| `BAD_USER_INPUT` | `The document asks for more than 2,000 rows. Ask for fewer with first or last.`                                            |
| `BAD_USER_INPUT` | `The document asks for more than 20 root fields, a totalCount counted as one more. Send several documents.`                |
| `BAD_USER_INPUT` | `The document repeats fields under one name too often. Ask for each field once.`                                           |
| `BAD_USER_INPUT` | `Syntax Error: Document contains more than 2000 tokens. Parsing aborted.`                                                  |
| `BAD_USER_INPUT` | `GraphQL introspection has been disabled, …`, in production.                                                               |
| none             | `Cannot perform mutations over GET`, a `405`.                                                                              |
| `BAD_USER_INPUT` | `first is at most 20 on Post.`, `first cannot be negative.`                                                                |
| `BAD_USER_INPUT` | `after is not a cursor this API returned.`                                                                                 |
| `BAD_USER_INPUT` | `Page forward with first and after, or backward with last and before, not both.`                                           |
| any kernel code  | as [Errors](/docs/next/errors) lists them, with `details`.                                                                 |
| `INTERNAL`       | `Internal error.`, with `correlationId`.                                                                                   |

At start:

- `Person: its list field would be named person too; set .with({ graphql: { plural } }).`
- `Posts: the root field posts is Post's; set .with({ graphql: { plural } }).`
- `posts: the root field posts is Post's; set .with({ graphql: { name } }).`, for a function.
- `graphqlPlugin: no query to expose; the application lists no model, a plugin's own models are never exposed, and no function is a query.`
- `graphqlPlugin: no query to expose; each model has .with({ graphql: false }) and no function is a query.`

### Limits

- No `node(id)` query, no batched requests and no persisted queries.
- A relation or a virtual selected twice with different arguments is
  refused; select it once.
- Each root field of a mutation is its own write, with no transaction
  around the document.
- Subscriptions need [`realtimePlugin()`](/docs/next/realtime).
