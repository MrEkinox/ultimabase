### Review fixes made in this session

- `fields/builtins/pointer.ts`: restored to the reference. The WIP inlined the
  metadata helper, which no longer type-checked.
- `relations/relation.ts`: restored to the reference. The WIP had added a
  `private mutate` member to the public `Relation` class (visible in
  `dist/index.d.ts` and on the prototype), plus formatting-only compaction.
- `schema/definition-compilation.ts`: the WIP split developer fields with
  `record[name] = field` on plain objects. A field named `__proto__` (own key)
  would then replace the record's prototype instead of being kept. The split now
  collects entry lists and uses `Object.fromEntries`, like the reference's
  `immutableRecord` copy.
- `schema/model-class.ts`: the static-mutation proxy again resolves the
  application surface by the declared class name (as in the reference), instead
  of reading `className` back through the proxy.

## Reference bugs found (documented, not fixed)

- `fields/builtins/enum.ts` (reference): a mapping source was copied with
  `mapping[key] = value` onto a plain object. An own `__proto__` key (from
  `JSON.parse` or a computed key) hit the `__proto__` setter, which ignores
  string values. So `options.values` silently lost that entry, while the accepted
  value list kept it. The rebuild keeps the entry (see "Behavior differences").
- `schema/field-builder.ts` `resolveCapturedFieldMap` (reference and rebuild,
  unchanged): resolved fields are accumulated with `fields[name] = field` on a
  plain object, so a field declared under the computed key `['__proto__']` is
  dropped and replaces the accumulator's prototype instead. The behavior was
  kept for parity. Found by reading the code, not executed. No test covers it.
