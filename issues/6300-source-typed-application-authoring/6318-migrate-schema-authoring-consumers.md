# 6318: Migrate schema authoring consumers

- Status: completed
- Milestone: 63
- Packages: `@ultimabase/core`, repository consumers
- Depends on: 6317
- ADR: ADR-0279, ADR-0280, ADR-0281, ADR-0283
- Execution contract: [milestone 63 DX and audit contract](../../docs/plans/2026-09-28-source-typed-application-authoring-target.md)

## Goal

Move ordinary schema declarations to `App.Schema.define()` (or
`UltimaBase.Schema.define()` for portable zero-plugin schemas), then remove the
standalone ordinary `Schema.define()` entry point without changing the sole
schema compiler. Keep `Schema.is()` and `Schema.defineSpecialized()` for their
current package-owned use cases.

## Baseline and bounded inventory

- Starting revision: `cb0b073c` after issue 6317's reviewed local commit; no
  push is authorized.
- The first TypeScript AST inventory finds 440 executable bare `Schema.define()`
  calls in Core and further consumers in PostgreSQL (69), Typegen (33), ACL
  (33), REST (24), and smaller packages. These counts deliberately exclude
  prose and embedded source strings, which require a separate audit. Existing
  configured `App.Schema.define()` calls are not migration targets.
- Migrate package groups with their own type/runtime verification before
  removing the standalone entry point. The previous issue-6314 broad rename
  probe was reverted; do not reuse it as a blind codemod.
- The Core schema, Access, application, and Query consumer groups now typecheck
  and pass focused tests after bounded migration. An initial 23-file Query
  probe was reverted, then the group was migrated in smaller batches. The direct
  internal `normalizeQueryInclusion()` fixture requires
  `QueryAst<SchemaReference<"IncludedUser">>` for a string-named pointer,
  whereas a configured target carries an exact `ConfiguredSchemaResult` that
  is not assignable through model method variance. The public
  `QueryBuilder.include()` method already checks target identity before its
  internal correlation cast and its positive test compiles; no public type
  change was needed. Runtime-negative fixtures now assert the earlier source
  rejection while still executing their Runtime checks. The direct normalizer
  fixture deliberately tests only its internal Runtime boundary. No
  `SchemaReference` redesign, public diagnostic weakening, or parallel graph
  was introduced.
- Core executable authoring consumers have no remaining bare `Schema.define()`
  calls; Core's ordinary suite passed (273 files, 1,383 tests). Validation,
  pg-vector, Roles, and Soft Delete consumer groups have passed their package
  typechecks and ordinary suites. Soft Delete also passed its built JavaScript
  and PostgreSQL E2E suite (4 files, 19 tests). Its relation/pointer E2E fixture
  retains a test-only cast for the accepted named-schema Typegen boundary.
  Website, README, starter, and other package consumers were then still in
  scope; these group checks were not the issue completion gate.
- Hooks, HTTP, Access, Password Auth, and the generated project template have
  since passed their package typecheck/test suites after migration. Hooks and
  Access retain source-editor negative checks that options do not appear without
  their plugin. These checks remain local evidence, not `yarn validate:full`.
- Architecture stop on ACL's exact sibling-field callback typing: replacing the
  legacy `Schema.define()` plus test-local `UltimaBaseGeneratedSchemaOptions`
  augmentation in `src/acl-option.test-d.ts` with
  `UltimaBase.use(aclPlugin()).Schema.define()` makes `acl.default` and
  `acl.resolveInput` `data.title`/`data.visibility` `unknown`. Both
  `field.string()` and direct `stringField()` declarations gave the same result.
  The probe was reverted, and the package typecheck and ordinary suite pass.
  ADR-0280 already rejected repeated source-only attempts for complete-schema
  Access/Hooks callbacks, but it classifies ACL as source-typed. At this
  checkpoint no ACL option descriptor was emitted; the exact ACL callback test depended
  on a test-only augmentation. The source editor test checks option availability
  but not exact sibling-field values. The resolution is recorded below.
- The user approved retaining ACL's exact complete-schema callback typing in
  the sole Typegen graph on 2026-10-01. ADR-0283 records the refined boundary.
  `aclSchemaOption` now supplies the public `ACLSchemaOption<this>` descriptor;
  source still exposes the option before generation, and the generated editor
  test proves exact sibling values and undeclared-field rejection. The
  package-local type fixture checks only the pre-generation callback shape.
  No Core-specific ACL code or second graph was added. The generated bytes and
  regeneration DX remain for issue 6316.
- Resolved source bootstrap mismatch during the PostgreSQL consumer pass: a custom plugin field
  declares `structuralContains.snapshotOperand(unknown)` that accepts the
  developer's `{ code: string }` and normalizes it to `{ partial: string }`.
  The old `Schema.define()` fixture accepted `{ code }` through its broad
  pre-generation filter, and the Runtime test verifies the normalized JSONB
  operand. `UltimaBase.Schema.define()` instead projected the callback's return
  type as the source `contains` input and rejected the valid `{ code }`. Under
  accepted ADR-0281, the exact custom-field `WhereInput` stays in Typegen;
  pre-generation source typing now exposes `contains` with an unknown operand
  rather than misrepresenting the internal normalized value. No Runtime input,
  Typegen emitter, or plugin API changed. The test retains `{ code }` without a
  cast; Core build, PostgreSQL test typecheck, the focused Runtime test, and
  the Typegen containment editor test pass.
- The unrelated Core relation fixture was moved from production `src/` to
  `tests/fixtures/`: its exported exact configured schemas cannot satisfy
  `isolatedDeclarations` with a broad `SchemaReference` annotation because
  relationship/model methods are invariant. The fixture is test-only, and its
  two dependent suites plus both Core typechecks pass after relocation. No
  production declaration policy was weakened. PostgreSQL's production
  `tsconfig.json` now excludes `src/**/*.test.ts` and `src/**/*.test-d.ts`, as
  Core already does; its separate test tsconfig still includes them.
- The executable old-form audit now finds only the deliberate compile-time
  `Schema.define` absence assertion and a configured language-service marker.
  The 1/10/50-schema locked benchmark passed; its measurements and the caveat
  about omitted complete generated `WhereInput` are in
  [evidence/6318-schema-authoring-benchmark.md](evidence/6318-schema-authoring-benchmark.md).
  The first permission-correct full validation passed 557 ordinary test files
  and 2,650 tests but stopped at 24 lint errors. Those migration-related
  errors were fixed. A later full validation passed 557 ordinary files/2,650
  tests, 636 coverage files/2,912 tests, build, constraints, and 17 website
  files/66 tests. Built E2E then exposed two stale committed Typegen outputs
  and two packed hover assertions tied to the old broad schema type. Both
  outputs were regenerated through the official writer, and 102 built E2E
  files/406 tests pass. The packed `SchemaResult.update()` hover now displays
  an exact but more verbose source input and abbreviates the result as
  `Promise<...>`; its documentation and type diagnostics remain intact. Issue
  6316 records this DX tradeoff for final review. The final full validation
  passed on the corrected diff.
- Compared with issue 6317, the final coverage has 2,397 uncovered statements,
  2,729 branches, 207 functions, and 2,166 lines, one more than the previous
  run for statements, branches, and lines. An earlier full run on the same
  production code matched all four prior uncovered counts exactly; the final
  one-hit difference is a coverage-run fluctuation, not a demonstrated source
  regression. The displayed percentages are 90.87/84.39/96.03/91.44%, versus
  90.88/84.39/96.03/91.45% in issue 6317. The issue still passes every
  locked threshold; issue 6316 should compare final aggregate samples rather
  than treat a hundredth-point difference as a capability change.

Documentation impact: both — the canonical authoring form changed in
Core examples, package READMEs, the starter, and public website pages; the
internal architecture/ADR and issue records changed as well.

## Acceptance criteria

- [x] Inventory standalone authoring across production, tests, fixtures,
      examples, website, generated starter templates, and source/packed editor
      probes; distinguish executable calls from prose and embedded source strings.
- [x] Migrate each consumer according to its exact installed plugin source
      contract, preserving direct options, custom fields, circular relations,
      indexes, specialized schemas, JavaScript behavior, and explicit registration.
- [x] Rewrite negative Runtime fixtures so they still exercise Runtime
      validation without weakening positive TypeScript diagnostics.
- [x] Remove only standalone ordinary `Schema.define()`; `App.Schema.define()`
      delegates to the same Core compiler and remains inert until registration.
- [x] Remove old-form type and barrel exports without adding a new global
      registry, source scope, generated client, or parallel schema compiler.
- [x] Review and update Core schema examples, package READMEs, public website
      pages, and starter templates; record exactly one Documentation impact
      classification.

- [x] Runtime tests preserve schema identity, immutable models, compiler
